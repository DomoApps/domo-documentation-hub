ROOT CAUSE
----------
The secret is a Snowflake Cortex PAT, but the script creates a vanilla
anthropic.Anthropic() client with NO base_url (scripts/build_minor_release_notes.py:278),
so it talks to api.anthropic.com directly and sends the Cortex PAT as the bearer.
Anthropic rejects it as an invalid token -> the clean 401.

CRITICAL: the 401 came from ANTHROPIC, not Snowflake. The code never contacted
Snowflake at all. So the "can a GitHub runner reach Domo's Snowflake?" question
has NOT actually been tested yet. The 401 is NOT evidence of a network block.


TWO SEPARATE PROBLEMS
---------------------
1. CODE (definitely broken, easy fix): client points at api.anthropic.com instead
   of the Cortex endpoint. Fix below.
2. NETWORK (untested — the REAL question behind the in-network-runner belief):
   can a GitHub-hosted runner reach <account>.snowflakecomputing.com? If Domo's
   Snowflake account has a network policy (IP allowlist) or is PrivateLink-only,
   GitHub-hosted runners are blocked -> a self-hosted in-network runner IS
   required. If not, no in-network runner is needed. This is a checkable fact,
   not something to assume. THE PROBE (below) answers it.

The code change is needed regardless of the network answer. The network answer
only decides WHERE the runner lives, not WHAT the code does.


SNOWFLAKE CORTEX FACTS (from Snowflake docs, confirmed 2026-10-23)
------------------------------------------------------------------
- Cortex exposes an Anthropic-Messages-API-COMPATIBLE endpoint, so the Anthropic
  Python SDK works against it with a base_url override.
- Endpoint:  https://<account>.snowflakecomputing.com/api/v2/cortex/v1/messages
  Set base_url to .../api/v2/cortex  (the SDK appends /v1/messages itself).
- Auth: PAT (Programmatic Access Token) as a static bearer. Jared confirmed the
  secret is a PAT. api_key is ignored; auth goes in the Authorization header.
- Model id "claude-haiku-5-5" IS a valid Cortex identifier — NO model change
  needed. (Cortex also offers claude-opus-5-5, claude-sonnet-5-5, etc.)
- Supported params: standard Anthropic Messages set. NOT supported: flex/priority
  tier and some anthropic-beta headers. -> DROP output_config={"effort":"low"}
  from the restyle call to be safe (build_minor_release_notes.py ~:283).


DECISIONS MADE
--------------
- Token type: PAT (static bearer).  [confirmed by Jared]
- Sequencing: PROBE REACHABILITY FIRST, before changing pipeline code. [Jared]


THE CODE FIX (apply AFTER the probe, in build_minor_release_notes.py make_restyler)
-----------------------------------------------------------------------------------
Replace:
    client = anthropic.Anthropic()
with:
    pat = os.environ["CORTEX_PAT"]
    client = anthropic.Anthropic(
        api_key="not-used",                       # ignored; header does the auth
        base_url=os.environ["CORTEX_BASE_URL"],   # https://<account>.snowflakecomputing.com/api/v2/cortex
        default_headers={"Authorization": f"Bearer {pat}"},
    )
Also: remove output_config={"effort": "low"} from client.messages.create(...).
Keep model="claude-haiku-5-5".

Secrets/vars housekeeping (do with the code fix):
  - Rename repo secret ANTHROPIC_API_KEY -> CORTEX_PAT (it's misleading as-is).
  - Add repo var/secret CORTEX_BASE_URL = https://<account>.snowflakecomputing.com/api/v2/cortex
  - Update env: block in sync-minor-release-notes.yml accordingly.
  - Update the header comment + docstring references from ANTHROPIC_API_KEY.
  - Keep the minor-release-notes skill's data-contract/env docs in sync.
