# KB Restructure — PM Review Status Ledger (Phase 4.5)

_Seeded 2026-08-28 by `scripts/build-pm-review-briefs.py`. **Hand-maintained from here on** — the script never overwrites this file, so your edits are safe across re-runs. Delete the file to re-seed a fresh template (e.g. if the PM roster changes)._

This ledger tracks the **workflow** of PM review — the milestones that can't be derived from the files.
The **live count of open work** per PM is in `RESTRUCTURE-TASKS.md` (regenerated by the script). Use the
two together: this file for *where each PM is in the process*, `RESTRUCTURE-TASKS.md` for *how much is left*.

## How to use it

For each PM, walk the columns left to right:

1. **Brief sent** — mark when you hand the PM their brief (`pm-review-briefs/pm-review-docs/<PM>.docx`).
2. **Responses in** — mark when they return answers (annotated docx, email, or meeting notes).
3. Give the answers to Claude → Claude applies edits, fills/removes `[pm-input]` markers, and reports back.
4. **Fact-checks applied** — mark when their drafted-article fact-checks are all confirmed or corrected.
5. **`[pm-input]` cleared** — mark when their open `[pm-input]` count in `RESTRUCTURE-TASKS.md` reaches 0.
6. **Lifecycle signed off** — mark when they've confirmed their legacy/retired batch(es) (feeds Phase 4.6).
7. **Decisions resolved** — mark when their open D-item(s) are decided.
8. **Done** — mark when 1–7 are complete. **When every PM row is Done → proceed to Phase 4.6.**

Legend: `todo` = open work of this type · `wip` = in progress · `done` = complete · `—` = none for this PM.
