## はじめに

Databricks、OpenAI、Amazon Bedrockのアダプターを使用すると、これらのサードパーティプロバイダーのモデルをDomo.AIソリューションに取り込むことができます。各アダプターでは、Domoでアカウントを設定するためにプロバイダーごとに異なる認証情報が必要です。これらはすべて、Data Centerの **［アカウント］** で設定します。

これらのプロバイダーから新しいAIモデルを作成する前に、まずモデルを取り込むアカウントを設定する必要があります。アカウントを接続すると、新しいモデルを作成する際にそのアダプターを使用できるようになります。その後、モデルを使用してデータを可視化したり、AIプロジェクトを作成したり、ほかのアプリやDomo全体でエンドポイントを使用したりできます。

この記事では、アダプターアカウントの設定方法と、各プロバイダーに必要な認証情報について説明します。

---

## アダプターアカウントを設定する

以下の手順に従って、AIモデルのアダプターアカウントを設定します。

1. Domoナビゲーションヘッダーで **［データ］** を選択してData Centerを開きます。
2. 左側のサイドバーで **［アカウント］** を選択します。
3. **［新規に追加］** > **［アカウント］** を選択します。 **［アカウントを追加］** モーダルが開きます。
4. ドロップダウンから、接続するアダプター（Databricks、OpenAI、またはAmazon Bedrock）を選択します。
5. 選択したプロバイダーに必要な認証情報を入力します。必要なフィールドについては、以下の各プロバイダーのセクションを参照してください。

   <Note>
     **注記：** モーダルの **［誰かに依頼する］** オプションを使用すると、組織内のほかのユーザーに接続を依頼できます。Domo内でユーザーを検索するか、そのユーザーをDomoインスタンスに招待します。
   </Note>

6. **［接続］** を選択します。

アカウントを接続すると、新しいモデルを作成する際に、使用可能なアカウントのリストにそのアカウントが表示されます。新しいモデルを追加してテストする方法については、 [こちら](/s/article/000005502) を参照してください。

<Tip>
  **ヒント：** 既存のアカウントを編集、共有、または削除する方法については、「 [コネクター/アダプターアカウントを管理する](/s/article/360042926054) 」を参照してください。
</Tip>

モデルを追加すると、スクロール可能で検索可能なサイドバーのAIモデルのリストにそのモデルが表示されます。 **［エンドポイント］** を選択すると、 **［テストエンドポイント］** の入力と出力が表示されます。モデルをテストするには、入力に応じて値を入力し、 **［モデルをテスト］** を選択します。

## Databricks

Databricksでモデルとワークスペースを構築し、MLフローモデルとしてDomoに取り込みます。

Databricksアカウントを追加してモデルとして使用可能にするには、以下が必要です。

- **ホスト名 —** Databricksのホスト名。
- **個人用アクセストークン —** Databricksの個人用アクセストークン。

Databricksアカウントを接続すると、Domo.AIセクションでDatabricksモデルをDomoに追加できます。新しいモデルを追加する方法については、 [こちら](/s/article/000005502) を参照してください。

## OpenAI

OpenAIアカウントを追加してモデルとして使用可能にするには、以下が必要です。

- **APIキー —** OpenAIのAPIキー。

## Amazon Bedrock

Domoは、モデルをDomoに取り込む際に、Amazon Bedrockの認証およびバージョン管理を使用します。

Amazon Bedrockアカウントを追加してモデルとして使用可能にするには、AWSアカウントの以下が必要です。

- **アクセスキー —** AWSのアクセスキー。
- **リージョン —** AWSアカウントが存在するリージョン。
- **シークレットキー —** AWSのシークレットキー。

### Amazon Bedrock Assume Role

Amazon Bedrock Assume Roleアカウントを追加するには、DomoがそのロールをAssumeできるようにする外部ID付きのAWS IAMロールをAWSアカウントで設定します。

アカウントを追加する際は、以下のフィールドを入力します。

- **Region —** AWSアカウントが存在するリージョン。
- **External Id —** DomoがAssumeするアカウントを検証するために使用される外部ID。これによりセキュリティ対策が追加されます。 **［Generate Code］** ボタンを使用してランダムな外部IDを生成し、それをAssumeされるロールのAWSセキュリティポリシーに貼り付けます。
- **Role Session Name —** ロールのAssume中にセッションを識別するために使用されます。任意の値を設定できます。
- **Role ARN —** DomoにAssumeさせたいロールのARN。次のような形式になります。

  ```
  arn:aws:iam::{accountId}:role/{roleToAssume}
  ```

Assumeするロールには、以下を含むポリシー設定が必要です。

```json
{
    "Effect": "Allow",
    "Principal": {
        "AWS": "arn:aws:iam::{domoAccountId}:root"
    },
    "Action": "sts:AssumeRole",
    "Condition": {
        "StringEquals": {
            "sts:ExternalId": "chosenExternalId"
        }
    }
}
```

このポリシーでは、以下のとおりです。

- `chosenExternalId` は、正しいロールがAssumeされていることをDomoが検証するために使用する、生成された ID です。Domoアカウントメニューの **［Generate Code］** オプションを使用して、ここにコピーして貼り付けます。ここの値は、Domoアカウントの値と一致している必要があります。
- `domoAccountId` は、リージョンに基づいて、ロールをAssumeするDomoのアカウントIDです。

<Warning>
  **重要：** `sts:ExternalId` 条件の値は、Domoアカウントに入力した外部IDと完全に一致している必要があります。値が一致しない場合、DomoはロールをAssumeできません。
</Warning>

Domo環境のアカウントIDは以下のとおりです。

| リージョン | DomoアカウントID |
| --------- | ---------------- |
| US        | 339405024189     |
| AU        | 010251424122     |
| EMEA (IE) | 687132894031     |
| JP        | 622384692065     |
| CA        | 710710207408     |
