## はじめに

タイムリーで関連性が高く、クリーンなデータに基づいて意思決定を行うためには、Domo環境を効率的に管理することが重要です。Content Governance Hub（CGH）は、これを実現するのに役立ちます。このアプリは、経過時間、使用状況、関連性などの事前定義された条件に基づいて、どのオブジェクトがアーカイブの候補であるかを明らかにする一元的なコントロールパネルとして機能します。

コンテンツが特定された後、一連の独立したアーカイブワークフローがBI環境のクリーンアップを自動化します。これらのワークフローはコンテンツを体系的にアーカイブし、手作業による監視やエラーの可能性を大幅に削減しながら、データガバナンス基準の維持を支援します。これらの機能を組み合わせて使用することで、データ品質を向上させ、より俊敏で十分な情報に基づいた意思決定プロセスを促進できます。

Content Governance Hubは、特に次のような場合に役立ちます。

- データリソースを合理化する必要がある **大量のデータを扱う企業** 。
- 最新のデータに基づいて定期的に戦略を更新し、古い情報を削除したい **チーム** 。
- データ保持ポリシーを効果的に管理する必要がある、 **コンプライアンス要件（GDPRやHIPAAなど）を持つ組織** 。
- 無駄のない関連性の高いBI環境を維持することで、 **業務効率を追求する企業** 。

## 仕組み

クリーンアッププロセスは、 **準備（Preparation）** と **実行（Execution）** の2つのフェーズに分かれています。

<Frame>![準備フェーズが実行フェーズにつながるContent Governance Hubのプロセスアーキテクチャ](/images/kb/content-governance-hub-process-architecture.png)</Frame>

- **準備 —** DomoStats、Domo Governanceデータセット、およびExceptions（例外）データセットがクリーンアップデータフローに供給され、それがCGHアプリで可視化されます。このダッシュボードでは、クリーンアップ作業を開始する前に、どのコンテンツに対応が必要かを特定できます。
- **実行 —** アーカイブワークフローが処理を引き継ぎ、クリーンアップデータフローで設定された条件に基づいて、ダッシュボードとカードを自動的にアーカイブします。

クリーンアップデータフローは、事前定義された条件を使用してアーカイブすべきコンテンツを判断しますが、組織固有の要件に合わせてカスタマイズできます。

<Frame>![コンテンツタイプ、アーカイブ候補、コンテンツ数を表示するCGHアプリのContent Summaryタブ](/images/kb/content-governance-hub-content-summary.png)</Frame>

<Note>
**注記：** ダッシュボードはデータセット、データフロー、コネクターデータセットをアーカイブ候補として表示しますが、現在これらのアセットタイプのアーカイブはサポートされていません。ワークフローによってアーカイブされるのはカードとダッシュボードのみです。
</Note>

## ワークフローを起動して操作する

アーカイブおよび復元ワークフローは、 **［Launch Workflows］** タブから起動します。デプロイ後、ワークフローはCGHアプリ内から起動する必要があります。

<Frame>![推定クレジット消費量とアーカイブ対象コンテンツのリストを表示するArchiving Workflow Launch画面](/images/kb/content-governance-hub-workflow-launch.png)</Frame>

この画面には、アーカイブ時に消費されるクレジット数と、アーカイブされるオブジェクトが表示されます。

<Tip>
**ヒント：** 重要なコンテンツが誤ってアーカイブされないように、ワークフローを実行する前にアーカイブされるコンテンツを確認してください。アーカイブ条件を変更した場合は、最新のデータが使用されるように、アーカイブ前にデータフローを再実行してください。
</Tip>

アーカイブされるコンテンツを変更するには、[アーカイブ条件をカスタマイズする](#customize-the-archiving-criteria)および[例外](#exceptions)を参照してください。

## クリーンアップデータフローのアーキテクチャ

クリーンアップデータフローは、ワークフローによってDomo内のどのコンテンツがアーカイブされるかを特定します。複数のDomoStatsソースを組み合わせて、コンテンツが使用されていないためアーカイブすべきかどうかを判断します。

Content Governance Hubは、アプリとともに4つのデータフローで構成されています。

- **Master | CGH**
- **Customization | CGH**
- **Restoration | CGH**
- **Dataset Tagging | CGH**

<Frame>![CGHアプリに供給される4つのCGHデータフローのリネージ](/images/kb/content-governance-hub-dataflow-architecture.png)</Frame>

### アーカイブ条件

各コンテンツタイプのアーカイブ条件は異なりますが、一般的には最終使用日がコンテンツがアクティブかどうかを判断する主な要素となります。次の表に既定の条件を示します。コンテンツがアーカイブされるには、特に明記されていない限り、すべての条件を満たす必要があります。

| コンテンツ | 既定のアーカイブ条件 |
| --- | --- |
| **カード** | 最終使用日はアクティビティログから取得されます。過去90日間にカードに対する（あらゆるタイプの）アクションがなく、 **かつ** 過去90日間にカードが存在するダッシュボードに対する（あらゆるタイプの）アクションがないこと。 |
| **ダッシュボード** | 最終使用日はアクティビティログから取得されます。過去90日間にダッシュボードに対する（あらゆるタイプの）アクションがないこと。 |
| **データセット + データフロー / データセットビュー** | 最終使用日はアクティビティログから取得されます。過去90日間にデータセットに対する `UPDATED` 以外のアクションがなく、 **かつ** データセットにアーカイブされていない子カード、データセットビュー、データフローがないこと。入力データフローの場合、同じ条件がそのすべての出力（リンクされた）データセットに適用されます。 |
| **データセットコネクター** | 過去90日間にデータセットに対する `UPDATED` 以外のアクションがなく、 **かつ** データセットに子カード、データセットビュー、データフローがないこと。 |

<Note>
**注記：** これらは既定の条件ですが、データフローをカスタマイズして条件を変更でき、使用可能な追加属性も多数含まれています。[アーカイブ条件をカスタマイズする](#customize-the-archiving-criteria)を参照してください。
</Note>

### 使用可能な追加属性

データフローは、コンテンツがアーカイブされるべきかどうかの判断には使用されない追加のメタデータを各コンテンツタイプに読み込みます。データフローを変更して、これらの属性をアーカイブ条件に含めることができます。これらの属性には、追加であることを示すために `[E]` というプレフィックスが付いています。

| コンテンツ | 追加属性 |
| --- | --- |
| **カード** | Page ID、Page Name、Scheduled Report、Sandbox Repository、Certified、Alerts |
| **ダッシュボード** | Scheduled Report、Sandbox Repository、Publish |
| **データセット + データフロー** | Sandbox Repository、Certified、Alerts、Import Type、Rows、Archived children、Linked archived children、Children |
| **データセットコネクター** | Import Type、Archived children、Linked archived children、Children |

### アーカイブデータセットのディクショナリ

以下のフィールドは、アーカイブデータセットで使用できます。データセットの粒度は重複のないオブジェクトレベルであるため、一部のフィールドは集計されているか、オブジェクトが最後に使用された時刻を参照します。これは、複数のダッシュボードに存在するカードや、複数の子を持つデータセットの場合に特に関連します。

| フィールド名 | 説明 |
| --- | --- |
| Type | コンテンツタイプ（Card、Dashboard、Dataset + Dataflow、Connector）。 |
| Object ID | コンテンツのDomo ID。 |
| Object Name | コンテンツのDomo名。 |
| Action | アクティビティログからの最後のアクションタイプ。 |
| Last used date | コンテンツが最後に使用された日付。 |
| Dataflow ID | データセットのソースデータフローのID。 |
| Linked Dataset Last used date | リンクされたデータセットの最終使用日。 |
| Linked Dataset Count | リンクされたデータセットの数。 |
| Unarchived | アーカイブされていない子の数。 |
| Linked Unarchived | リンクされたアーカイブされていない子の数。 |
| Archiving period | コンテンツが未使用と見なされるまでの、ユーザーが定義する期間。 |

次の追加属性フィールドも使用できます。

| フィールド名 | 説明 |
| --- | --- |
| Page ID | カードオブジェクトのみ — カードが最後に使用されたときに存在していたダッシュボードのID。 |
| Page Name | カードオブジェクトのみ — カードが最後に使用されたときに存在していたダッシュボードの名前。 |
| Scheduled Report | コンテンツがスケジュールレポートで使用されているかどうかを示します。 |
| Sandbox Repository | コンテンツがSandboxリポジトリで使用されているかどうかを示します。 |
| Certified | コンテンツが認定されているかどうかを示します。 |
| Alerts | コンテンツに対するアラートの数を示します。 |
| Publish | コンテンツがDomo Publishで使用されているかどうかを示します。 |
| Import Type | データソースのタイプ。 |
| Rows | 行数。 |
| Archived | アーカイブされた子の数。 |
| Linked Archived | リンクされたアーカイブ済みの子の数。 |
| Children | データセットの子のカンマ区切りリスト。 |

### リンク

アーカイブデータセットでは、 *リンク* の概念が何度か登場します。次の図は、リンクの意味を示しています。

<Frame>![入力データフローが3つのデータセットとその子カードおよびデータセットを生成するリンク図](/images/kb/content-governance-hub-linking-diagram.png)</Frame>

この例では、入力データフローが3つの出力データセットを生成し、すべて現在アーカイブされていません。

- データセット1には2つの子カードがあります。
- データセット2には1つの子カードがあります。
- データセット3には子カードと子データセットがあります。

3つのデータセットはすべて同じ入力データフローを共有しているため、各データセットの *リンクされたアーカイブされていない子* の数には、そのデータフローによって生成されたすべてのデータセットの子が含まれます。

| データセット | データフロー | アーカイブされていない子 | リンクされたアーカイブされていない子 |
| --- | --- | --- | --- |
| データセット1 | 入力データフロー | 2 | 5 |
| データセット2 | 入力データフロー | 1 | 5 |
| データセット3 | 入力データフロー | 2 | 5 |

## アーカイブ条件をカスタマイズする

アーカイブ条件は **Customization** データフローで設定します。ロジックは各コンテンツタイプの数式タイル内で定義されており、必要に応じて条件を調整できます。

<Frame>![各コンテンツタイプのアーカイブ条件と例外の数式タイルを示すCustomizationデータフロー](/images/kb/content-governance-hub-archiving-criteria-tiles.png)</Frame>

<Warning>
**重要：** アーカイブ条件への調整は、対応する例外の数式タイルにもコピーして、コンテンツがアーカイブ候補である理由、またはそうでない理由をユーザーが理解できるようにしてください。
</Warning>

すべてのコンテンツに適用されるカスタム条件を指定するには、最後の数式タイル（アーカイブの事前ステップ）を使用します。

<Frame>![「Change Null Owners to No Owner」、「Rank & Window」、「Add Formula」などのアーカイブ事前ステップの数式タイル](/images/kb/content-governance-hub-archiving-prestep-tiles.png)</Frame>

### 入力Webフォーム

アーカイブプロセスにパラメータを入力するために使用できるWebフォームが4つあります。

- **Archiving Parameters | Archiving —** コンテンツが未使用と見なされるまでの期間を調整します。既定は90日です。
- **Override | Archiving —** データフローの条件を満たしていなくてもアーカイブしたいコンテンツを指定します。
- **Exclusions | Archiving —** 決してアーカイブしないオブジェクトを指定します。
- **Restoration Input | Archiving —** 復元ワークフローによって復元されるオブジェクトを指定します。

<Note>
**注記：** データフローのスキルに自信のあるお客様は、アーカイブのニーズに合わせて任意のCGHデータフローを調整できます。CGHに今後拡張が加えられると、それらはSandboxを使用してプッシュされるため、加えた変更が上書きされる可能性があります。事前に通知され、拒否することもできます。
</Note>

## 例外

データフローはオブジェクトが使用されているほとんどのケースを判断できますが、注意すべき例外がいくつかあります。

| コンテンツ | 推奨される代替策 |
| --- | --- |
| APIによって直接アクセスされるデータセット（常に検出されるとは限りません） | Exclusionsリストに含めます。 |
| 定期的なコンテンツ（年に1回だけ使用される財務レポートなど） | Exclusionsリストに含めます。 |
| 公開されたコンテンツ | 公開コンテンツのDomoStatsデータは信頼性が低い場合があります。Exclusionsリストに含めます。 |
| DataFusion | 含まれません — 現在、そのメタデータのデータソースがありません。 |
| Domoパッケージアプリ | Domoパッケージアプリで使用されるデータセットやカードは認定する必要があります。 |
| 増分ロード（アップサートおよびパーティション） | ソースデータが他に存在しない場合は、Exclusionsリストに含めます。 |

## コンテンツがアーカイブされる仕組み

データフローとは異なり、ワークフローはシンプルで直接的です。サポートされている各コンテンツタイプに1つずつ、2つのアーカイブワークフローがあります。

### カードのアーカイブ

カードのアーカイブは次のプロセスに従います。

1. アーカイブグループがカードにオーナーとして追加されます。（このグループはプロセスの事前設定済みパラメータです。）
2. カードがすべてのダッシュボードから削除されます。
3. カードがアーカイブダッシュボードに追加されます。（このダッシュボードは事前設定済みパラメータです。）
4. アーカイブグループ以外のすべてのオーナーが削除されます。
5. カードのタイトルが変更され、 `[Archiving]` が含まれます。
6. その他のすべてのユーザーが削除されます。

### ダッシュボードのアーカイブ

ダッシュボードのアーカイブは次のプロセスに従います。

1. アーカイブグループがダッシュボードにオーナーとして追加されます。（このグループは事前設定済みパラメータです。）
2. ダッシュボードがアーカイブダッシュボードのサブダッシュボードに移動されます。（このダッシュボードは事前設定済みパラメータです。）
3. ダッシュボードのタイトルが変更され、 `[Archiving]` が含まれます。
4. アーカイブグループ以外のすべてのオーナーが削除されます。
5. その他のすべてのユーザーが削除されます。

## アーカイブされたコンテンツを復元する

復元ワークフローを使用して、アーカイブされたコンテンツを復元できます。

### カードの復元

カードの復元では、カードの名前、オーナー、グループが復元されます。

### ダッシュボードの復元

ダッシュボードの復元では、ダッシュボードが元の親ダッシュボードに戻され、その名前、オーナー、グループが復元されます。
