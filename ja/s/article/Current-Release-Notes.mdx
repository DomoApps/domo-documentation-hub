## 新機能と機能拡張

### App Studioの機能拡張

#### カードの場所の可視化

カードの場所を表示するカード詳細の情報アイコンで、カードが存在するApp Studioのページも表示されるようになりました。この情報アイコンは、カード名の横にある右パネルでも利用できます。

<Frame>![](/images/kb/app_studio_card_location.jpeg)</Frame>

#### カードの移動とコピー

ダッシュボードの移動/コピー機能がApp Studioでも利用できるようになりました。右パネルの3点メニューからアクセスし、ページ間でカードを移動またはコピーできます。

<Frame>![](/images/kb/app_studio_move_copy_cards.jpeg)</Frame>

### アーカイブされたDataSetの視覚的インジケーター

Domoは、一定期間カードやAnalyzerによってクエリされていないDataSetをアーカイブすることで、データアクセスを最適化します。アーカイブされたDataSetは削除されませんが、アーカイブを解除するまでアクセスできません。アーカイブ状態の通知はより目立つように改善され、見落としにくくなりました。

- 通知がDataSetの［概要］タブの上部に表示されるようになりました
- 赤色を使用して注意を引き、DataSetにアクセスするために対応が必要な可能性があることを示します

この更新により混乱が軽減され、DataSetがアーカイブされているかどうか、およびアーカイブを解除する方法がより明確になります。

<Frame>![](/images/kb/archived_datasets_indicator.png)</Frame>

### Azure SQL Active Directoryサービスプリンシパル認証

Azure SQLのクラウド統合で、ネイティブの認証方法としてActive Directoryサービスプリンシパルがサポートされるようになりました。以前はユーザー名とパスワードによる認証に限定されていましたが、Azure SQL接続でサービスベースのID アクセスを使用できるようになり、Azureデータソース全体で一貫性が得られ、共有ユーザー認証情報が不要になります。

Azure SQLのクラウド統合を作成または編集する際に、統合構成画面で認証方法としてActive Directoryサービスプリンシパルを選択します。

### カード埋め込みの機能拡張

カード埋め込みの機能拡張では、埋め込みフレームワークが更新され、埋め込みユーザーインターフェイスが改善され、カスタマイズ機能が拡張されます。セグメント、クイックフィルター、変数などの機能を有効または無効にできるようになり、背景色、目盛り線の色、テキストの色などのパラメーターも構成できます。カードはより整ったサイズ調整とスケーリングでレンダリングされ、ドリルダウンは戻るボタン、表示されるフィルターのパンくずリスト、最終的なデータの表とともに期待どおりに機能します。これにより、グラフやカスタムAppに加えて、Notebookカードのサポートも追加されます。

以下のスクリーンショットは、従来の埋め込みカード体験と新しい埋め込みカード体験の違いを示しています。

<Frame>![Card embedded using the new framework — Controls panel open with quick filters and variable selectors](/images/kb/card-embed-v2-with-controls.png)</Frame>

埋め込みダイアログにもこれらの変更が反映されます。新しいバージョンでは、追加の表示オプション（セグメント、クイックフィルター、変数）が表示され、新しい埋め込みURLと間もなく廃止されるURLの両方が表示されるため、どのバージョンが使用されているかを識別し、新しい埋め込み体験に移行できます。

パブリック、プライベート、プログラムによる埋め込みの手順ごとの移行手順については、[埋め込みカードを新しいカード埋め込みURLに移行する](/s/article/Migrate-Embedded-Cards-to-the-New-URL)を参照してください。


### コードエンジンパッケージの使用状況の可視化と削除

デプロイしたコードエンジンパッケージがどこで使用されているかを確認し、Domo内のどこからも参照されなくなったパッケージを削除できるようになりました。

使用状況の可視化により、パッケージを参照しているすべてのカスタムAppとワークフローを、アクセスできないプライベートな参照の数を含めて、明確かつリアルタイムに把握できるため、変更を加える前にパッケージの影響範囲全体を常に把握できます。安全な削除機能により、使用されなくなったデプロイ済みパッケージを完全に削除でき、APIキーや認証情報などの機密情報を含めて公開されたパッケージに対する修復手段が提供されます。

主なメリットは次のとおりです。

- 変更を加える前に、カスタムAppとワークフロー全体で使用状況を完全に可視化
- 参照されなくなったデプロイ済みパッケージの安全な削除
- 確認できない参照を含め、使用が存在する場合は常にブロックされるガードレール付きの削除
- 削除できない、Domoが提供するパッケージの保護

### データモデリングビルダーと視覚化の統合

Domoのデータモデリング体験がBIレイヤー全体に統合されたため、セマンティックモデルを一度構築すれば、Analyzer、App Studio、カードフィルター、ページフィルター、ダッシュボード全体で使用できます。グラフのレンダリング、フィルタリング、並べ替え、サマリー数値、Beast Modeはすべてモデルに対して機能します。

モデルはMagic ETLのDataSet、DataSetビュー、SnowflakeのDataSetをサポートしているため、大規模で冗長なフラットテーブルを実体化する代わりに、モデリング体験内でウェアハウスのデータを表示できます。

### AzureホスティングのDomoインスタンスへのDatabricksライトバック

DatabricksのライトバックがAzureホスティングのDomoインスタンスでサポートされるようになりました。以前はAWSホスティングのDomoインスタンスでのみ利用可能でしたが、Databricksのライトバックが Domoインスタンスのホスティング場所に関係なく機能するようになったため、AzureホスティングのDomoを利用しているお客様は、既存のワークフローを変更することなく、AzureとAWSの両方のDatabricksについて、Databricks環境にデータをライトバックできます。

### レガシー認証の更新

Domoは、ユーザー認証の処理方法を更新し、DA-SIDと呼ばれる古いログイントークンを廃止します。これは背後で行われるセキュリティの改善であり、ほとんどのユーザーは変化に気づきません。対応が必要なお客様には、Domoから直接連絡します。

### Magic ETLの機能拡張

<Note>**注：** これらの機能のデモを見るには、[Magic: Reloadedウェビナー](https://www.youtube.com/watch?v=ddYDlKo85Ic)の再生をご覧ください。</Note>

#### 分類タイル

AI分類タイルは、テキスト、画像、ファイルなどのデータを事前定義されたクラスに分類し、構成の詳細ではなく分類エンティティに集中できるようにします。

[Magic ETLの分類タイル](/ja/s/article/000005741)の詳細については、こちらを参照してください。

#### SQLに変換

SQLに変換オプションを使用すると、DataFlowのドラッグアンドドロップアクションによって生成される基盤のSQLを確認できます。各タイルでSQLをカスタマイズおよび編集したり、ドキュメント作成用にアクションをSQLとして抽出したり、そのロジックを別のシステムで使用したりできます。DataFlowの背後にあるSQLを確認することで、ユーザーとサポートチームが問題を診断し、クエリを最適化し、パフォーマンスを向上させるのに役立ちます。

#### カスタマイズ可能なウィンドウレイアウト

Magic ETLのオーサリングキャンバスで、アクションペイン、構成ペイン、プレビューウィンドウなどのウィンドウの位置をカスタマイズし、それぞれを開いた状態または閉じた状態でピン留めするかどうかを選択できるようになりました。レイアウトをDataFlow全体で保存および保持できるため、Magic ETLをさまざまな画面での作業スタイルに合わせられます。

#### ダークモード

Magic ETLのキャンバスでダークモードが利用できるようになりました。キャンバスの既定の外観として、ライト、ダーク、またはシステム設定からの継承を選択でき、Magic ETLの表示方法と使用方法を制御できます。

#### 実行の詳細のヒートマップ

DataFlowの実行を分析する際、どのアクションが処理時間の大部分を占めているのか、あるいはどこで行が脱落したり増加したりしているのかを判断するのは難しい場合があります。DataFlowの実行の詳細ページにヒートマップと付随するテレメトリー指標が追加され、実行のトラブルシューティングと理解を深められるようになりました。リソース使用への影響、処理された行数、出力された行数などのテレメトリーオプションから選択し、各アクションの指標を実行グラフ上で直接表示できます。

<Frame>![](/images/kb/magic_etl_execution_heatmap.png)</Frame>

#### 以前のDataFlowバージョンの読み込み

古いバージョンを現在のバージョンにすることなく、DataFlowの以前のバージョンを表示できるようになりました。以前のバージョンを開いてそのロジックと構成をすべて確認し、新しいバージョンとして、またはまったく新しいDataFlowとして保存できます。

#### 複数ステートメントSQLタイル

複数ステートメントSQLタイルを使用すると、複数のSQLタイルをつなぎ合わせるのではなく、単一のタイルで複数のSQLステートメントを記述し、複数の出力を作成できます。これにより、よりコード寄りの操作感が得られ、単一のSQLスクリプトの一部として中間テーブルを構築できます。

#### 新しいキャンバスナビゲーションコントロール

Magic ETLのキャンバスをナビゲートする方法を選択できるようになりました。従来のスクロールによるナビゲーション動作に加えて、新しいクリックドラッグナビゲーションオプションにより、他のキャンバスベースのツールと同様に、クリックしてドラッグしてキャンバス内を移動できます。設定はMagic ETLのユーザー設定メニューで指定します。

<Frame>![](/images/kb/magic_etl_canvas_navigation.png)</Frame>

#### 永続的なユーザーレベルの設定

グリッド線のバリアント、外観（ライトモードまたはダークモード）、レイアウトのアップグレード、プレビュー実行で「出力された行数」を表示するかどうかなど、ユーザーレベルの設定をインスタンス内のすべてのDataFlowで保持できるようになりました。

#### プレビューでの行数

DataFlowのオーサリング中にプレビューを実行すると、各アクションによって出力される行数が出力ノード上またはその近くに表示されるようになりました。これにより、各アクションがデータにどのように影響するかを追跡しやすくなり、出力DataSetを作成する前に品質の問題を発見できます。

#### 列の選択タイルの機能拡張

列の選択タイルが再設計され、列の並べ替えと管理がより簡単になり、列や列のグループの並べ替えのオプションが改善されました。

#### 感情分析タイル

感情分析タイルは、レビュー、ソーシャルメディアの投稿、アンケートなどのテキストをポジティブ、ネガティブ、またはニュートラルに自動的に分類するため、ブランドの評判を監視し、結果に基づいて対応できます。

[Magic ETLの感情分析タイル](/ja/s/article/000005741)の詳細については、こちらを参照してください。

### Mason Appエディターの廃止

2026年10月14日より、Mason Appを作成および編集する機能がDomoで利用できなくなります。新しいMason Appの作成や既存のMason Appの編集を含むMason Appのオーサリングは終了します。これは、現在Masonフレームワークを使用してAppを構築または保守しているすべてのユーザーに影響します。

既存のMason Appは引き続き実行され、エンドユーザーがアクセスできます。削除されるのはオーサリングと編集の体験のみです。現時点では、他のApp開発ツールやより広範なApp Studioエコシステムに変更は加えられません。

現在Mason Appを開発または保守している場合は、開発ワークフローをDomo Apps（カスタムApp）に移行することをお勧めします。

[プロコードエディターを使用したDomo Appの構築](/ja/s/article/000005500)の詳細については、こちらを参照してください。

### App StudioとAnalyzerの新しいグラフの改善

3つの新しいグラフの種類と丸みを帯びたバーにより、Appでデータを表示する方法が増え、より現代的な外観になります。

- **Multi Progress Bar**は、カテゴリごとに独自の行を割り当て、実績、最大値、目標を1行で表示します
- **Symbol Matrix**は、2つのディメンションをグリッドにプロットし、各シンボルのサイズと色を値に応じて設定します
- **Ribbon Chart**は、カテゴリ間で積み上げられたセグメントを接続するため、シェアやランクの変化が動きとして読み取れます

バーは丸みを帯びた角もサポートするようになり、App全体でより柔らかく現代的な外観になります。

### 新しい左ナビゲーションのオンボーディング

Domoでは、新しい左ナビゲーションを見つけて移行することがより簡単になりました。管理者には、新しいナビゲーションが利用可能であることを知らせる製品内バナーが表示され、［詳細］オプションからナビゲーション設定が開きます。ナビゲーション設定では、すべてのユーザー、管理者のみ、または特定のグループに対して新しいナビゲーションを有効にできます。ナビゲーション設定には、変更の計画に役立つドキュメントやその他のリソースへのリンクも用意されています。

管理者が新しいナビゲーションをオンにすると、各ユーザーは初めてサインインしたときに、新しい体験を紹介する短いメッセージと動画で迎えられます。

[ユーザーを新しい左ナビゲーションに移行する](/ja/s/article/Migrate-Users-to-the-New-Left-Navigation)方法の詳細については、こちらを参照してください。

### OAuthのみの読み取り専用統合

Databricks、Snowflake、BigQueryを含む、OAuthをサポートするすべてのエンジンに対して、読み取り専用のOAuthのみの統合をネイティブに作成できるようになりました。OAuthに標準化している企業は、他の認証情報の種類を構成することなく、ユーザーからマシンへのOAuth認証を使用して接続できます。

### ダッシュボード、App Studio、Embedのpvariableサポート

Domoは、ダッシュボード、App Studio、Embed全体でpvariableをサポートするようになりました。ページのURLパラメーターを渡してページの読み込み時に変数を適用できるため、リンクを開いた時点で適切な変数値をすでに設定できます。

[Domoの変数](/ja/s/article/7903767835031)の詳細については、こちらを参照してください。

### 地域別の日付と数値の書式設定

Domoは、CLDR国際標準に従って日付と数値を書式設定するようになり、すべてのブラウザーとオペレーティングシステムで一貫した書式設定が保証されます。

### セマンティックビューの統合

他のSnowflakeテーブルと同様に、クラウド統合を通じてSnowflakeのセマンティックビューを登録できるようになりました。これにより、Snowflakeですでに定義したテーブル、リレーションシップ、シノニム、説明、指標が、そのビジネスロジックを手作業で再構築することなくDomoに取り込まれます。

Domoはセマンティックビューを読み取り専用のデータモデルとしてインポートし、そのメタデータをDomoスキーマに表示し、データモデルエディターでそのリレーションシップをマッピングし、そのディメンション、メジャー、派生指標をAnalyzerとApp Studioで公開します。Snowflakeが信頼できる情報源であり続けるため、指標の定義は一貫性が保たれ、アナリストはモデルを再作成することなくすぐにカードを構築できます。

### ワークフローの機能拡張

#### DataSetクエリタスクの行なしサポート

DataSetクエリタスクが、結果を返さないクエリをサポートするようになりました。クエリが行を返さない場合でも、構成を保存して出力パラメーターを生成できるため、空の結果セットが想定されるシナリオの設計とテストが容易になります。DataSetクエリタスクは、データが返されない場合でも実行時に正常に実行されるようになりました。

#### MCPトリガー

新しいMCPトリガーにより、他のユースケース向けに設計されたトリガーを転用する代わりに、AIがサポートされ、ガバナンスが効いた、目的に特化した方法でワークフローを直接開始できます。MCPトリガーはワークフローがデプロイされると自動的に有効になるため、構成は不要です。また、ワークフローの実行の詳細ページには、ワークフローがAIによって開始された時点が示されるため、AIが開始した実行を明確に可視化できます。

[MCPを使用してAIツールをDomoに接続する](/ja/s/article/Connect-AI-Tools-to-Domo-Using-MCP)方法と[ワークフローの管理](/ja/s/article/000005179)について、詳細を参照してください。

#### コードエンジン関数のバージョン管理

新しいバージョンの変更オプションにより、ワークフローでのコードエンジン関数のバージョンの更新がより簡単になりました。変更を加える前に、現在の関数バージョンと切り替え先のバージョンの間で入力と出力を比較できるため、パラメーターの違いを明確に把握できます。両方のバージョンに同じ入力と出力が存在する場合、既存のマッピングが自動的に保持され、不要な再マッピングが不要になります。

### AIチャットの更新

AIチャットが、複雑で複数の要素から成る質問に対応し、複数のDataSetにまたがる質問に回答できるようになりました。ただし、DataSet間の結合とユニオンは引き続きサポートされておらず、代わりに各DataSetを個別にクエリして結果を統合します。また、より詳細な分析をサポートし、Documents（非構造化データ）でも機能するようになりました。さらに、視覚化をサポートするようになり、視覚化の表示と作成が可能になりました。ファイルのアップロード、画像の貼り付け、@メンションによる追加のナレッジの取り込みができます。AIチャットはナレッジベース（KB）にもアクセスできるようになり、Domoで会話形式で実行できることが広がりました。

[AIチャット](https://www.domo.com/docs/s/article/AI-Chat-v2)の詳細については、こちらを参照してください。

### AIチャットの消費モデル

AIチャットが、クレジット使用についてDomoのAI Pro消費モデルを利用するようになり、DomoのAI Pro機能全体で使用される同じ消費フレームワークにAIチャットが揃えられました。

[AIチャット](https://www.domo.com/docs/s/article/AI-Chat-v2)の詳細については、こちらを参照してください。

### MCP Toolkits - AlertsとWorkspaces

MCP Toolkits - AlertsとWorkspacesの提供により、Domo AIエージェントがユーザーに代わってアラートとワークスペースを管理できるため、Domo AIを通じて会話形式でそれらを管理できます。機能には、アラートとワークスペースの完全な作成、読み取り、更新、削除、アイテム、フォルダー、サブスクライバー、共有などの関連する概念の管理、およびすべてのツールが呼び出し元ユーザーの基盤リソースへのアクセスを尊重するため、許可を考慮した動作が含まれます。

[MCPを使用してAIツールをDomoに接続する](/ja/s/article/Connect-AI-Tools-to-Domo-Using-MCP)の詳細については、こちらを参照してください。

### Appブロードキャスト

Appブロードキャストにより、同じDomoページ上のカスタムAppが、ページフィルターや変数に頼ることなく、リアルタイムで相互に通信できます。機能には次のものが含まれます。

- Appは名前付きメッセージをトピックに公開し、ページ上の他のAppからのメッセージをサブスクライブできます
- マップAppがKPIカードを駆動できます
- フィルターパネルが最大3つのグラフを一度に更新できます
- Appはmanifest.jsonファイルでチャネルを宣言でき、App Studioは視覚的な配線インターフェイスを提供するため、作成者はコードに触れることなくAppを接続できます

追加の詳細と実装ガイダンスは、developer.domo.comの開発者向けドキュメントで入手できます。

### MCP Toolkits - Automation

新しいMCP Toolkits - Automationの提供により、Domo AIが自然言語を通じて、自動化サービス全体で自動化を安全に作成、更新、管理、実行できます。これらのツールキットはAI Libraryで利用でき、それらのサービスに対する既存のすべての許可と権限が引き続き適用されます。

- **MCP Toolkits - Workflows**は、ワークフローのライフサイクル全体をカバーします
- **MCP Toolkits - Code Engine**は、コードエンジンパッケージを管理します
- **MCP Toolkits - Queues (Task Center)**は、Task Centerの作業キューを管理します
- **MCP Toolkits - Forms**は、フォームを管理します

[MCPを使用してAIツールをDomoに接続する](/ja/s/article/Connect-AI-Tools-to-Domo-Using-MCP)の詳細については、こちらを参照してください。

### Case Statement Builder

Case Statement Builderは、一般的な条件ロジックのユースケース向けのガイド付きビルダーを提供するため、条件ロジックを構築するためにDQLを知る必要がなくなります。計算フィールドを作成する際に、ルールビルダーまたはプレーンなBeast Modeを選択し、条件ビルダーでルールを上から下へと積み重ね、保存したルールを生のSQLとしてではなくビルダーで再度開けます。ビルダーで処理できないものはすべてBeast Modeに変換できます。

### Magic ETLでのDocumentsサポート

非構造化ドキュメントデータをMagic ETLのDataFlowに取り込み、他のデータと一緒に処理し、結果のファイルをドキュメントコレクションにライトバックできるようになりました。Documentsの下にある3つの新しいタイルがこれを可能にします。

- **Collection Input**は、ETLへの入力としてドキュメントコレクションを選択します
- **Document Read**は、コレクションからファイルのバイトを読み取ります
- **Document Write**は、対象のコレクションにファイルを書き込みます

### グローバルカレンダーと会計カレンダーのサポート

クラウド統合で、カスタムの会計カレンダーと標準カレンダーの両方をサポートするために独自のカレンダーテーブルを登録できるようになったため、標準外の会計年度を持つ組織は、データウェアハウスを離れることなく正確な日付ベースのレポートを得られます。次の2つの方法で設定できます。

- **新しいカレンダーの生成**：カレンダーの種類、会計年度の開始、検証日、年の範囲を順に案内するガイド付きウィザードを使用します
- **既存のカレンダーの接続**：ウェアハウスにすでに存在するカレンダーテーブルをDomoに指定します

登録後、カードとAnalyzerのレポートはカレンダーを使用して正確な日付のグループ化と前期比較を行い、4-4-5、4-5-4、5-4-4の会計構造もサポートします。

[クラウド統合の会計カレンダーと標準カレンダーの構成](https://www.domo.com/docs/s/article/Fiscal-and-Standard-Calendar-Configuration-for-Cloud-Integrations)の詳細については、こちらを参照してください。

## 解決済みの問題

### BigQueryとDatabricksでのデータモデルのスキーマのマッピング

BigQueryまたはDatabricksでデータモデルをクエリすると、スキーマのマッピングが正しく読み込まれない場合がありました。データモデルは、サポートされているすべてのエンジンでスキーマを正しく解決するようになりました。

### データリネージ計算のパフォーマンス

DataSetが供給するカードやその他のダウンストリームのアーティファクトの数を再計算する処理が遅く、場合によっては不正確な数が報告されることがありました。リネージの再計算がより高速かつ正確になりました。
