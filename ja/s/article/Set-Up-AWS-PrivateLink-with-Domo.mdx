## はじめに

この記事では、AWS PrivateLinkをDomoで使用できるか評価する方法、お客様側の設定を完了する方法、既存のPrivateLink接続を管理する方法について説明します。

PrivateLinkが自社の状況に適していない場合は、Domoの担当者に連絡し、IP許可リストなどの代替案についてご相談ください。

---

## 必要な許可

この設定を完了するために必要なDomoの許可はありません。AWSアカウントへの管理者アクセスが必要です。

## PrivateLinkの仕組みを理解する

PrivateLinkは次の両サイドを接続します。

- **エンドポイントサービス（お客様サイド）—** 接続を許可するプライベートリソースを背後に持つAWS Network Load Balancer（NLB）をホストします。次に、そのNLBに関連付けられたエンドポイントサービスを作成し、接続に必要なDomo権限を付与します。
- **VPCエンドポイント（Domoサイド）—** Domoのクラウドエンジニアが、お客様のエンドポイントサービスに接続するDomoのAWSアカウントにVPCエンドポイントを作成します。また、指定したポートのみにトラフィックを制限するセキュリティグループも作成します。

すべての接続要求はDomoによって（エンドポイントサイド/クライアントサイド）、お客様のNLB上またはNLBの背後にあるサーバーに対して開始されます。つまり、Domoはお客様のプライベートリソースからデータを取得できますが、お客様のネットワークから開始された接続はDomoのプライベートVPCに到達できません。

## 設定前の検討事項を確認する

PrivateLinkの設定に取り掛かる前に、次の点を確認してください。

### リージョンに関する要件

PrivateLinkのエンドポイントは、接続先のエンドポイントサービスと同じAWSリージョンにのみ作成できます。**お客様のエンドポイントサービスは、Domoインスタンスと同じAWSリージョンにある必要があります。**米国を拠点とするお客様であれば、通常、`us-east-1`（米国東部、バージニア州北部）か`us-west-2`（米国西部、オレゴン州）にあります。ご不明な点がある場合は、Domoの担当者に問い合わせて、インスタンスをホストしているリージョンを確認してください。

お客様のプライベートリソースが別のリージョンにある場合は、PrivateLinkを確立する前に、AWSリージョン間ルーティングでそのギャップを埋める必要があります。

- [VPCピアリング接続](https://docs.aws.amazon.com/ja_jp/vpc/latest/peering/)
- [Transit Gateway](https://docs.aws.amazon.com/ja_jp/vpc/latest/tgw)

リージョン間リンクは特定の状況下で可能ですが（この記事のSnowflakeに関するセクションおよびFAQを参照してください）、例外の承認が必要であり、追加のデータ転送コストが発生する場合があります。

### 接続方向

PrivateLinkは双方向TCP通信を可能にしますが、**すべての接続はDomo（エンドポイント）サイドから開始する必要があります**。サーバーはインバウンド接続を待機し、受け入れる必要があります。Domoの各種コネクターとCloud Amplifierは、クライアントとしてサーバーに接続します。

### 複数のリソースへのアクセス

AWSは単一のエンドポイントサービスの背後にある複数のNLBをサポートしますが、Domoのエンドポイントはそのうちの1つにのみマッピングします。単一のPrivateLink上で複数のリソースを公開するには、同じNLB上の（それぞれが独自のリスナーとターゲットグループを持つ）別々のTCPポートにリソースをルーティングします。もしくは、複数のPrivateLink接続を作成することもできますが、個々の接続に追加料金が発生する場合があります。

既存のPrivateLinkがあり、同じVPC内の新しいリソースへのアクセス権を追加する場合は、新しいリンクを作成するのではなく、新しいリスナーとターゲットグループを既存のNLBに追加することを推奨します。

### セキュリティ

PrivateLinkは認証に代わるものではありません。リンクを介してアクセスできるリソースには、独自のアクセス制御（データベース資格情報、TLS証明書など）が設定されている必要があります。PrivateLink自体は、アプリケーションレベルのセキュリティではなく、ネットワークレベルの隔離を提供します。

## 料金

PrivateLinkに関して、Domoは2つのSKUを請求します。

| SKUの説明                                     |
| --------------------------------------------------- |
| PrivateLinkの設定（都度料金、リンクごと）          |
| PrivateLinkの年間費（保守、サポート、データ） |

価格の詳細については、Domoの担当者にお問い合わせください。一部の標準的ではないシナリオでは、VPの承認が必要です。また、AWSはそれとは別に、リンクの両サイドでエンドポイントとデータ転送の使用量を請求します。

## PrivateLinkを設定する

### ステップ1 — リソースを特定する

Domoに公開するプライベートリソースと、NLBのポートにマッピングする方法を決定します。各リソースには一意のTCPポートが必要です。それぞれのホスト名/IPとポートを記録します。

### ステップ2 — ネットワークロードバランサーを作成する

[AWSのネットワークロードバランサーに関するドキュメント](https://docs.aws.amazon.com/ja_jp/elasticloadbalancing/latest/network/)を参照してください。

- 実現可能であれば、リージョン内の**すべての利用可能なゾーン**でNLBを設定します。ターゲットリソースがすべてのゾーンで使用できるわけではない場合は、NLBで**クロスゾーンロードバランシング**を有効にします。これは強く推奨されます。そうしないと、あるAZにあるDomoのエンドポイントが、別のAZにのみ存在するターゲットに到達できない場合があります。
- 各リソース/ポートの組み合わせに対して、**リスナー**と**ターゲットグループ **を作成します。
- 必要な場合を除き、**NLBにセキュリティグループをアタッチしないでください**。アタッチする場合は、PrivateLinkトラフィックにインバウンドルールを適用*しない*ようにNLBを設定する必要があります（[NLBのセキュリティグループ設定](https://docs.aws.amazon.com/ja_jp/elasticloadbalancing/latest/network/load-balancer-security-groups.html#update-security-settings)を参照してください）。これを行わない場合は、任意のIPアドレスからのインバウンドトラフィックを許可する（これによってセキュリティモデルが損なわれます）か、Domoのプライベートネットワーク範囲の知識（これによってネットワーク抽象化が損なわれます）が必要になります。

### ステップ3 — エンドポイントサービスを作成する

[AWSエンドポイントサービスに関するドキュメント](https://docs.aws.amazon.com/ja_jp/vpc/latest/privatelink/create-endpoint-service.html)を参照してください。

- 上記で作成したNLBに関連付けられている、**ネットワーク**ロードバランサーのタイプを使用してエンドポイントサービスを作成します。
- 新しいエンドポイントの場合は、**［Acceptance Required］**を有効にします。これにより、Domoの接続リクエストがアクティブになる前に、そのリクエストの確認および承認を行えます。

### ステップ4 — Domoに権限を追加する

[エンドポイントサービスの権限の追加に関するAWSドキュメント](https://docs.aws.amazon.com/ja_jp/vpc/latest/privatelink/add-endpoint-service-permissions.html)を参照してください。

DomoのAWSアカウントのプリンシパルARNをエンドポイントサービスの許可されたプリンシパルに追加します。DomoインスタンスがあるリージョンのARNを使用します。

| リージョン                  | 識別子     | DomoアカウントのARN                 |
| ----------------------- | -------------- | -------------------------------- |
| 米国東部（バージニア北部）   | us-east-1      | `arn:aws:iam::339405024189:root` |
| 米国西部（オレゴン）        | us-west-2      | `arn:aws:iam::339405024189:root` |
| カナダ（中部）        | ca-central-1   | `arn:aws:iam::710710207408:root` |
| ヨーロッパ（アイルランド）        | eu-west-1      | `arn:aws:iam::687132894031:root` |
| ヨーロッパ（ロンドン）         | eu-west-2      | `arn:aws:iam::632843870520:root` |
| アジア太平洋（シドニー）   | ap-southeast-2 | `arn:aws:iam::010251424122:root` |
| アジア太平洋（東京）    | ap-northeast-1 | `arn:aws:iam::622384692065:root` |
| アジア太平洋（ムンバイ）   | ap-south-1     | `arn:aws:iam::266735800013:root` |

### ステップ5 — 情報をDomoに送信する

Domoの担当者に以下の情報を提供します。

1. **エンドポイントサービス名** — AWSコンソールの**［VPC］**>**［Endpoint Services］**にあります。`com.amazonaws.vpce.REGION.vpce-svc-XXXXXXXXXXXXXXXXX`の形式になっています。
2. **TCPポート** — NLBでリスナーを設定している（または設定する予定がある）ポート。
3. **プライベートDNS名**（オプション）— リソースがDomoサイドで特定のホスト名を必要とする場合（例えば、TLS証明書CNや仮想ホスト名と一致させる場合）は、それらも含めます。

### ステップ6 — Domoがエンドポイントを作成するのを待つ

Domoのクラウドエンジニアが、お客様のエンドポイントサービスがDomoのAWSアカウントからアクセスできることを確認し、指定したポートのみを許可するVPCエンドポイントとセキュリティグループを作成します。また、Route 53のプライベートホストゾーンに、リクエストされたプライベートDNSレコードも作成します。

### ステップ7 — 接続リクエストを承諾する

[エンドポイントリクエストの承諾に関するAWSドキュメント](https://docs.aws.amazon.com/ja_jp/vpc/latest/privatelink/accept-reject-endpoint-requests.html)を参照してください。

Domoによるエンドポイントの作成が完了すると、お客様のエンドポイントサービスで**［Pending］**と表示されます。AWSコンソールで接続リクエストを承諾します。数分以内にステータスが**［Available］**に変更されます。

接続を承諾したことをDomoの担当者に知らせます。ステータスが**［使用可能］**にならない場合は、Domoがトラブルシューティングをサポートします。

### ステップ8 — DomoコネクターまたはCloud Amplifierを設定する

Domoの担当者が、DomoサイドのエンドポイントのDNS名を提供します。以下の形式になっています：

```
vpce-XXXXXXXXXXXXXXXXX-XXXXXXXX.vpce-svc-XXXXXXXXXXXXXXXXX.REGION.vpce.amazonaws.com
```

プライベートリソースに到達する必要があるDomoコネクターまたはCloud Amplifierのデータフローを設定する際に、これを**ホスト名**として使用します。カスタマイズされたプライベートDNS名をリクエストしていた場合は、代わりにそれらを使用できます。

<Note> **注記：**プライベートIPアドレスを使用して接続することはできません。PrivateLinkは2つのネットワークを相互に抽象化するため、お客様のネットワークのプライベートIPは、DomoのVPC内では意味を持ちません。PrivateLinkのDomoサイドに到達するときは、常にDNS名（またはカスタムDNSエイリアス）を使用してください。未加工のIPアドレスは絶対に使用しないでください。</Note>

## Snowflake PrivateLinkを設定する

DomoのCloud AmplifierをPrivateLink経由でSnowflakeに接続することはサポートされている使用事例ですが、ワークフローが異なります。なぜならSnowflakeは完全に管理されたサービスであり、基盤となるAWS VPCに直接アクセスすることはできません。

### 必要条件

1. **Snowflakeアカウント階層：**PrivateLinkは、Snowflakeの**Business Critical**エディションか、それより上位のエディションでのみサポートされています。続行する前に階層を確認してください。
2. **リージョンの一致：**SnowflakeのPrivateLinkエンドポイントは、お客様のDomoインスタンスと同じAWSリージョンにある必要があります。Snowflakeのリージョンは、Snowflakeセッションで`SELECT CURRENT_REGION();`を実行することで確認できます。リージョンの不一致がある際に、リージョン間の例外が可能な場合があります。Domoの担当者にお問い合わせください。

### プロセス

1. クラウドサービスベンダーのPrivateLinkアクセスをリクエストする**Snowflakeのサポートチケット**を作成します。[Snowflake PrivateLink setup guide for cloud service vendors](https://community.snowflake.com/s/article/HowtosetupPrivatelinktoSnowflakefromCloudServiceVendors)を参照してください。
2. お客様のリージョン用の**DomoのAWSアカウントID**をSnowflakeに提供します。`us-east-1`および`us-west-2`の場合、`339405024189`になります。その他のリージョンについては、上記のステップ4にあるARNの表を参照してください（アカウントIDはARN内の12桁の数字です）。
3. SnowflakeがDomoのアカウントを承認したら、**PrivateLink VPCE ID**（Snowflakeのドキュメント内の`privatelink-vpce-id`）を特定します。これは、Domoに渡すエンドポイントサービス名です。
4. **SnowflakeアカウントのURL**をDomoの担当者に共有します。
5. Domoが接続の設定を完了します。それから、Snowflakeの標準パブリックホスト名の代わりに、Domoが提供するプライベートDNS名を使用するようにCloud Amplifierを設定します。

## トラブルシューティング

### エンドポイント作成の失敗を解決する

最も一般的な原因は、DomoのAWSアカウントのARNがエンドポイントサービスの許可されたプリンシパルに追加されていないことです。お客様のリージョン用の正しいARN（上記のステップ4を参照）が追加されていることを確認します。追加されたら、Domoが検証を再試行できます。

### リンクが利用可能になった後の接続の問題を解決する

ネットワーク接続が確立されているが（リンクは利用可能）、Domoのコネクターが接続できない場合は、次の点を確認します。

- **正常なターゲット：**NLBのリスナーには、ターゲットグループ内に正常なターゲットがありますか？
- **クロスゾーンロードバランシング：**Domoのエンドポイントがターゲットと異なるAZにある場合は、NLBでクロスゾーンロードバランシングを有効にする必要があります。
- **NLBセキュリティグループ：**NLBにセキュリティグループをアタッチした場合、PrivateLinkトラフィックに対するインバウンドルールの適用も無効にしましたか？無効にしていない場合は、セキュリティグループを削除するか、その設定を更新します。
- **正しいポート：**Domoに提供したポートが、NLBのアクティブなリスナーと一致することを確認します。

### ネットワーク接続に成功した後のコネクターエラーを解決する

DomoがNLBへのTCP接続を確立できても、コネクターが引き続き失敗する場合（例：SQL Server接続での`Login failed for user`）、PrivateLinkネットワーク層は正常に機能しています。問題は、アプリケーションレベルの認証にあります。認証情報、データベース権限、およびデータベース自体の許可されたログインソースを検証します。認証を成功させるため、または正しいリソースをマッピングするために、カスタムDNS名が必要になる場合があります。必要なカスタムDNS名があれば、Domoの担当者に連絡します。

### プライベートIPアドレスが機能しない理由を理解する

これは想定される動作です。PrivateLinkトラフィックは、IPではなくDNS経由でルーティングされます。Domoが提供するDNS名（またはカスタムDNSエイリアス）を使用する必要があります。未加工のプライベートIPアドレスは絶対に使用しないでください。NLBの背後にあるリソースのプライベートIPは、DomoのVPCからルーティングできません。

## 既存のリンクを管理する

### ポートやリソースを追加する

既存のPrivateLink上に新しいリソースや追加のポートを公開するには、既存のNLBに新しいリスナーとターゲットグループを新しいポート用に追加してから、Domoの担当者に新しいポート番号を連絡します。Domoがセキュリティグループを更新し、新しいポートを許可します。この使用事例では、新しいエンドポイントサービスやPrivateLinkを作成する必要はありません。

### 追加のリンクを作成する

新しいリソースが別のAWS VPCやネットワーク（既存のNLB経由で到達できない）にある場合は、新しいエンドポイントサービスとPrivateLinkが必要です。上記の設定手順を繰り返します。リンクを追加するたびに、DomoとAWSから追加料金が発生する場合があります。

### リンクを削除する

PrivateLinkが不要になった場合は、Domoの担当者に連絡し、既存のリンクを拒否します。DomoはVPCエンドポイントを廃止します。その後、お客様サイドのエンドポイントサービスとNLBを削除できます。AWSコンソールのCloudWatchメトリクスは、ティアダウンの決定を行う前に、リンクがアクティブにトラフィックを通過させているかどうかを判断するのに役立ちます。

## よくある質問

<AccordionGroup>

<Accordion title="データソースがDomoインスタンスとは異なるAWSリージョンにある場合、PrivateLinkを使用できますか？">
直接使用することはできません。PrivateLinkでは、エンドポイントとエンドポイントサービスが同じAWSリージョンにある必要があります。リソースが別のリージョンにある場合は、AWSのVPCピアリング接続かTransit Gatewayを使用して、トラフィックを正しいリージョンのNLBにルーティングする必要があります。Snowflakeの特定のケースで、リージョンの不一致を解決できない場合（Snowflakeの設定が固定されているため）、Domoはリージョン間の例外を承認できる場合があります。Domoの担当者にお問い合わせください。
</Accordion>

<Accordion title="Cloud Amplifierで使用するために、PrivateLink経由でSnowflakeに接続できますか？">
はい。これはサポートされている使用事例です。Snowflakeは完全に管理されたサービスであるため、プロセスが異なります。Snowflakeサポートチケットを作成してDomoのAWSアカウントの許可をリクエストすると、Snowflakeがエンドポイントサービス名を提供します。NLBを自分で設定することはありません。詳細については、前述の「Snowflake PrivateLinkを設定する」セクションを参照してください。SnowflakeによるPrivateLinkのサポートには、Business Criticalエディションか、それより上位のエディションが必要です。
</Accordion>

<Accordion title="接続先のリソースごとに個別のPrivateLinkを設定する必要がありますか？">
必要とは限りません。NLB上で異なるTCPポート（リソース/ポートごとに1つのリスナーおよびターゲットグループ）を使用することにより、単一のPrivateLink経由で複数のリソースにアクセスできます。別のPrivateLinkが必要になるのは、リソースが異なるAWS VPC内にある場合、または同じNLB経由で到達できないネットワーク内にある場合だけです。
</Accordion>

<Accordion title="NLBにセキュリティグループをアタッチする必要がありますか？">
いいえ。NLBにセキュリティグループをアタッチすることは、PrivateLinkでは必須ではありませんし、推奨もされません。アタッチする場合は、PrivateLinkトラフィックにインバウンドルールを適用しないようにNLBを設定する必要があります。そうしないと、任意のIPアドレスからのインバウンドトラフィックを許可する必要があり、有用なセキュリティが提供されません。NLBはセキュリティグループなしのままにしておき、ターゲット自体のアクセス制御に依存します。
</Accordion>

<Accordion title="Domoがエンドポイントを作成した後でも、接続が「Pending」と表示されるのはなぜですか？">
エンドポイントサービスの所有者が接続を受け入れるまで、「Pending」状態であることが見込まれます。AWSコンソールで**［VPC］**>**［Endpoint Services］**に移動し、保留中の接続リクエストを見つけて承諾します。数分以内にステータスが［Available］に変更されます。
</Accordion>

<Accordion title="プライベートリソースと通信するためにDomoコネクターを設定する際、どのホスト名を使用すればいいですか？">
リンクを設定した後にDomoから提供されるDNS名を使用します。`vpce-XXXXXXXXXXXXXXXXX-XXXXXXXX.vpce-svc-XXXXXXXXXXXXXXXXX.REGION.vpce.amazonaws.com`の形式になっています。カスタマイズされたプライベートDNS名をリクエストしていた場合は、代わりにそれらを使用できます。プライベートIPアドレスは使用しないでください。PrivateLinkトラフィックはDNS名でルーティングする必要があります。
</Accordion>

<Accordion title="DNS名の代わりにプライベートIPアドレスを使用できますか？">
いいえ。NLBの背後にあるプライベートIPアドレスは、DomoのVPCからルーティングできません。必ずDomoが提供するDNS名（またはDNS名に解決されるカスタムDNSエイリアス）を使用して接続する必要があります。未加工のIPアドレスを使用しようとすると失敗します。
</Accordion>

<Accordion title="リンクが接続された後、コネクターがログインに失敗します。これはPrivateLinkの問題ですか？">
おそらく違います。エンジニアリングチームが検証可能なお客様のNLBへのTCP接続をDomoが確立できるが、コネクターが認証エラーを返す場合（例：`Login failed for user`）、ネットワーク層は正常に機能しています。この問題はアプリケーション層で発生しています。データベースの資格情報、ユーザー権限、およびデータベースがお客様のNLBのプライベートIPからの接続を許可しているかどうかを確認します。認証を成功させるため、または正しいリソースをマッピングするために、カスタムDNS名が必要になる場合があります。必要なカスタムDNS名があれば、Domoの担当者に連絡します。
</Accordion>

<Accordion title="既存のPrivateLinkにポートやリソースを追加する必要がある場合はどうすればよいですか？">
既存のNLBに新しいリスナーとターゲットグループを新しいポート用に追加し、その後Domoの担当者にセキュリティグループルールを更新して新しいポートを許可するよう依頼します。新しいエンドポイントサービスは不要で、Domoからの追加料金は発生しません。
</Accordion>

<Accordion title="DomoインスタンスがあるAWSリージョンを確認するにはどうすればよいですか？">
Domoの担当者にお問い合わせください。米国を拠点とするお客様であれば、通常は`us-east-1`か`us-west-2`にあります。リージョンによって、許可する必要があるDomoアカウントのARNや、リージョン間のルーティングを行わずにリソースからPrivateLinkを実行できるかどうかが決定されます。
</Accordion>

<Accordion title="PrivateLinkにはコストがかかりますか？">
はい。Domoからは、1回限りの設定料金と年間メンテナンス料金が請求されます（上記の「料金」セクションを参照してください）。また、AWSによって、リンクの両サイドでエンドポイント時間とデータ転送に対して請求されます。Domoの担当者は、現在の価格設定と適用可能な割引をご案内できます。
</Accordion>
