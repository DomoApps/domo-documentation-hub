title: "Domo Documentation Hub v2.14.0 Release Notes"
---

Hello everyone!

We're excited to announce that version 2.14.0 of the Domo Documentation Hub is now available! This release brings two new AI feature articles, MCP and connector documentation improvements, and an important AppDB API fix. You can view these changes in our knowledge base at [www.domo.com/docs](https://www.domo.com/docs).

## 🌟 What's New

### 🤖 AI Chat v2 Documentation (Beta)

Two brand-new dedicated articles now cover Domo's next-generation AI Chat experience. The new [AI Chat v2](https://www.domo.com/docs/s/article/AI-Chat-v2) article explains how to ask complex, multi-part questions about your data, analyze unstructured Documents, and generate visualizations directly from a conversation interface — currently available in beta. The companion [AI Chat v1](https://www.domo.com/docs/s/article/000005539) article has been substantially revised to clearly distinguish the two versions so customers know which experience they're using and how the two differ.

### 🧠 Bring Your Own Model

A new [Bring Your Own Model](https://www.domo.com/docs/s/article/Bring-Your-Own-Model) article explains how customers can connect their own AI model — such as a custom language model — to Domo instead of using a Domo-provided model. The article covers prerequisites, configuration steps, and how BYOM fits into the broader Domo AI ecosystem.

### 📊 Domo AI Pro: Documents Pricing

The [Domo AI Pro](https://www.domo.com/docs/s/article/000005918) overview now includes a new Documents section detailing how file storage, agent knowledge storage, agent knowledge processing, and agent knowledge queries each consume AI credits. New links to Domo's Consumption Supplemental Terms and AI Pro Pricing pages were also added for easy reference.

### 🔌 MCP Server — Consumption FAQ and Prerequisites

The [Connect to the Domo Essentials MCP Server with Standard OAuth](https://www.domo.com/docs/s/article/MCP-Standard-OAuth) article received two improvements: the prerequisites section now reflects the current beta allowlisting requirements (including the AI Chat/AI Library and Use MCP grants needed), and a new FAQ entry explains the AI Operation charges incurred by MCP tool calls, with concrete token-usage examples for search and query operations.

### 🔗 Connector Article Updates

Several connector articles received new content and improvements:

- **New article:** [GoTo Phone Connector](https://www.domo.com/docs/s/article/GoTo-Phone-Connector) — retrieve GoTo Phone call data for reporting and analysis in Domo.
- **Snowflake Marketplace:** The Snowflake integration article has been updated to reflect Snowflake's transition from Partner Connect to their Marketplace. The article, now titled [Deploy a Domo Trial from the Snowflake Marketplace](https://www.domo.com/docs/s/article/360048717414), includes updated navigation steps and a direct link to the Domo listing.
- **Writeback Connectors:** Prerequisites sections across five writeback connector articles (Eloqua, Amazon Redshift, Azure Blob Storage, Microsoft OneDrive, Amazon S3 AssumeRole) have been streamlined — redundant inline steps for creating API clients have been replaced with a single link to the centralized API Clients article.
- **[Microsoft SharePoint Connector](https://www.domo.com/docs/s/article/Microsoft-SharePoint-Connector):** Article renamed to correct the capitalization of "SharePoint" and expanded with additional content.
- Additional field documentation: File Name Match Criteria, Organization ID, and Report Type fields were added to the CSV SFTP Advanced Security, Adaptive Insights, and Microsoft Teams connector articles.

### 🛠 AppDB API: Restored Filter Fields Warning

The [AppDB API](https://www.domo.com/docs/portal/API-Reference/app-framework-apis/AppDB-API) reference had a critical warning about filter rules accidentally removed in a previous release. It's restored: all four core fields (`name`, `applyOn`, `applyTo`, `query`) are required when uploading filter rules — even when empty — and omitting any causes the upload to fail. A minimal working example is included alongside the warning.
