## Callout Labels (Corrections to Style Guide)

The XTM TM shows that professional translators used `注記：` for `Note:` overwhelmingly (164 of 173 approved instances). The existing Japanese articles in `ja/s/article/` also exclusively use `注記：`. The style guide entry (`**注：**`) was incorrect.

| Component   | English label    | **Correct Japanese label** | ~~Wrong form~~ |
| ----------- | ---------------- | -------------------------- | -------------- |
| `<Note>`    | `**Note:**`      | `**注記：**`               | ~~`**注：**`~~ |
| `<Warning>` | `**Important:**` | `**重要：**`               | —              |
| `<Tip>`     | `**Tip:**`       | `**ヒント：**`             | —              |

Inline `Warning:` text (not the MDX `<Warning>` component) → `警告：` when it appears as a prefix in sentence content (e.g., connector field descriptions).

## UI Element Naming Conventions

The TM uses two distinct bracket types for UI element names. The distinction is important:

### `「 」` — Japanese quotation brackets

Used for: menu item names, page/article titles when referenced inline, dialog window names, dropdown option labels.

```mdx
<!-- English -->
Select **Admin** from the navigation header.

<!-- Japanese -->
ナビゲーションヘッダーから **「管理者」** を選択します。
```

### `［ ］` — Full-width square brackets

Used for: UI field labels, input field names, panel section headings, Domo agent configuration fields.

```mdx
<!-- English -->
In the Role field, enter a short persona description.

<!-- Japanese -->
**［権限］** フィールドに、短いペルソナの説明を入力します。
```

### Combining bold and brackets

Follow the English source for whether the element name is bold. When bold, the brackets are inside the bold markers:

```mdx
**「管理者設定」** を選択します。   ← menu name, bold
**［権限］** フィールド              ← field name, bold
「ダッシュボード」 を開きます。     ← menu name, not bold
```

## Verb and Register Patterns

From the TM: `します` (47,041x) dominates over `してください` (9,915x). Rules:

- **Default for instructional steps**: `〜します` — describes the action as what the system/user does, not a command.
- **Use `〜してください`** only when the sentence is explicitly imperative/urgent or the English uses "please" or "must."
- **`できます`** (22,305x) for capability statements ("you can do X" → `〜できます`).

Examples:
```
EN: Select the DataSet.       → JA: DataSet を選択します。
EN: Click Save.               → JA: **「保存」** をクリックします。
EN: You can filter by date.   → JA: 日付でフィルタリングできます。
EN: You must configure this.  → JA: これを設定する必要があります。
```

## How the `/localize` Skill Uses This File

1. **At start of every Japanese translation**: the skill reads this file in full via `cat localization/Japanese-Localization-Reference.mdx` before translating a single word.
2. **During translation**: uses the expanded term glossary above (which supersedes the style guide where noted), and applies phrase patterns for recurring structures.
3. **Quality review step (Japanese-specific)**: the skill checks every translated file against the checklist below.
4. **After human review and commit to main**: the skill runs an LQA extraction pass and appends new entries to the LQA Log section below.

## Japanese Quality Checklist (TM-Augmented)

This checklist is run during Step 4 of the `/localize` skill after every Japanese translation. It extends the universal and language-specific checks in the style guide.

- [ ] `<Note>` label is `**注記：**` — not `**注：**`
- [ ] `<Tip>` label is `**ヒント：**`
- [ ] `<Warning>` label is `**重要：**`
- [ ] "Chart" (generic) translated as `チャート`, not `グラフ` — unless it's a named chart type suffix
- [ ] "Role" (agent field) translated as `権限`; "Instructions" (agent field) as `説明`
- [ ] UI field names wrapped in `［ ］`; menu/page names wrapped in `「 」`
- [ ] Verb instructions use `〜します` as default, not `〜してください` (unless imperative/urgent)
- [ ] `Step N:` formatted as `ステップ N：` (full-width colon, space after)
- [ ] "For more information" → `詳細については`
- [ ] "Learn more" → `詳細` or `詳細については`
- [ ] No translation of: DataSet, DataFlow, Magic ETL, Beast Mode, Analyzer, Buzz, Workbench, API, CRM, SQL, OAuth, SAML, Domo
