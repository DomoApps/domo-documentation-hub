Web copy: 

  
Data Models give you a powerful, centralized way to define and manage the relationships between your datasets. 

When your data is scattered across different tables, it can be a challenge to bring it all together. Data Models solves this by providing a visual editor where you can map how your data fits together. You can connect tables, define relationships, and create calculations that work across your entire data landscape. 

The best part? Joins happen at query time. To ensure the fastest possible performance for your most common analysis needs, Data Models currently create an inner join. The result is faster analysis and decisions you can trust. We're actively working on expanding our join capabilities to support even more use cases, including left outer joins, in the near future.

Enhancements to Databricks Authorization 
THUMBNAIL (by default, this shows at the top of the page) 

 
Target persona: IT Leader, Data Engineer, Data Architect, Analytics Engineer, Data Analyst, Data Scientist 
Meta description: Strengthen your data security by upgrading to OAuth 2.0 M2M authentication for Domo, Databricks, and Lakebase. Eliminate risky password-based connections and legacy PATs with a modern, secure, token-based workflow. 
Primary tags: Admin & Governance, Security & Trust 
Secondary tags: IT, Data Architecture, Data Governance, Security & Governance 
One sentence summary of feature: Future-proof your integration and enhance security by replacing static credentials and legacy Personal Access Tokens (PATs) with Databricks’ recommended OAuth 2.0 machine-to-machine (M2M) authentication for Databricks and Lakebase connections. 
Web copy:  

Align your data architecture with industry best practices and strengthen your security posture by securing your Databricks and Lakebase connections with OAuth 2.0. Relying on static usernames, passwords, or long-lived Personal Access Tokens (PATs) creates significant security vulnerabilities and burdensome administrative overhead which are methods that modern data standards are actively moving away from. 

Domo now supports OAuth 2.0 machine-to-machine (M2M) authentication for both Databricks and Lakebase. This update allows you to adopt the officially recommended authentication standard, replacing insecure or legacy credentials with a modern flow that utilizes short-lived tokens. 

Key Benefits: 

Enhanced Security: Eliminate the risk of shared or leaked static credentials. 

Simplified Management: Admins can configure a service principal with a client ID and secret for a one-time setup, reducing the need for manual rotations. 

Future-Proof Integration: Stay aligned with Databricks’ security roadmap by moving away from PATs. 

To implement this more secure connection, simply select the OAuth 2.0 M2M option when setting up or editing your Databricks or Lakebase service account connections in Domo.

Column PDP - Alerts Compatibility 
THUMBNAIL (by default, this shows at the top of the page) 
Target persona: Domo administrators, data governors, and any business user who relies on automated alerts for datasets containing sensitive information governed by Personalized Data Permissions (PDP). 
Meta description: Strengthen data governance with Domo's latest update. Alerts are now fully compatible with Column PDP, ensuring that automated notifications on sensitive datasets respect all data masking policies for each recipient. 
Primary tags: Admin & Governance 
Secondary tags: Security & Governance, Data Governance, Security & Trust, Automation, Analytics, BI 
One sentence summary of feature: Domo Alerts now support datasets with Column PDP enabled, allowing users to receive automated notifications that securely apply the appropriate data masking for each recipient. 
Web copy: 
Get timely, secure insights on your most sensitive data. Domo Alerts are now fully compatible with Column-level Personalized Data Permissions (PDP). 

Previously, you couldn't use Alerts on datasets where Column PDP was enabled to mask sensitive data. This meant you couldn't get automated notifications about the metrics that matter most, simply because they required an extra layer of security. 

With our latest enhancement, that limitation is gone. You can now create Card and DataSet Alerts on any data source, even those with active Column PDP policies. Domo ensures that the data in every alert notification is contextual to its recipient, automatically enforcing the correct data masking and permissions. Now, you can stay informed without ever compromising your data governance standards.

Meta description: Empower developers and reduce admin workload with Domo's self-serve access token creation. A new grant allows users to generate their own tokens, improving security, streamlining access, and accelerating developer platform adoption. 
Primary tags: Admin & Governance

One sentence summary of feature: Domo's new "Create Access Tokens" grant allows non-admin users to generate their own tokens, removing administrative bottlenecks and improving security for developer platform integrations. 

 
Web copy: 

Streamline developer access and enhance security with Self-Serve Access Token creation in Domo. 

Previously, creating Access Tokens was restricted to administrators, creating a bottleneck for developers and end-users needing to connect to services like the Domo MCP server. This friction slowed down projects and placed an unnecessary operational burden on admins. 

Now, with a new "Create Access Tokens" grant, you can empower the exact users who need it to generate their own tokens on demand—no admin required. This new self-service model removes the bottleneck, enabling faster adoption of Domo's developer platform features. 

For security, token creation requires an active Elevation session, and admins retain full visibility to monitor and revoke any token across the instance. By extending self-service capabilities with robust administrative oversight, Domo makes it easier for developers to build while ensuring governance and control.
