The App DB API allows developers to interact with AppDB, a NoSQL database for storing arbitrary JSON documents. This API supports CRUD operations, querying with MongoDB predicates, partial document updates, bulk operations, and aggregation, enabling developers to manage data efficiently within their Domo applications.

## Features

- **CRUD Operations**: Create, read, update, and delete documents in AppDB collections.
- **Querying**: Query documents using the full range of MongoDB query predicates, including date queries via MongoDB Extended JSON v2.
- **Aggregation**: Group, count, sum, average, min, and max query results by field.
- **Partial Updates**: Use MongoDB update operators to modify specific fields within existing documents without replacing the entire document.
- **Bulk Operations**: Delete multiple documents in a single request.
- **Collection Management**: Programmatically update collection schemas and permissions.

## Endpoints

### Query Document

**Description**: Retrieve documents from a collection via query.

AppDB supports the full range of MongoDB query predicates that can be used in a `find()` function. The following operators are **not** supported:

- `$where` — JavaScript expression evaluation is disabled server-side.
- `$near` and `$nearSphere` — proximity searches require a geospatial index, which AppDB collections do not have.

All other operators in the [official MongoDB query predicate documentation](https://www.mongodb.com/docs/manual/reference/mql/query-predicates/) are supported, including comparison, logical, array, data type, bitwise, `$expr`, `$jsonSchema`, and `$regex` operators. The geospatial shape operators `$geoWithin` and `$geoIntersects` are also supported when your documents contain GeoJSON data.

**HTTP Request**:

```http
POST /api/datastores/v2/collections/{collectionId}/documents/query
```

**Headers**:

- `X-DOMO-Developer-Token`: `<developer token here>`
- `Accept`: `application/json`
- `Content-Type`: `application/json`

**Request Body**:

```json
{
  "content.userId": {
    "$eq": "123456789"
  }
}
```

**Response**:

```http
HTTP/1.1 200 OK
```

```json
[
    {
        "id": "12345678-8683-4aa8-a3ca-3ad2c5c4cc47",
        "datastoreId": "12345678-3366-4b4e-b968-48c1b0a453f4",
        "collectionId": "12345678-ef0b-4c2d-8f39-db29042dad57",
        "syncRequired": true,
        "owner": "123456789",
        "createdBy": "123456789",
        "createdOn": "2023-09-26T20:46:10.290Z",
        "updatedOn": "2025-05-08T20:52:33.176Z",
        "updatedBy": "123456789",
        "content": {
            "listId": "12345678-4865-457e-ab4a-6e5ce70a7c69",
            "userId": "123456789",
            "listTitle": "New Test"
        }
    },
    ...
]
```

**Querying Based on Dates**

Dates can be queried in AppDB using the [MongoDB Extended JSON v2](https://www.mongodb.com/docs/manual/reference/mongodb-extended-json/) spec. This casts the provided string to a date object using the `$date` operator. The date string must be in ISO format.

```json
{
  "createdOn": {
    "$lte": {
      "$date": "2020-05-12T00:00:00.000Z"
    }
  }
}
```

### Query Documents with Aggregations

After the query filters which documents to return, you can add query string parameters to aggregate the results. Each parameter (except `groupby`) can optionally take an alias — useful when passing the same property to different aggregations to avoid name collisions.

**HTTP Request**:

```http
POST /api/datastores/v2/collections/{collectionId}/documents/query?groupby={property1},{property2}&count={alias}&avg={property1 alias1},{property2 alias2}&sum={property1 alias1}&max={property1 alias1}&min={property1 alias1}&orderby={alias1 ascending|descending}&limit={limit}&offset={offset}
```

**Headers**:

- `X-DOMO-Developer-Token`: `<developer token here>`
- `Accept`: `application/json`
- `Content-Type`: `application/json`

**Arguments**:

Any parameter that accepts field names uses standard MongoDB dot notation. Fields inside the `content` object must be prefixed with `content.` (e.g., `content.campaignName`). Top-level document fields (`owner`, `createdOn`, etc.) can be referenced directly without a prefix. The `count`, `limit`, and `offset` parameters take aliases or integers and do not use field names.

| Parameter    | Type    | Required | Description                                                                                                                                                      |
| ------------ | ------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| collectionId | String  | Required | The ID of the collection.                                                                                                                                        |
| groupby      | String  | Optional | Comma-separated list of properties to group by.                                                                                                                  |
| count        | String  | Optional | Alias for a count aggregation.                                                                                                                                   |
| avg          | String  | Optional | Comma-separated list of properties with aliases to average.                                                                                                      |
| min          | String  | Optional | Comma-separated list of properties with aliases to find the minimum.                                                                                             |
| max          | String  | Optional | Comma-separated list of properties with aliases to find the maximum.                                                                                             |
| sum          | String  | Optional | Comma-separated list of properties with aliases to sum.                                                                                                          |
| unwind       | String  | Optional | Comma-separated list of array properties to unwind (flattens nested arrays — one row per array element).                                                         |
| orderby      | String  | Optional | Field or alias to order by, followed by `ascending` or `descending`. Accepts either an aggregation alias or a field name (using dot notation for nested fields). |
| limit        | Integer | Optional | Maximum number of results to return. Default is 10,000.                                                                                                          |
| offset       | Integer | Optional | Number of results to skip before returning. Default is 0.                                                                                                        |

**Request Body**:

```json
{}
```

An empty object `{}` returns all documents before aggregating. Pass a MongoDB query object to filter first.

**Response**:

```json
[
  {
    "_id": {
      "campaignName": "Red Campaign",
      "month": "February"
    },
    "documentCount": 2,
    "sumClicks": 210,
    "avgClicks": 105.0,
    "maxClicks": 120,
    "minClicks": 90
  },
  {
    "_id": {
      "campaignName": "Blue Campaign",
      "month": "January"
    },
    "documentCount": 1,
    "sumClicks": 100,
    "avgClicks": 100.0,
    "maxClicks": 100,
    "minClicks": 100
  }
]
```

The `groupby` fields are returned inside the `_id` object when multiple fields are grouped; with a single `groupby` field, `_id` is a scalar value. Aggregation values (`count`, `sum`, `avg`, `min`, `max`) are returned as top-level fields using their configured aliases.

### Partially Update Documents

**Description**: Perform partial updates on documents using MongoDB query and update operations.

**Supported Operators**:

- `currentDate`
- `inc`
- `min`
- `max`
- `mul`
- `rename`
- `set`
- `unset`
- `addToSet`
- `pop`
- `pull`
- `pullAll`
- `push`

**Supported Modifiers**:

- `each`
- `position`
- `slice`
- `sort`

Refer to the official [MongoDB Update Operators documentation](https://www.mongodb.com/docs/manual/reference/mql/update/) for details. Note that `$setOnInsert` is not supported because queries must reference an existing document or property; using it has no effect because AppDB partial updates do not perform upserts.

**HTTP Request**:

```http
PUT /api/datastores/v1/collections/{collectionId}/documents/update
```

**Headers**:

- `X-DOMO-Developer-Token`: `<developer token here>`
- `Accept`: `application/json`
- `Content-Type`: `application/json`

**Request Body**:

The request body must be structured as a single object containing a `query` and an `operation`.

```json
{
  "query": "{mongo query JSON}",
  "operation": "{mongo operation JSON}"
}
```

Example:

```json
{
  "query": { "content.status": "Draft" },
  "operation": {
    "$set": {
      "content.status": "Active"
    }
  }
}
```

**Response**:

```http
HTTP/1.1 200 OK
Content-Type: application/json;charset=UTF-8
1
```

Returns the number of updated documents or properties.

### Bulk Delete Documents

**Description**: Remove multiple documents from a collection in a single request.

_Please note, this will end up reaching the maximum url length limit of your browser/client. If you have a large number of documents to delete, this can be done in batches._

**HTTP Request**:

```http
DELETE /api/datastores/v1/collections/{collectionId}/documents/bulk?ids=[ids]
```

**Headers**:

- `X-DOMO-Developer-Token`: `<developer token here>`
- `Accept`: `application/json`
- `Content-Type`: `application/json`

**Response**:

```http
HTTP/1.1 202 Accepted
```

```json
{
  "Deleted": 2
}
```

Returns the count of deleted documents.

### Update Collection Permissions

**Description**: Update permissions for a collection as it relates to a specific Custom App. Proxy ID is available in the Asset Library

**Parameter Options**:

| **Permission**   | **Name**       | **Description**                                                                |
| ---------------- | -------------- | ------------------------------------------------------------------------------ |
| `read`           | Read           | Grants the ability to read documents in the collection.                        |
| `share`          | Share          | Grants the ability to share the collection with other users or groups.         |
| `delete`         | Delete         | Allows the deletion of the entire collection.                                  |
| `write`          | Write          | Provides write access to the collection, including creating and updating data. |
| `admin`          | Admin          | Grants full administrative control over the collection.                        |
| `create_content` | Create Content | Allows creating new documents in the collection.                               |
| `read_content`   | Read Content   | Enables reading the content of documents in the collection.                    |
| `update_content` | Update Content | Permits updating existing documents in the collection.                         |
| `delete_content` | Delete Content | Authorizes the deletion of documents from the collection.                      |

**HTTP Request**:

```http
PUT /api/datastores/v1/collections/{collectionId}/permission/RYUU_APP/{proxyId}?permissions=read,create_content,read_content,update_content,delete_content
```

**Headers**:

- `X-DOMO-Developer-Token`: `<developer token here>`
- `Accept`: `application/json`
- `Content-Type`: `application/json`

**Response**:

```http
HTTP/1.1 204 No Content
```
