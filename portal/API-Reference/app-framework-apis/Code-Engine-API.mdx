The App Framework Code Engine API lets a Custom App invoke a Code Engine function over an alias, using the app's authenticated iframe session. It is the companion API to the `ryuu.js` / `domo.js` SDK's `domo.codeEngine(alias, input)` method.

<Note>
**Building an app?** For the task-oriented walkthrough (manifest `packageMapping`, wiring screen, troubleshooting), see [Calling Code Engine From a Custom App](/portal/Automate-Actions/Code-Engine/calling/from-a-custom-app). This page is the endpoint reference; the calling guide is where most app developers should start.
</Note>

## Authentication

Endpoints under `/domo/codeengine/v2/...` use the Custom App's authenticated iframe session. The SDK (`ryuu.js` / `domo.js`) transparently handles the session token — you do not (and should not) embed a developer token in client-side code.

These endpoints are only reachable from inside a Domo iframe. For server-to-server calls from outside Domo, use the [Product API Code Engine reference](/portal/API-Reference/Product-APIs/Code-Engine) with a developer token instead.

**Base URL:** `https://{instance}.domo.com`

## Quickstart

The SDK handles the call for you:

```javascript
import domo from 'ryuu.js';

const sum = await domo.codeEngine('awesomeFunction', {
  number1AppInput: 5,
  number2AppInput: 10,
});
```

`awesomeFunction` is the alias you declared in your app's `manifest.json` `packageMapping` array. The SDK issues `POST /domo/codeengine/v2/packages/{alias}` under the hood; the server resolves the alias, executes the function as the app's virtual user, and returns the aliased output.

For the full manifest + wiring walkthrough, see [Calling Code Engine From a Custom App](/portal/Automate-Actions/Code-Engine/calling/from-a-custom-app).

## Endpoints

- `POST /domo/codeengine/v2/packages/{alias}` — **Run by alias**. Primary endpoint. Body is an object of aliased input parameters; response is the aliased output value (primitive or object).
- `POST /domo/codeengine/v2/packages/{alias}/complex` — **Run by alias (complex response) — deprecated 2023-06-27.** Wraps the aliased output in an execution envelope with an `executionId`. The SDK does not expose this variant. If you are reading legacy app code that uses it, migrate to the primary endpoint.

Per-endpoint contracts are rendered from [`openapi/framework/codeengine.yaml`](https://github.com/DomoApps/domo-documentation-hub/blob/main/openapi/framework/codeengine.yaml) — see the sibling nav entries under this page for the full request/response details.

## Alias mapping

The `alias` in the path is **not** the real package ID or function name. It is the string you defined in the app's `manifest.json` under `packageMapping[].alias`. The server looks up the alias against the app instance's wired package, remaps aliased parameter keys to the underlying function's parameter names, and remaps the output back to your `output.alias` before returning.

This indirection is what lets an app use its own naming without coupling to a specific Code Engine package ID or version. It also means the input keys you send must match `packageMapping[].parameters[].alias` — they are not the underlying parameter names.
