title: Calling Code Engine From Outside Domo
description: Onboarding for server-to-server callers — developer-token authentication, running a function via REST, and re-fetching executions.
---

Server-to-server callers invoke Code Engine over REST using a Domo Product API developer token. This path is for CI jobs, server-side integrations, and any external system that runs outside a Domo iframe.

## When to use

- A CI/CD pipeline needs to run a Code Engine function as part of a build or deploy step.
- A server-side integration needs to trigger Code Engine from outside Domo.
- A scheduled script needs to invoke a function on a cron.
- A non-Domo system needs to call a function and read its result.

**Do not use this path for client-side code.** Developer tokens must stay server-side. For browser/mobile clients, route calls through your own server as a proxy.

## Prerequisites

- A Domo Product API developer token with Code Engine execute scope. See [Product API authentication](/portal/API-Reference/overview#product-apis).
- A Code Engine package with at least one **released** version — working versions are not callable externally.
- The token's owning user has `EXECUTE` permission on the package. See [Permissions and Sharing](../concepts/permissions-and-sharing).
- The package's UUID (`packageId`), the released version string (`version`), and the function's exported name (`functionName`). The `packageId` is in the Code Engine UI URL when you open a package; version and function names are visible in the package's version list and function list.

## Quickstart — curl

```bash
curl -X POST \
  "https://{instance}.domo.com/api/codeengine/v2/packages/{packageId}/versions/{version}/functions/{functionName}" \
  -H "X-DOMO-Developer-Token: $DOMO_DEV_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "inputVariables": {
      "datasetId": "abc-123"
    },
    "settings": { "getLogs": true }
  }'
```

## Quickstart — Node.js

```javascript
const response = await fetch(
  `https://${instance}.domo.com/api/codeengine/v2/packages/${packageId}/versions/${version}/functions/${functionName}`,
  {
    method: 'POST',
    headers: {
      'X-DOMO-Developer-Token': process.env.DOMO_DEV_TOKEN,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      inputVariables: { datasetId: 'abc-123' },
      settings: { getLogs: true },
    }),
  },
);
const execution = await response.json();

if (execution.status !== 'SUCCESS') {
  throw new Error(
    `Function failed: ${execution.errorInformation?.errorMessages?.join('; ')}`,
  );
}
return execution.result;
```

## Quickstart — Python

```python
import os, requests

instance = os.environ['DOMO_INSTANCE']
token = os.environ['DOMO_DEV_TOKEN']

url = f"https://{instance}.domo.com/api/codeengine/v2/packages/{package_id}/versions/{version}/functions/{function_name}"
resp = requests.post(
    url,
    headers={'X-DOMO-Developer-Token': token, 'Content-Type': 'application/json'},
    json={'inputVariables': {'datasetId': 'abc-123'}, 'settings': {'getLogs': True}},
)
resp.raise_for_status()
execution = resp.json()

if execution['status'] != 'SUCCESS':
    raise RuntimeError(execution['errorInformation']['errorMessages'])
print(execution['result'])
```

## Input and output shape

Request body keys are real parameter names (not aliases — alias mapping is only for Custom Apps).

Response is a `FunctionExecution` object with fields like `executionId`, `status`, `result`, `stdout.log`, `stderr.log`, `errorInformation`, and timing fields. See the [API reference](/portal/API-Reference/Product-APIs/Code-Engine) for the full schema.

## Working with logs

Set `settings.getLogs: true` to include captured `stdout.log` and `stderr.log` in the response. This is useful during development. Turn it off (`false`, or omit the field — defaults to `false`) in production to reduce response size and avoid accidentally logging secrets.

## Re-fetching by execution ID

Every execution has a stable `executionId`. If you captured one earlier (e.g. from a Workflow step output) and want to re-fetch the full record:

```
GET /api/codeengine/v2/packages/{packageId}/executions/{executionId}
```

Returns the same `FunctionExecution` shape. See the [API reference](/portal/API-Reference/Product-APIs/Code-Engine) for the full endpoint contract.

## Security

- Never embed developer tokens in client-side code (browser JS, mobile apps, public repos).
- Route all end-user-initiated calls through a server-side proxy.
- Rotate tokens periodically. Revoke immediately if a token leaks.
- Scope tokens narrowly — do not reuse a broad-scope token for Code Engine calls if you can avoid it.

## Troubleshooting

- **`404 Not Found`** — The version is not released, or `functionName` is wrong. Verify in the Code Engine UI.
- **`200 OK` with `status: "FAILED"`** — Function-level error. Always branch on `status`, not just HTTP status. Inspect `errorInformation.errorMessages` and `stderr.log`.
- **`200 OK` with `status: "RESULT_TYPE_FAILURE"`** — The function returned a value whose type does not match its declared output. Inspect `errorInformation.expectedType` vs `actualType`.
- **`403 Forbidden`** — The token lacks Code Engine execute scope, or the token's owning user lacks `EXECUTE` on the package.
- **`401 Unauthorized`** — Token missing, expired, or revoked.
