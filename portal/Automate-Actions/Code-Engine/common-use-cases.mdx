Code Engine fits into four common integration patterns. Each has its own dedicated guide under [Calling Code Engine](./overview#how-to-call-code-engine).

- **From a Workflow** — Workflows chain Code Engine functions with Domo’s built-in actions to automate business processes. Global functions that Domo maintains, plus custom functions you write, appear as drag-and-drop action steps. See [Calling Code Engine from a Workflow](./calling/from-a-workflow).

- **From a Custom App** — Apps wired to a Code Engine function via `packageMapping` can call any Domo internal API (or any external API) from client-side code, without embedding credentials. See [Calling Code Engine from a Custom App](./calling/from-a-custom-app).

- **From a Brick** — Bricks either trigger a Workflow that calls Code Engine (declarative) or host a Custom App that invokes the SDK directly (interactive). See [Calling Code Engine from a Brick](./calling/from-a-brick).

- **From outside Domo** — CI/CD jobs, scheduled scripts, and server-side integrations invoke Code Engine over REST with a Product API developer token. See [Calling Code Engine from Outside Domo](./calling/from-outside-domo).

<Note>
**Pro-tip**
Domo has a global package to start a DataFlow. Jupyter Notebooks in Domo can be scheduled as DataFlows. This means that you can spin up and run a Jupyter job via Code Engine, which can be useful when you’d like to do heavier data processing.
</Note>
