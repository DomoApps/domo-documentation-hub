## Intro

App Studio is a low-code app builder that allows anyone to create, distribute, and consume apps.

App Studio levels up the interactive Domo dashboard experience you're used to. The foundation is an intuitive and highly customizable drag-and-drop interface that allows you to create app layouts. The rich themes library lets you personalize everything from cards, tables, and fonts to color palettes and icons to align your app with your brand. Customizable themes make app design approachable for non-designers.

The seamless navigational interface lets you collect all your content together in one place. Use components like tabs, buttons, card pop-ups, and natively integrated forms to create custom experiences and take actions directly from the app—actions like sending an email, triggering a DataSet, or moving to another page in the app. You can even bring in Domo Bricks to have more control over customization. App Studio also has [Forms](/s/article/000005171) natively integrated, as well as as well as customizable [app components](/s/article/000005864).

<Note>
  **App Studio integrations**

  - App Studio integrates with Domo Everywhere so you can publish App Studio apps. See
    [Publish Content to a Subscriber Instance](/s/article/360045120554) to learn more.
  - App Studio also integrates with Sandbox. Learn more about
    [Domo Sandbox](/s/article/4403367344023) in the Knowledge Base.
  - The Forecasting Universal Model from Domo. AI allows you to [forecast from a card](/s/article/000005567#forecast-in-a-domo-app) in your App Studio app.
</Note>

## Share an App

To share an app, open it and select <img src="/images/kb/ka0Vq000000C3gT-00N5w00000Ri7BU-0EM5w000006wBJ2-1.jpg" style={{width: 20, height: 20, display: 'inline', verticalAlign: 'start', margin: '0'}} /> **Distribute** in the app's [main navigation](#view-an-app). You can share the app with users and groups in your Domo instance, or enter an email address to invite a new user, and you can send an email notification of the shared app. To control which rows of data each viewer sees, apply [Personalized Data Permissions (PDP)](/s/article/360042934614) to the underlying DataSets.

### App Sharing Is App-Level Only

Sharing in App Studio applies to the entire app. There is currently no way to share or hide individual pages with different users or groups, and personalized data permissions cannot be scoped to a single app page. Every user who has access to an app can open all of its visible pages.

When different audiences need different pages, the supported approach is to build a separate app for each audience and share each app with the appropriate users or groups. You can [duplicate an app](#duplicate-an-app) to reuse a common structure as a starting point.

### Design the Mobile Layout

App Studio maintains a mobile layout that is separate from the desktop layout. Use the **Desktop/Mobile toggle** in the [main navigation](#main-navigation) to switch between the two views while editing. Because the layouts are independent, you can tailor the mobile experience—rearranging, resizing, and hiding elements—without changing how the app looks on desktop.

#### Format Page

Under **Format Page**, you can use the dropdowns and other controls to configure the following:

### Filter Behavior and Limitations

Keep the following behaviors in mind when you work with filters and controls in an app.

- **Clear Filters does not reset persistent filters.** Clearing filters—whether with a **Clear filters** button action or **Clear All** in [Controls](#view-an-app)—removes standard page filters, but it does not reset [persistent filters](#configure-persistent-filters), persisted date ranges, or persisted Variable controls. To change a persisted value, adjust that filter or control directly rather than clearing filters.

- **Allow filtering is all or nothing.** In a card's [Filter Exceptions](#filter-exceptions-tab) tab, **Allow filtering** subjects the card to either all page filters or none of them. There is no way through this setting to allow only some filter columns to affect a single card.

#### Tabs Tips and Limitations

Keep the following in mind when you build with tabs.

- **Nest components inside the tab, not just over it.** When you add cards and other elements to a tab, drag each one onto the blue line that appears inside the tab so it is technically nested in the tab and not merely positioned on top of it. Elements that only look like they are inside a tab can cause the app to fail to save.

- **Tabs share a height.** A Tabs element sizes to the tallest tab, so a tall tab adds empty space to shorter tabs. To balance the height, add a [Spacer](#add-a-spacer) to the shorter tabs. This spacer adjustment applies to the desktop layout and does not carry over to the mobile view. (As noted above, the Tabs layout also will not resize smaller if the last item in any tab is at its minimum height.)

{/* [pm-input] Khushboo — confirm the tab nesting/save behavior (improperly nested components causing save failures) and the shared-height behavior with the Spacer workaround, including that the spacer workaround does not carry over to mobile. Synthesized from community forum reports; needs confirmation. */}

- **You cannot copy a tab's layout to another tab.** Each tab's layout is built independently; there is no option to copy one tab's arrangement of elements into another tab.

- **You cannot link directly to a tab.** A [Page Drill](#page-drill) or button action can open an app page, but it cannot open a specific tab within a page. Use separate pages when you need a direct link to specific content.

{/* [pm-input] Khushboo — confirm the current limitations that a tab layout cannot be copied to another tab and that no navigation action (Page Drill or button) can deep-link to a specific tab within a page. Synthesized from community forum reports; needs confirmation. */}

- **There is no collapsible or accordion element.** App Studio does not include a collapsible or accordion section. To keep long pages manageable, split content across [tabs](#add-tabs) or additional [app pages](#add-an-app-page).

### Add Date Ranges

The **Date Range** feature lets you define time-based data sets precisely within a component. This configuration is useful for performing historical comparisons, aligning data with specific fiscal periods, and controlling the visual display of time metadata.

The following settings are available within the Date Range panel:

- **Range:** Defines the primary time interval for the data set (such as Current Month, Last 7 Days, or Year to Date).
- **Graph By:** Sets the granularity of the time axis on the visualization. Options include **Daily**, **Weekly**, **Monthly**, **Quarterly**, and **Yearly** intervals.
- **Compare To:** Enables comparative analysis by overlaying the current range against a previous period, such as **Previous Period** (sequential) or **Previous Year** (same period, one year prior).
- **Date Range Field:** Specifies the exact column from the underlying DataSet that contains the timestamps used to drive the range logic.
- **Date Filter:** Provides an additional layer of refinement to include or exclude specific dates within the broader selected range.
- **Use Fiscal Calendar:** When enabled, the range logic aligns with your organization's defined fiscal year start and end dates rather than the standard Gregorian calendar.
- **Hide Date on Card Details:** When selected, removes the date range text from the header or footer of the visualization, creating a cleaner interface for dashboards where the time context is already established.

## Download Content from a Doc Card

App users can *only* download the file (document, presentation, photo, video, or other) embedded in an App Studio Doc Card if presentation mode is enabled when the card is added to the app.

This process is described in two parts: first, the app creator enables presentation mode for a Doc Card; second, an app user downloads the applicable file.

### Enable Presentation Mode for Doc Card

Presentation mode is off by default. Enable it by following the steps below.

Open your App Studio app in edit mode and select the Doc Card where the file you want users to download is located.

1. In the **Settings** tab of the right configuration panel, select **Content Display Options** > **Presentation mode**.

   A checkmark displays by **Presentation mode**, meaning it is enabled for the card.

   <Frame>![](/images/kb/ka0Vq000000C3gT-00N5w00000Ri7BU-0EMVq000005Gbjt.jpg)</Frame>

2. Save the changes to your app and close edit mode.

### Download a Doc Card File

While viewing an app, if presentation mode is enabled for a Doc Card, an app user can download the file locally by following the steps below.

Open an app in view mode and locate the Doc Card containing the file you want to download.

1. Hover over the card and select <img src="/images/kb/ka0Vq000000C3gT-00N5w00000Ri7BU-0EMVq000005GapS.jpg" style={{width: 20, height: 20, display: 'inline', verticalAlign: 'start', margin: '0'}} /> **Expand** to open presentation mode.

   <Frame>![](/images/kb/ka0Vq000000C3gT-00N5w00000Ri7BU-0EMVq000005GZ8c.jpg)</Frame>

2. Select **Download** at the top of the screen.

   The file is downloaded locally.

   <Frame>![](/images/kb/ka0Vq000000C3gT-00N5w00000Ri7BU-0EMVq000005Ge6f.jpg)</Frame>
