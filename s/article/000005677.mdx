## Intro

SharePoint Online Writeback Connector enables organizations to create and manage custom team-focused and project-focused sites for collaboration. Use Domo's SharePoint Online Writeback connector to push data from a Domo DataSet to Sharepoint. To learn more about the SharePoint API, visit their page ([https://msdn.microsoft.com/en-us/lib.../jj860569.aspx](https://msdn.microsoft.com/en-us/library/office/jj860569.aspx "https://msdn.microsoft.com/en-us/library/office/jj860569.aspx") ).

You configure your Domo-Sharepoint connection in the Data Center. This topic discusses the fields and menus that are specific to the Sharepoint Online Writeback connector user interface. General information for adding DataSets, setting update schedules, and editing DataSet information is discussed in [Adding a DataSet Using a Connector](https://domo-support.domo.com/s/article/360042926274?language=en_US "Adding a DataSet Using a Connector").

## Prerequisites

To configure this connector, you must have the Domo Client ID and Client Secret. Learn how to get your [Domo Client ID and Secret](/s/article/000005240#create-api-clients).

#### To obtain your SharePoint Secret ID:

1. Go to [https://portal.azure.com](https://portal.azure.com/ "https://portal.azure.com").
2. Select **Azure Active Directory > App registrations**.
3. Find and click your web app.
4. The "application ID" is your **Secret ID**.

#### To obtain your SharePoint Value:

1. Go to [https://portal.azure.com](https://portal.azure.com/ "https://portal.azure.com").
2. Select **Azure Active Directory > App registrations**.
3. Find and click your web app.
4. Open **Certificates and secrets**.
5. Click **+New secret**.
6. Provide the value description and the expiry period for your secret.
7. Click **Add**.<br/><br/>

    Your new value will appear. Copy and paste in your Domo connector SharePoint client secret field.

## Troubleshooting

<AccordionGroup>
<Accordion title="I get 'Your DataSet could not be created' when I run the connector.">

This error generally points to a problem with the destination path or the connecting app's permissions rather than with the DataSet data itself. Check the following:

* **Folder path** — Confirm the value in the **Folder Path** field matches an existing location on the target SharePoint site. The folder path is case-sensitive, so it must match the site's folder names exactly (for example, `testFolder/TestNestedFolder`).
* **Site and file selections** — Verify that the site chosen in **Sites Discovery** (or returned by your **Site Search Query**) is the one you intend to write to, and that the **FileName** and **Where to Store the File?** selections are valid.
* **Credentials and app permissions** — Confirm the **Domo Client ID** and **Domo Client Secret** are current, and that the Azure app registration behind them still has the permissions required to write to SharePoint (see the **Prerequisites** section above).
