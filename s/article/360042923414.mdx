## Intro

This article explains how to add a rank or windowed row-number column to a DataSet using MySQL or RedShift DataFlow variables, how to keep rows that tie on a value, and how to restart the count when a value changes.

---

To create a rank or row count for a DataSet, you can use a MySQL or RedShift DataFlow.

## In MySQL

Type the following code in your DataFlow:

`Select`

`a.*`

``,@rank:= @rank + 1 AS `Rank` ``

`FROM your_dataset a`
  
`,(SELECT @rank:=0) b`

`ORDER BY ___`

## In MySQL Windowed

You can also create a windowed row count using variables. MySQL evaluates the FROM and ORDER BY portions of the query before evaluating the SELECT portion. Each column in the SELECT is then evaluated in order. You can take advantage of this order of evaluation to replicate the ROW\_NUMBER and other windowing functions.

Type the following code in your DataFlow:

`SELECT`

`` a.`Name`, ``

`` a.`Amount`, ``

`` CASE WHEN a.`Name` = @PriorRecordName then @RowNumber:= @RowNumber + 1 ``

`` WHEN a.`Name` <> @PriorRecordName then @RowNumber:= 1 ``

`END AS 'Windowed Row Number',`

`` @PriorRecordName:= a.`Name` ``

`` FROM `mydatatable` a, (SELECT @PriorRecordName:= '', @RowNumber:= 0) AS b ``

`` ORDER BY a.`Name, a.`Amount ``

In this query, the variables @PriorRecordName and @RowNumber are initialized before the SELECT portion of the query. The variables are initialized with the empty string and 0, respectively. Then, each column in the SELECT statement is evaluated in order. This method relies on the data being sorted correctly, so it is essential to include the `Name` and `Amount` columns in the ORDER BY of the query.

The CASE statement determines how the `Windowed Row Number` is set. If the value of `Name` matches the value of the @PriorRecordName, then @RowNumber is incremented by one and that value is returned as the `Windowed Row Number` column. However, if `Name` does not match @PriorRecordName, then @RowNumber receives the value 1 and that value is returned as the `Windowed Row Number`. Finally, the @PriorRecordName variable is set to the `Name` field value.

In its entirety, the query is returning rows in order, checking to see if the value of `Name` in the current row is the same as that in the prior row, and assigning a `Windowed Row Number` value accordingly.

## Keep All Rows That Tie on a Date

A `ROW_NUMBER()` filter assigns a unique number to every row, so filtering to row number 1 keeps exactly one row per group and silently drops ties. When several rows share the same latest date — for example, multiple plans that share the most recent `EFFDT` — use one of these approaches to keep all of them:

* **Rank instead of numbering.** In RedShift, use `RANK()` in place of `ROW_NUMBER()`. `RANK()` gives tied rows the same rank, so filtering to rank 1 keeps every row on the latest date:

  `RANK() OVER (PARTITION BY plan_id ORDER BY EFFDT DESC)`

* **Compare to the group maximum.** Compute the latest date per group and keep the rows that match it — for example, aggregate `MAX(EFFDT)` grouped by the same key, join that back to the data, and keep rows where `EFFDT` equals that maximum.

Add every column that defines the group to the `PARTITION BY` list. The partition, not the row order, is what determines which rows are compared.

## Rank on a Change in Value

To restart the count whenever a value changes, name that value explicitly as the partition (RedShift) or as the comparison column (MySQL). The windowed examples above rely on the `PARTITION BY` column — or, in MySQL, on the `@PriorRecordName` comparison together with the `ORDER BY` clause — to detect the change. Sort order alone is not enough: without an explicit grouping column, the query has no way to know where one group ends and the next begins, so include the grouping column in both the comparison and the `ORDER BY`.
