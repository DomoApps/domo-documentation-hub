## FAQs

<AccordionGroup>
<Accordion title="Is there an easy way to capture the current state of a DataSet and copy it into a new, independent DataSet?">

There are 3 solutions to this problem:

* Use Domo's DataSet Copy Connector. This Connector lets you copy DataSets within your instance or across instances. You will need a username, password, access token, and DataSet ID to create a copy of the DataSet. You may need to work with your MajorDomo to generate an access token for your instance. For more information about this Connector, see
  [DataSet Copy DataSet Connector](/s/article/360043436533 "DataSet Copy DataSet Connector").
* Set your DataFlow to just append rows. You will then get a "snapshot" for each time the DataSet updates. This will lead to a lot of duplicate data, which you can easily filter out for analysis by filtering on either \_BATCH\_ID\_ (a running counter of how many times that DataSet has been updated) or \_BATCH\_LAST\_RUN\_ (the date field of the last update time). Any analysis using a filter on these would always use the same data and you would have the bonus of getting a snapshot every day. So the DataSet would change, but any new data added would not affect your snapshot.
* Recreate the Connector configuration with the "Append" setting and you will have a completely independent DataSet (not just one connected in a DataFlow). (If you simply change the update settings of the existing Connector, you will have to filter for the most recent batch in all connected Cards so you do not get inflated numbers.)
</Accordion>

<Accordion title="Is it possible to 'snapshot' data on a daily basis to run point-in-time reports?">

Yes. Domo lets you create "append chains" across DataSets in order to snapshot. To do this, when configuring the **Update Settings** for the Connector, simply select **Append** instead of **Replace**. From there, you can use the "BATCH\_LAST\_RUN" value (a column Domo adds when a DataSet runs) as your snapshot date.

Note that by taking this approach, you must be careful when using this DataSet for non-snapshot use cases since it automatically counts all historical values instead of the latest snapshot. You can run this kind of DataSet through an ETL or SQL DataFlow to add a "Latest" column that flags the records that came in as part of the last run. You can then use that column as a filter for Cards that satisfy a current, not snapshot, use case.
</Accordion>

<Accordion title="I am not seeing a particular field (column) in a report when I import data using a certain connector. Can Domo add this field for me?">

If you would like to have a certain field, value, etc. added to a Connector, you can submit an enhancement request to our Product team using the **Feedback** option in the **More** menu in your Domo instance and let them know which field you would like added to the Connector. Our Product team reviews every enhancement request submitted this way and will contact you if the field can indeed be added.
</Accordion>

<Accordion title="Can I use the Date/Time field as merge keys in connectors?">

No, we do not support Date/Time fields as merge keys because Date/Time columns are not guaranteed to be unique.
</Accordion>

<Accordion title="I can't find a connector I need in the Domo Appstore. Can I build a custom connector?">

Domo has hundreds of pre-built Connectors and is always adding more to the list. In the event that you find yourself needing to get data into Domo from a system or writeback data from Domo to a system, and a Connector for this purpose does not already exist, contact your Account Executive or Customer Success Manager to discuss the option of creating a new Connector or updating an existing Connector.

If you're a little more technical, you can use our Connector IDE to build your own to any custom Connector. To get started, see our [Developer Portal](https://developer.domo.com/connect-to-domo "https://developer.domo.com/connect-to-domo"). For a list of all of our third-party custom Connectors currently available, see Available Custom Connectors.
</Accordion>

<Accordion title="Is it possible to refresh my data faster than every 15 minutes?">

Yes, in order to do this, please reach out to your account team for evaluation.
</Accordion>

<Accordion title="Is there a limit to the number of columns that can be imported using a connector?">

Yes, Connectors allow for up to 1,500 columns in a DataSet.
</Accordion>

<Accordion title="How do connectors authenticate with a source that requires multi-factor authentication (MFA)?">

Most Domo connectors authenticate to your source system with a single stored set of credentials (a service account) and run unattended on a schedule. Because no person is present to respond to an interactive MFA prompt when the connector runs, a connector generally cannot complete a login that requires interactive MFA at connection time.

If your source enforces MFA, consider the following approaches:

* Use a dedicated **service account** that is exempt from interactive MFA, if your source supports one.
* Use an **app password** (a source-generated credential that bypasses the interactive MFA prompt) where the source offers one.
* Use a connector that authenticates with **OAuth** for that source, where one is available.

<Accordion title="Why didn't my DataSet empty when a Replace run returned zero rows?">

When a connector run returns no rows, Domo does not overwrite the existing DataSet with an empty result — even when the update method is set to **Replace**. Retaining the previous data helps protect against a source or query problem silently wiping your DataSet. The existing data is kept until a run returns rows.

If you need a zero-row run to actually clear the DataSet, a common workaround is to UNION a single sentinel (placeholder) row into your source query so the run always returns at least one row, then filter that row out downstream in a DataFlow or DataSet View.

## Troubleshooting Specific Errors

<AccordionGroup>
<Accordion title="Cloudflare is preventing me from connecting.">

If you have Cloudflare running, be aware that this may prevent the Domo Connector from connecting to your server. If this is the case, you will need to configure Cloudflare to allow access to the connector. This page explains how to do this:

https://support.cloudflare.com/hc/en-us/articles/200171806-Error-1010-The-owner-of-this-website-has-banned-your-access-based-on-your-browser-s-signature
</Accordion>

<Accordion title="I get the error message 'FTP is not supported' when configuring the CSV Advanced/XML Advanced/JSON Connector.">

Due to security concerns, Domo no longer permits uploading data using FTP. If necessary, please update your server settings to support SFTP instead of FTP.
</Accordion>

<Accordion title="I've configured my Netsuite connection correctly as shown in Connecting to NetSuite Data in Domo, but I keep getting an 'Unexpected Error' message.">

Check your Netsuite column names for invalid characters such as apostrophes, quotation marks, backslashes, etc.
</Accordion>

<Accordion title="My spreadsheet upload failed (unsupported file, macro-enabled workbook, or 'no data found').">

When uploading a spreadsheet with a file connector, check the following:

* **Macro-enabled workbooks (.xlsm) are not supported.** Save the workbook as a standard **.xlsx** file and upload that instead.
* If you see a message that the file is not supported and to use a legacy connector, the file's format or version isn't handled by the current uploader. Re-save the file in a supported format (for example, **.xlsx** or **.csv**) and try again.
* A **"no data found"** message usually means the sheet Domo read was empty or the data didn't start where expected. Confirm the correct sheet is selected, remove blank leading rows, and make sure the header row and its data are present.

<Accordion title="Dates from an Excel file pulled through the Box connector came in as numbers.">

Excel stores dates internally as serial numbers. When the Box connector reads an Excel file, date cells can be ingested as those underlying numeric serial values rather than as formatted dates. To recover date typing, convert the numeric value back to a date in Magic ETL — add a formula/column that converts the Excel serial number to a date, then set the resulting column's type to Date.

<Accordion title="My connector failed with a vague message like 'Domo is ready but…' or 'Failed to execute import successfully.'">

These are generic wrapper messages Domo shows when a connector run does not complete. They rarely name the real problem on their own — the underlying cause is usually in the response the source API returned (an authentication failure, a bad parameter, a rate limit, or a source-side outage). To find it, read the underlying API error (see "How can I see the underlying API error behind a connector failure?" below), then correct the configuration or credentials the source is rejecting.

<Accordion title="I get the error 'Indexing failed: Empty primary key.'">

This error occurs when the DataSet is indexed on an upsert or merge key and one or more rows have an empty (null or blank) value in a key column. Every row must have a non-empty value in each key column. Check the source data or query for rows with a missing key value, and either populate the key or filter those rows out before the data is imported.

<Accordion title="I get an error that the schema has too many columns (maximum 1,500).">

Connectors allow up to **1,500 columns** in a DataSet. If a run fails because the schema exceeds this limit, reduce the number of columns the source returns — select only the fields, reports, or objects you need instead of pulling everything, or split the data across more than one DataSet. Removing unused columns downstream does not help; the limit applies to what the connector brings in.
</Accordion>

<Accordion title="How can I see the underlying API error behind a connector failure?">

When a connector shows a generic failure, the source system's own error is often visible in your browser's developer tools:

1. Open your browser's developer tools (usually **F12**, or right-click and select **Inspect**) and select the **Network** tab.
2. Reproduce the action that fails — for example, run or validate the connector.
3. Find the failed request (often shown in red, or with a 4xx/5xx status).
4. Select it and review the **Response** (and **Headers**) to see the exact error message and status the source API returned.

Use that message to identify the real cause — for example, an expired token (401), a permissions problem (403), a bad parameter (400), or a rate limit (429).
</Accordion>

<Accordion title="An OAuth-based connector suddenly returns zero rows or stopped pulling data.">

OAuth connections rely on an access token that is periodically renewed with a stored refresh token. If the refresh token expires or is revoked — for example, because the granting user changed their password, lost access, or the source's token lifetime elapsed — the connection can stop returning data, sometimes without a hard failure. To restore it, re-authorize the account: go to the **Accounts** tab in the Data Center, open the affected connector account, and reconnect (sign in again through the source's OAuth screen). For more information about managing accounts, see [Managing User Accounts for Connectors](/s/article/360042926054).

<Accordion title="A Google connector is blocked by our Google Workspace admin settings.">

If your organization uses Google Workspace, an administrator may need to trust or approve the Domo app before it can connect, even when the individual user's credentials are correct. This is the same root cause behind Google Sheets connections that fail for managed accounts. Ask your Google Workspace administrator to approve/trust the Domo app in the Google Admin console's app-access controls, then reconnect the account.

## Connector Best Practices

* Know your data. Have a vision for the data you expect to pull and how it will be used.
* Think about the range of data, and pull in data according to what you will use. Only bring in the data you need.
* Think about scheduling, especially with regards to the following:

  + How is the data structured?
  + How will the data be viewed?
  + Be mindful of resources (look at associated DataSets).
  + Remember data runs in UTC time!
