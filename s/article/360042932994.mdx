## Intro

You can share access rights for cards and dashboards with groups and users. In the **Share** dialog, you can share and remove access for any resource to which you have access. This dialog is available for all cards and dashboards.  If you have an Admin default security role or a custom role with the Manage All Cards, Pages and Apps (App Studio) grant enabled, you can share any card or dashboard. For more information about default security roles, see [Managing Custom Roles](/s/article/360043438973 "Default Security Role Reference").

When you share cards and dashboards, Domo sends an email to those with whom you shared the cards and dashboards. You can enter a message to be added to the email.

<Frame><img alt="" src="/images/kb/ka0Vq0000002mbd-00N5w00000Ri7BU-0EM5w000005vOHY.png"/></Frame>
You can choose whether to send notifications when you share content with others. You do this by toggling the **Send email notifications** option in the **Share** dialog.

You can also choose to receive notifications when content is shared with you. You do this in the Manage Notifications & Alerts screen. For more information about this screen, see [Managing Your Alerts](/s/article/360043430533 "Notifications and Alerts").

When you share a card with a user or group, access to the DataSet(s) powering the card is granted to that user or group.

For administrative information about granting and restricting access to content to users and groups, see [Controlling Access to Cards and Pages](/s/article/360042934254 "Controlling Access to Cards and Pages").

For information about specifying group content in the Overview Page for group members, see [Specifying Default Overview Content for Users](/s/article/360043439153 "Specifying Default Overview Content for Users").

For information about sharing Pages and Subpages, see [Managing Pages](/s/article/360043428253 "Managing Pages").

<Note>
  **Notes:**

  * If you share a card with someone, that person will be able to view the card AND the DataSet it is powered from.
  * If you share a card powered by a DataFlow-generated DataSet...

  + If the user already has access to cards that grant them access to all of the input DataSets in the DataFlow, they can view the DataFlow.
  + If the user does not have access to Cards that grant them access to all of the input DataSets in the DataFlow, they cannot see the DataFlow.

  Learn how to create a Magic ETL DataFlow .

</Note>

## Share Access to Resources

When you share access to a card with a user, a copy of that card is sent to the user's **Shared** page; when you share access with a group, a copy of the card is sent to the **Shared** page of every member of the group. When you share access to a dashboard with a user, the dashboard is added to the user's **Dashboards** pane, displayed on the left side of the screen; when you share access with a group, the dashboard is added to the **Dashboards** pane for every member of the group.

<Note>
  **Troubleshooting group access:** When you share a card or dashboard with a group, access normally propagates to every current member of the group. If some group members report they still can't see content that has been shared with their group, remove the group from the **Access List** (see [Remove Access to Resources](#remove-access-to-resources)) and then share the content with the group again. Re-sharing forces access to propagate to all current members.

## Remove Access to Resources

You can also remove access to resources for certain users or groups in the **Share** dialog.

**To remove access from users or groups,**

1. Locate the user or group name in the **Access List**.
2. Click the "X" to the right of the corresponding user or group name in the **Access List**.

   <Note>
     **Note:** When a member of a shared group is removed from the group, sharing of the card is removed, unless access is granted via another group or as a user. For more information, see [Controlling Access to Cards and Pages](/s/article/360042934254 "Controlling Access in Domo").

   </Note>

## Link to a Filtered Page or Card View

Sharing through the **Share** dialog opens content in its default state. To point someone at a *specific filtered view* in your Domo instance — for example, a dashboard pre-filtered to one region or sales rep — build an in-app deep link from the target's object ID and one or more `pfilters` URL parameters. This link opens in a browser that is signed in to Domo and is distinct from the `pfilters` used for embedded content, which apply to a Domo iframe hosted outside Domo.

**To build a filtered deep link,**

1. Copy the object ID from the URL of the content you want to link to:

   * **Dashboard (page):** open the dashboard. The page ID is the string of numbers after `/page/` in the URL — for example, `https://mycompany.domo.com/page/123456789`.
   * **Card:** open the card. The card ID is the string after `/kpis/details/` in the URL.

2. Append a `pfilters` query parameter to the URL. Each filter specifies the `column`, `dataSourceID` (the DataSet ID), `dataType`, `operand`, and `values` to filter on — the same filter pattern used by programmatic filters. Encode quotation marks as `%22`.

3. Share the finished URL with anyone who already has access to the content. When they open it, the page or card loads with your filter already applied.

For the full `pfilters` syntax — including multiple filters and a Beast Mode recipe that generates these deep links dynamically from a Table card — see [Sample Beast Mode Calculations: Miscellaneous Transforms](/s/article/360043430113 "Deep Linking with Filters").

<Note>
  **Note:** A deep link does not grant access. Recipients still need access to the content and to any PDP policy on the underlying DataSet, and the filtered view respects each viewer's own permissions.
</Note>

<Note>
  **Note:** Building the URL by hand, as described above, is currently the way to create a shareable filtered-view link.
