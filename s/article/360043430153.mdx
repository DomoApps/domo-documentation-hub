## Intro

This article describes how to troubleshoot common errors when using Beast Mode calculations, including case statement formatting, date formatting, and others.

---

## The "Aggregated and Non-aggregated Columns" Warning

When a calculation combines an aggregated expression (such as `SUM()` or `COUNT()`) with a row-level column, the editor shows the message **"This calculation uses both aggregated and non-aggregated columns."** This is a **warning, not a blocking error** — the calculation still saves and the card still renders. It is safe to ignore when the non-aggregated column resolves to a single value per group shown on the card; it signals a real problem (duplicated rows, blank cells, `*****` pivot errors, or grand totals that re-evaluate a `CASE` instead of summing) when that column takes more than one value within a displayed group. For the full explanation, worked examples, and fixes, see [Use Non-aggregated Columns in Aggregated Beast Modes](/s/article/000005559 "Use Non-aggregated Columns in Aggregated Beast Modes").

## Case Statement Formatting

A case statement requires a few keywords placed in a particular order.

```
    CASE
    WHEN `State` = 'California'
    THEN 'CA'
    ELSE `State`
    END
```
  
The case statement will be in error if it doesn't include these elements or is not written correctly.
  
You can include as many `WHEN` conditions as you would like, but must have a `THEN` for every `WHEN.`

```
    CASE
    WHEN `State` = 'California'
    THEN 'CA'
    WHEN `State` = 'Washington'
    THEN 'WA'
    ELSE `State`
    END
```

## Date Formatting

The functions you can use are `DATE_FORMAT()` and `STR_TO_DATE()`. When using the `STR

_TO_DATE()` function you must use the exact same format your string column is already in so that the function can properly convert it to a date type.
  
For example, you have a string type column,`Date,` that needs to be converted to a date type. The format of your values is MM-DD-YYYY.
  
`` STR_TO_DATE(`Date`,'%m-%d-%Y') ``
  
If your values are formatted as YY/DD/MM, then use
  
`` STR_TO-DATE(`Date`,'%y/%d/%m') ``
  
After you have a date type column, if you want to change the format, use the `DATE_FORMAT()` function. This function can accept and generate any date format needed.
  
Your `Date` column is formatted as DD-MM-YY, but you would like to see it as MM-DD-YYYY
  
`` DATE_FORMAT(`Date`,'%m-%d-%Y') ``
  
To learn more about which date format specifiers to use, such as `%m` or `%y`, see [Date Format Specifier Characters in Beast Mode](/s/article/360043429953 "Date Format Specifier Characters in Beast Mode").

## Field name vs. String Value vs. Numeric Value.

In calculations, the actual field name is referenced using the backtick (` ). Inputting a hard string value requires single quotes (' ), while referencing a numeric value requires no quotes.
  
```
CASE WHEN `Return Customer?` = 'Y' THEN 1
WHEN `Return Customer?` = 'N' THEN 0
END
```

<Note>
  **Note:** Putting single quotes (') around numeric values will NOT result in an error but will output the 1s and 0s as a string-type column.

</Note>

## Strings Compared to Dates

When using the `DATE_FORMAT()` function, this converts the value to a `varchar` datatype, also known as a string. This is problematic because you can longer use the value as a date such as for comparisons. If your column should be a `date` format after using the `DATE_FORMAT()` function, then you need to use `STR_TO_DATE()` to convert it back to a date type.
  
Using the following calculation, the output would be a string-type column.
  
`` DATE_FORMAT(`Date`,'%m-%d-%Y') ``
  
To convert the string to a date, we would want to wrap our entire calculation in the `STR_TO_DATE()` function.
  
`` STR_TO_DATE(DATE_FORMAT(`Date`,'%m-%d-%Y'),'%m-%d-%Y') ``
  
In the case that you have a string column that needs to be converted to a date column and you want it formatted differently, you must do the following:
  
`` STR_TO_DATE(DATE_FORMAT(STR_TO_DATE(`Date`,'%y-%m-%d'),'%m-%d-%Y'),'%m-%d-%Y') ``
  
Because it works from the inside out, the `` `Date` `` column, which is formatted as YY-MM-DD is first converted to a date. We would like to see the column as a MM-DD-YYYY format, so we then use `DATE_FORMAT()` to do so. However, now we are left with a string-type column. Lastly, we will use the STR

\_TO\_DATE() function to return it to a date type.

## Use of Trim Function

Many times, strings will leave unwanted spaces at the end or beginning of the value. This is problematic when using formulas that call out the exact value. The `trim()` function will trim off any unnecessary white space.
  
For example, if the `Zipcode` column contains values that have white space, such as '12345   '. Knowing white space exists in your values is extremely important if you are, for example, using the `COUNT()` function. `COUNT()` will count the number of characters in a string, including white space. By using the `trim()` function first, you ensure that you count only the number of valid characters in your `Zipcode` values.
  
`` COUNT(TRIM(`Zipcode`)) ``

## "A Column in the Calculation Does Not Exist"

This error usually means a string literal was left unquoted, so Beast Mode is trying to read it as a column name. Wrap string values in single quotes so they aren't interpreted as columns:

```
CASE WHEN `Status` = Won THEN 1 ELSE 0 END      -- error: Won is read as a column
CASE WHEN `Status` = 'Won' THEN 1 ELSE 0 END    -- correct: 'Won' is a string value
```

The same error appears when a calculation references a column that isn't in the DataSet powering the card — for example, a mistyped column name, or a shared Beast Mode that expects a column the current DataSet doesn't have.

## COUNT vs. SUM of a CASE Statement

Both `COUNT` and `SUM` can aggregate a `CASE`, but they behave differently:

- `COUNT(CASE WHEN ... THEN 1 END)` counts the rows that match the condition. Non-matching rows return `NULL` (there is no `ELSE`), and `COUNT` ignores `NULL`, so only matching rows are counted.
- `SUM(CASE WHEN ... THEN 1 ELSE 0 END)` adds up the 1s, which also totals the matching rows. Here the `ELSE 0` is required so every row contributes a numeric value.

Avoid mixing the two patterns. `COUNT(CASE WHEN ... THEN 1 ELSE 0 END)` counts *every* row — both the 1s and the 0s — which is a common cause of inflated counts.

## CASE Evaluation Order

A `CASE` statement evaluates its `WHEN` conditions from top to bottom and stops at the first one that is true. Order your conditions from most specific to most general so that a broad condition doesn't capture rows before a narrower one can. For example, place a `> 90` bucket before a `> 50` bucket; otherwise every value above 90 is caught by the `> 50` condition first.

## Syntax Error Checklist

If you see the message "This calculation contained a syntax error," check the following:

- Column names are wrapped in backticks: `` `column` ``.
- String values are wrapped in single quotes: `'text'`.
- Numeric values have no quotes.
- Every `CASE` has matching `CASE`, `WHEN`, `THEN`, and `END` keywords, with a `THEN` for each `WHEN`.
- Aggregations wrap the entire expression rather than sitting inside the `CASE` — for example, `SUM(CASE ... END)`, not `CASE ... THEN SUM(...) END`.

## HTML-Encoded Characters in Text Values

Text imported from web sources sometimes contains HTML-encoded characters — for example, an ampersand stored as `&amp;` instead of `&`, or an apostrophe stored as `&#39;` instead of `'`. These encoded values can display inconsistently: a table cell might show the raw code (`AT&amp;T`) while a chart tooltip shows the decoded character (`AT&T`), or the reverse.

The most reliable fix is to normalize the values upstream in Magic ETL, before they reach the card, using `REPLACE` in a formula tile to swap the encoded string for the character you want:

```
REPLACE(`Company`, '&amp;', '&')
```

You can stack multiple `REPLACE` calls to handle several encoded characters. Because normalizing in Magic ETL writes the corrected value back into the DataSet, every card, table cell, and tooltip then reads the same clean text.
