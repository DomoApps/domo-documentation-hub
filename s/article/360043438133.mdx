Follow the steps in this topic to set up Okta as a SAML 2.0 identity provider for Domo. You must have an "Admin" default security role or a custom role with "Manage All Company Settings" enabled to set up SAML. For more information about default roles, see [Managing Custom Roles](/s/article/360043438973 "Default Security Role Reference").

## Prerequisites

If you don't already have an Okta tenant, sign up for one at [okta.com](https://www.okta.com) and complete the activation email Okta sends you.

**To set up Okta in Domo,**

1. Sign in to the Okta Admin Console at `https://<your-org>-admin.okta.com`.
     
   {/* TODO[screenshot]: Okta Admin Console home page showing the left-hand navigation with Applications expanded */}
2. In the left navigation, go to **Applications** > **Applications**, then select **Create App Integration**.
     
   {/* TODO[screenshot]: Applications list page with the Create App Integration button highlighted */}

   <Note>
     **Note:** A prebuilt Domo app is available in the Okta App Integration Catalog and can be used instead of creating a new app integration. However, the catalog app may not support all the current capabilities of Domo SSO.
   </Note>
3. In the **Create a new app integration** dialog, select **SAML 2.0**, then select **Next**.
     
   {/* TODO[screenshot]: Create a new app integration dialog with SAML 2.0 selected */}
4. On the **General Settings** step, enter the **App name** (for example, `Domo`) optionally upload an app logo, and select **Next**.
5. On the **Configure SAML** step, complete the SAML fields using the values from Domo's SAML setup page in **Admin Settings** > **Security** > **SAML**. At a minimum, set the following:

   * **Single sign-on URL** — in Domo, this is labeled as the [SAML Assertion Endpoint URL](/s/article/000005827#information-your-idp-may-need).
   * **Audience URI (SP Entity ID)** — in Domo, this is called the [Domo Entity ID](/s/article/000005827#information-your-idp-may-need) (typically your Domo subdomain, for example `videotraining`).
   * **Name ID format** — **EmailAddress**.
   * **Application username** — User **Email**. The unique identifyer of the user in Domo.

   <Note>
     **Note:** Your Domo URL determines the subdomain value. For example, if your Domo URL is `videotraining.domo.com`, your subdomain is `videotraining`.
   </Note>
6. (Optional) To send Okta group memberships to Domo, scroll to **Group Attribute Statements** and add an attribute. Set **Name** to `groups`, **Name format** to **Unspecified**, **Filter** to **Regex**, and the filter value to `.*` to send all groups. Select **Next**.
     
   For additional context, see [Okta's documentation on configuring SAML group attributes](https://help.okta.com/en-us/content/topics/apps/define-group-attribute-statements.htm).
7. On the **Feedback** step, select **I'm an Okta customer adding an internal app**, then select **Finish**. Okta opens the new Domo app's **Sign On** tab.
8. On the **Sign On** tab, select **View SAML setup instructions** (in the **SAML Signing Certificates** section on the right) and copy the **Identity Provider Single Sign-On URL**, **Identity Provider Issuer**, and **X.509 Certificate** into the matching fields on Domo's SAML setup page. Save the SAML configuration in Domo.
     
   {/* TODO[screenshot]: Okta Sign On tab for the Domo app with the View SAML setup instructions link visible */}
9. (Conditional) If you configured the `groups` attribute statement in step 6 and want Domo to import those groups, in Domo's SAML setup page check **Import groups from identity provider** and save.
10. Back in the Okta Admin Console, open the Domo app and select the **Assignments** tab to grant access to users and groups.
      
    {/* TODO[screenshot]: Assignments tab of the Domo app in Okta showing the Assign dropdown */}
11. To assign users, select **Assign** > **Assign to People**, find each user, select **Assign**, confirm the user attributes, and select **Save and Go Back**. Select **Done** when finished.
12. To assign groups, select **Assign** > **Assign to Groups**, then select **Assign** next to each group that should have access to Domo. Select **Done** when finished.
      
    <Note>
      **Note:** A good best practice is to maintain one Okta group per client or team and assign that group to the Domo app. Adding or removing a user from the group grants or revokes their Domo access automatically.
    </Note>
13. (Optional) To create a new group in Okta, go to **Directory** > **Groups**, select **Add group**, enter a name and description, and select **Save**. Then open the group, select the **Applications** tab, and select **Assign applications** to give the group access to the Domo app.
      
    {/* TODO[screenshot]: Directory > Groups page with the Add group button visible */}
14. (Optional) To create a new user in Okta, go to **Directory** > **People**, select **Add person**, complete the form (including any groups the user should belong to in the **Groups** field), and select **Save**. New users receive an Okta activation email; their status changes to **Active** after they set a password.
      
    {/* TODO[screenshot]: Directory > People page with the Add person dialog open */}

Once the SSO setup is complete, a new option appears in the publication groups configuration in Domo. In the **Add Group** section you can enter an individual user email that has Domo access in Okta, or an Okta group that has access to the Domo app.

Users can then access Domo in either of the following ways:

* Sign in to Okta at `https://<your-org>.okta.com` and select the **Domo** tile on their dashboard. They are taken directly into Domo.
    
  {/* TODO[screenshot]: Okta end-user dashboard showing the Domo app tile */}
* Sign in at the Domo instance URL and choose **Single Sign-On**. They are prompted for their Okta credentials (or signed in automatically if they already have an active Okta session).
