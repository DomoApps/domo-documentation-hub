## Append Rows Tile

<Frame>
<img alt="Append_Rows.png" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EM5w000005vNhU.png"/>
</Frame>

The Append Rows tile lets you append rows from multiple DataSets (with similar columns and data structure) into one DataSet, returning occurrences of all matches, including duplicate rows.

<Note>
  **Note:** You can only append data rows from input DataSets having the same data structure and data type. If the data structures do not match, the Append Rows tile creates extra columns to accommodate the non-matching data. For example, if you tried to append text to a whole numbers column, two columns would be created—one for the whole numbers column and one for the text column.
</Note>

### Configure the Append Rows Tile

1. Select the **Append Rows** tile on the canvas to open the tile editor.
2. (Optional) At the top of the tile editor, rename the tile by selecting **Edit** and entering the name you want.
3. In the **Configuration** tab of the tile editor, select the dropdown in step 1 and choose which columns to include in the append from the following options:

   * **Include columns from DataSet —** Select one of the input DataSets to include its columns.
   * **Include all columns —** Includes unique columns from all of the input DataSets.
   * **Only include shared columns —** Includes only columns that are used in every input DataSet.
4. Choose how to handle when column types don't match: **Use best compatible data type** OR **Display a type error**.
5. Review changes to be made to each DataSet.
6. Select **Done** in the top right corner of the tile editor.

   <Tip>
     **Tip:** You can preview the data transformed by a tile by selecting **Run Preview**. When the transform is complete, the results are available in the **Preview** tab of the tile editor.
   </Tip>

## Join Data Tile

<Frame>
<img alt="Screenshot 2024-11-11 at 3.24.06 PM.png" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000003kPkr.jpg"/>
</Frame>

With the Join Data tile, you can combine columns from two DataSets or data “streams” into one DataSet using common values in a specific column or set of columns.

<Warning>
  **Important:**
  * The specific column you use to combine rows must exist in both DataSets and have the same data structure.
  * For Inner, Left Outer, and Fill Outer joins, specify the primary or "lookup table" with the unique values as the first input DataSet (on the left). The identifying column cannot have more than 10,000 duplicates of any value.
</Warning>

1. Connect the two input DataSets you want to combine to a Join Data tile on the canvas.
2. Select the **Join Data** **tile** to open the tile editor at the bottom of the screen.
3. (Optional) In the tile editor, rename the tile by selecting **Edit** by the name field and entering the name you want.
   
   <Frame>

#### Write a Join Expression

If you choose **+ Expression condition** in step 2 of the tile editor, use the freeform field to write an expression that identifies the relationship between the tables.

<Frame>
<img alt="Screenshot 2024-11-13 at 12.41.33 PM.png" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000003nQE9.jpg"/>

Select **Expand** (diagonal arrows icon) to open the formula editor so that you have more room to compose your join expression.

You can use inequality operators such as (such as \<, >, >=, and \<+); keywords that allow you to indicate the relationship as a range (like BETWEEN); and other functions you might use in a SQL-based join.

Select **Validate formula** (circular arrows icon) to validate your join expression before running your DataFlow.

### Join Types

This table describes the available join types.

|  Join         |  Description                                                                                                                   |
|---------------|--------------------------------------------------------------------------------------------------------------------------------|
|  Inner        |  Includes only matching rows in both input DataSets.                                                                           |
|  Left Outer   |  Includes all rows from the first input DataSet (on the left) and matching rows from the second input DataSet (on the right).  |
|  Right Outer  |  Includes all rows from the second input DataSet (on the right) and matching rows from the first input DataSet (on the left).  |
|  Full Outer   |  Includes all rows from both input DataSets.                                                                                   |

### Join Data Configuration

The gear next to the **Join Type** dropdown menu provides you with the option to restrict your joins to one of several types:

* Many to Many (Not Restricted)
* Many to One
* One to Many
* One to One

<Frame>
<img src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000005buWb.jpg"/>
</Frame>

This setting is optional and is not needed for the **Join Data** tile to function. When set, it does make it easier to prove that a join is working as intended in some cases.

Selecting one of the options validates the constraint at the time the join attempts to execute in the DataFlow. If the constraint is violated (for example, multiple values are in the right table and join to the same key on the left when the relationship is set as one-to-one), then you receive an error, and the DataFlow is terminated.

Each option enforces a different expectation about how join-key values relate between the two tables:

| Relationship Type | What It Enforces |
| --- | --- |
| Many to Many (Not Restricted) | No constraint is enforced. Any number of rows on either side can share the same join key. This is the default. |
| Many to One | Multiple rows in the left table can match the same row in the right table, but each left-table row matches at most one right-table row. |
| One to Many | Each left-table row can match multiple right-table rows, but each right-table row matches at most one left-table row. |
| One to One | Each join key matches at most one row in each table. |

Leave the setting at **Many to Many (Not Restricted)** if you do not need the integrity check.

### Troubleshoot a Join

Use the following guidance when a join does not return the columns or rows you expect.

**A column is missing from the join field list.** The dropdowns in the join criteria only list columns that reach the Join Data tile. If a column was dropped by an upstream Select Columns tile, or is restricted by Personalized Data Permissions (PDP) on the input DataSet, it will not appear as a join field. Add the column back in the upstream tile so it flows into the join.

**The join key is not matching.** The columns you join on must share the same data type. A text key will not match a numeric key even when the values look identical, and differences such as zero-padding (for example, `007` versus `7`) prevent a match. Cast one side to match the other with a Set Column Type or formula tile upstream, and confirm both keys are formatted the same way. For more on preparing join keys, see [Join DataSets by Adding a Unique Key Column](/s/article/360043427933).

**A Left Outer join still shows only matched rows on a card.** A Left Outer join keeps every row from the left table, but the right-table columns are null for rows that did not match. On a card, a filter on a right-table field—or a series or aggregation that excludes nulls—can hide those unmatched rows so the result looks like an inner join. Check the card's filters and fields, and wrap right-table columns in IFNULL in a downstream formula tile to give unmatched rows a default value.

## Split Join Tile (Limited Release)

<Warning>
  **Important:** The Split Join tile is currently only available for Magic ETL on Snowflake or Databricks. It is targeted for general release by the end of 2025.
</Warning>

If you have a Domo integration with Snowflake or Databricks, you can access the Split Join tile in Magic ETL. This tile allows you to have multiple output streams from a join in your DataFlow. It is useful when you want to see the results of a join and when rows didn't join from the left or right tables.

### Configure Split Join Tile

1. Drag a Split Join tile to the canvas from the **Combine Data** section of the left panel. This tile has a bigger footprint on the canvas than a standard tile, and it grows as you add more output streams.
2. Connect the left and right tables on your canvas to the tile.
     
   <Frame>
   <img alt="" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000008k1XZ.jpg"/>
   </Frame>

3. Configure your join and column handling in the tile editor as you would with a regular
   [Join Data](#configure-the-join-data-tile) tile.
     
   <Frame>
   <img alt="" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000008k2Bt.jpg"/>
   </Frame>
   
4. Under **Output Names**, check the boxes next to the output you would like. You can rename them.
     
   <Frame>
   <img alt="" src="/images/kb/ka0Vq000000G5AD-00N5w00000Ri7BU-0EMVq000008k2IL.jpg"/>

   The outputs you select display on the canvas in multiple nodes.
