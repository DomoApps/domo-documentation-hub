## Intro

A "recursive" or "snapshot" DataFlow is a DataFlow that uses itself as an input.

DataFlows (both SQL and Magic ETL) cannot append data natively like Connectors. However, if you need to create a DataFlow that appends data, you can do so by running it once and then using the output as part of the input for the next run. By doing this, every time the DataFlow runs, it includes the data from before and also appends the new data onto itself.

<Warning>**Important:** There are significant behavioral differences in Magic ETL. Read the [Behavior Changes and Feature Updates in Magic ETL](/s/article/360047787514) article before converting mission-critical Magic ETL DataFlows. ** Failure to do so may cause an unintended change to your DataFlow's behavior.**</Warning>

To avoid this any time you are editing, create an additional DataSet that is a copy of your historical DataSet. This DataSet will remain static. If anything happens to your historical DataSet, you will have a backup from before you began editing.</Warning>

## Output Dataset Targeting Rules

Keep these rules in mind when deciding where a Magic ETL DataFlow writes its output:

- **An output can equal an input only in a recursive DataFlow.** Pointing an output DataSet back at one of the flow's own input DataSets is exactly the recursive pattern described in this article. Outside of that pattern, reusing an input as an output isn't supported.
- **You can't natively retarget an output to an arbitrary existing DataSet.** Magic ETL writes each output to the DataSet it created for that output tile. There's no native option in the editor to redirect an output to write into a different, pre-existing DataSet.

## Choosing a Snapshot Approach

There are several ways to keep a history of your data over time. Use this comparison to choose the one that fits your needs:

| Approach                                                         | How it works                                                                                                                                                                                                                           | Use when                                                                                                                                    |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| Recursive DataFlow                                               | The DataFlow feeds its own output back in as an input and appends new rows on each run, maintaining the full history inside one Magic ETL DataFlow (described in this article).                                                        | You want history maintained within a single DataFlow and control over how new rows are matched and appended.                                |
| [DataSet Copy connector](/s/article/360043436533) in Append mode | On a schedule, the connector copies a source DataSet into a separate DataSet whose update mode is set to **Append**, stamping each run with meta columns—including **Batch Last Run**—so every snapshot is time-stamped automatically. | You want to snapshot a DataSet on a schedule without editing the source DataFlow, and you want an automatic run timestamp on each snapshot. |
| Date spine / calendar join                                       | You join your data to a generated date (calendar) dimension so there is a continuous row per date.                                                                                                                                     | You need a complete, gap-free row per date regardless of whether the source produced data for that date.                                    |

To keep current and historical data together, combine your current DataSet with the historical (snapshot) DataSet using an **Append Rows (Union)** tile. For a worked example of appending year-to-date data into a historical archive, see [Archiving Historical Data Using a DataFlow](/s/article/360043428073).
