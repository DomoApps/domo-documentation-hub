## Intro

The following troubleshooting steps can help you solve common issues in Jupyter Workspaces. If your issue is not listed here, or the steps do not resolve your issue, contact your Account Executive (AE) or Customer Success Manager (CSM).

For general information about Jupyter, see our [Jupyter Workspaces | User Guide](/s/article/36004740075).

## Jupyter Workspaces Won't Start

If Domo reports an error after you have attempted to start Jupyter or the status returns to "Stopped" instead of "Started," your user most likely does not have a usage policy configured by an Admin.

<Frame><img alt="mceclip0.png" src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EM5w000005vNu5.png"/></Frame>
Follow these steps to fix the issue:

1. In the navigation header, select
   **Admin** > **Feature Settings** > **Jupyter** and make sure that:
   1. The
      **Jupyter Account Activated** toggle is enabled
   2. If the
      **Active Account Plan** is set to **Manual**, you or the user have a usage policy with an appropriate instance size limit.

   <Frame><img alt="Screenshot 2024-12-11 at 2.25.19 PM.png" src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EMVq000004II5p.jpg"/></Frame>

## Error Installing Third-Party Libraries

If you receive a failure when installing third-party libraries for Python or R, the library or its dependencies are not compatible with the current conda environment.

Follow these steps to resolve the issue:

1. Install the appropriate conda pip command from a workspace terminal. Include the conda channel if necessary.

   <Frame><img alt="mceclip2.png" src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EM5w000005vNtp.png"/></Frame>
2. If the conda install fails in the terminal, try a pip/cran command.

   pip command:

   ```
   pip install -U scikit-learn
   ```

   R/cran command:

   ```
   install.packages("cluster")
   ```

3. Navigate to the Jupyter Workspaces list, select
   <img src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EM5w000005vNtu.png" style={{width: 20, height: 20, display: 'inline', verticalAlign: 'start', margin: '0'}}/> **Wrench** > **Edit** for the workspace.
4. Select
   **Manage Kernel Snapshots**.

   <Frame><img alt="Screenshot 2024-12-10 at 12.46.07 PM.png" src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EMVq000004HcL7.jpg"/></Frame>
   The **Manage Kernel Snapshots** modal displays.
5. In the modal, check the box labeled
   **Restore to base kernel environment**.

   <Frame><img alt="Screenshot 2024-12-10 at 12.46.19 PM.png" src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EMVq000004HXi3.jpg"/></Frame>
6. Select
   **Restore** Kernel.
7. Uninstall any libraries installed locally using pip or cran.

## Input Dataset Not Found

If a notebook returns an error such as "Input dataset with id ... not found" when reading data, the DataSet you are referencing is not attached to the workspace as an input, or you do not have access to it.

Follow these steps to resolve the issue:

1. Confirm the DataSet is added to the workspace. From the Jupyter Workspaces list, select
   <img src="/images/kb/ka0Vq0000005UQT-00N5w00000Ri7BU-0EM5w000005vNtu.png" style={{width: 20, height: 20, display: 'inline', verticalAlign: 'start', margin: '0'}}/> **Wrench** > **Edit** for the workspace, then verify the DataSet appears under **Input DataSets**. If it is missing, select **Add Input DataSet**, choose the DataSet, and select **Save Workspace**. See [Reading Data](/s/article/36004740075#reading-data) for details.
2. Confirm you are reading the DataSet by the correct name or ID. The name or ID passed to `read_dataframe` must match an input DataSet on the workspace.
3. Confirm you have access to the DataSet in Domo. Workspace access does not grant DataSet access — you must have permission to the underlying DataSet. Input and Output DataSets are shared with workspace Co-Owners, but other shared users need their own access to the DataSet.

## Account Credential Access Errors

If `get_account_property_value` returns a 404 even though the account exists and is attached to the workspace, the account's connector most likely does not allow reading unencrypted credential values.

To resolve the issue, edit the account (in **Data** > **Accounts**) and, when creating or editing it, expand **show advanced options** and enable **Allow authorized users to access unencrypted credentials**. This option is hidden under advanced options and is off by default for many connectors. After enabling it, retry the call from your notebook.

## Scheduled Execution Failures

If a Jupyter DataFlow created from a Jupyter Workspace notebook fails to execute successfully, it may be due to one of the following reasons:

* Python/R language syntax or logic errors
* The notebook cells executed in an order resulting in an error
* The notebook file has been deleted
* Error accessing the third-party system

Follow these steps to resolve the execution failure:

1. Attempt to execute the notebook's cells in order from the Jupyter Workspace environment.
2. Review the execution details in the recent\_executions directory in your workspace.

   The following files are available:

   * output.jpynb 
   * output.html 
   * output.pdf 
   * stdout 
   * stderr

### "Edit in Jupyter" Opens a Blank or Wrong Notebook

When you schedule a notebook, Domo creates a Jupyter DataFlow that is linked to the source `.ipynb` file in your workspace. Selecting **Edit in Jupyter** from the DataFlow's Details view opens that source notebook.

If the source notebook has been renamed, moved, or deleted, the DataFlow can no longer locate the original file, so **Edit in Jupyter** may open a blank notebook or a notebook that does not match the code that ran.

Follow these steps to locate and repair the code behind a failing scheduled job:

1. Open the workspace and check the `recent_executions` directory for the last run's `output.ipynb`, `stdout`, and `stderr` files to see the code and error output that actually executed.
2. If the source file was renamed or moved, restore it to the original name and path the DataFlow expects, or re-create the schedule from the current notebook so the DataFlow links to the correct source file. See [Schedule a Notebook](/s/article/36004740075#schedule-a-notebook).
