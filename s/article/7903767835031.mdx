## Intro

<Warning>
  **Important:**
  A Variable is a value that functions in a Beast Mode. You can create a Variable without using it in a Beast Mode, but you cannot use the Variable in a card or on a dashboard unless you use it in a Beast Mode.

</Warning>

<Frame><img alt="Screen_Shot_2022-09-28_at_3.28.54_PM.png" src="/images/kb/ka0Vq0000008ZWr-00N5w00000Ri7BU-0EM5w000005vXl5.png"/></Frame>
Variables allow data analysts to interact with the data on cards and create dashboards that are fully functional apps, as well as effectively reducing content clutter. Variables provide low-code solutions for many use cases, including the following:

* What-if analysis
* KPI exploration
* Time comparison
* Score cards for product performance
* Guided analysis

This article introduces Variables, default values, and controls; gives instructions on how to complete various tasks with Variables; and discusses Variables and governance.

## Variables and the Beast Mode Editor

Because Variables must be added to a Beast Mode to function, you can create them in the enhanced Beast Mode Editor.

You can access the Beast Mode Editor from inside **Analyzer** by selecting the **Beast Mode** tile in the **Visualize Tab**, or by selecting **Add Calculated Field** from the left side rail in Analyzer.

<Frame><img alt="accessing_BME.png" src="/images/kb/ka0Vq0000008ZWr-00N5w00000Ri7BU-0EM5w000005vXlH.png"/></Frame>
Inside the Beast Mode Editor, you can view all Variables in your Domo instance by selecting the **Variables** tab.

<Frame><img alt="variables_tab.png" src="/images/kb/ka0Vq0000008ZWr-00N5w00000Ri7BU-0EM5w000005vXks.png"/></Frame>
Variables are organized by data type: Numbers, Strings, and Dates. Any user with the Edit Cards grant can use any Variable in an instance, but only those with the Edit Variables grant can create, edit, or delete Variables.

To learn more about this grant, see Variables and Governance later in this article.

<Frame><img alt="Screen_Shot_2022-10-07_at_12.19.50_AM.png" src="/images/kb/ka0Vq0000008ZWr-00N5w00000Ri7BU-0EM5w000005vXlF.png"/></Frame>
When you create a Variable, you must give it a name, select a data type, and set a default value. This basic Variable can be added to a Beast Mode by any user in the instance with the right permissions. You can think of this basic Variable as a global Variable.

If you create a Variable and later modify the default value or any of the other basic details, those changes are reflected everywhere that the Variable is being used, in any Beast Mode in your instance where it appears.

## Controls

As mentioned previously, you can configure and modify controls for your Variables. Controls allow you to update your Variable's value to find new insights, adjust selections, and update your cards dynamically on a dashboard or in card Details.

If you are familiar with Domo, controls function with the same hierarchy as Quick Filters. In **Analyzer**, controls display in the same panel as Quick Filters, and that panel is labeled **Controls**, as a general term for both Variable controls and Quick Filters.

<Frame><img alt="controls_in_analyzer.png" src="/images/kb/ka0Vq0000008ZWr-00N5w00000Ri7BU-0EM5w000005vXlA.png"/></Frame>
If you aren't familiar with Quick Filters, what this means is that changes to a control on a dashboard override any changes to a particular control in Analyzer. The changes are only visible in the user's current location in Domo. For example, if you modify a control on a dashboard when you open the card in Analyzer, the control will have the same value as was last saved for it in Analyzer.

### Default Control

The first type of control, a Default Control, is configured in the Beast Mode Editor. There are several kinds of Default Controls, such as dropdowns, pills, sliders, and textbox inputs. The kind of Default Control you can use with a Variable depends on the data type of the Variable.

You can configure a Default Control when you create a Variable or come back later to add it by editing your Variable.

If you change the default value for a Variable after creating the Default Control, the Default Control does not update automatically. To change the Default Control, you must change it in the Beast Mode Editor and save the change.

**Default Control and Other Users**

If you create a Variable without a Default Control and return to add one later, or if you initially configure the Variable with a Default Control and later update it, your changes do not override the different controls other users may have created or modified as they use your Variable in their cards and dashboards. This is not the same as for the default value—if you change the default value for a Variable, every occurrence of that Variable in your instance reflects the change in the cards and dashboards of both you and other users.

Another user can potentially adjust the Default Control for your Variable. If you then remove your Variable from a card or Beast Mode, when you try to add your Variable to another Beast Mode, the Variable's Default Control reflects the adjustments from the other user.  You would need to go back to the Beast Mode Editor and adjust the Default Control to the original value if you want the your Variable's Default Control to have the original value. To prevent changes like this to Variables you create, see Locking/Unlocking a Variable, below.

### Dashboard Variable Controls

After you add a Variable to a Beast Mode, add the Beast Mode to a card in Analyzer, optionally adjust the Card Variable Control, and save the card, you can add the card to a dashboard. Note that any changes made to the Card Variable Control in Analyzer do not transfer to the Variable when you use it on a dashboard. When a Variable control is added to a dashboard, the control is called a Dashboard Variable Control.

When you first add a Dashboard Variable Control to a dashboard, all cards on the dashboard that contain that Variable reflects the default value of the Variable at the basic or global level in **Variable Settings**. If you then modify the Dashboard Variable Control, all cards on the dashboard that use that Variable reflect the modification.

Just as for Card Variables Controls, modifications to a Dashboard Variable Control do not transfer. If you modify a Dashboard Variable Control, the modification is not reflected in Analyzer, card Details, or Story Presentation Mode.

## Variable Scope and Limitations

A Variable's definition is global to your instance, but its effect on any given card is scoped by where the Variable is used.

### Which Cards a Variable Affects

A Variable affects only the cards whose Beast Mode references it. Because a Variable must be used inside a Beast Mode to function (see the [Intro](#intro)), adding a Dashboard Variable Control does not change every card on a dashboard—only the cards that use that Variable in a Beast Mode respond when you modify the control. Cards that do not reference the Variable are unaffected.

The Variable's *definition* (name, data type, and default value) is shared everywhere, so editing the default value propagates to every Beast Mode in your instance that uses the Variable, across DataSets and cards. The *control* does not propagate the same way; see [Default Control and Other Users](#default-control) and the [Controls](#controls) section for the control-vs-definition model.

### Reference a Variable's Value in Labels and Text

A Variable's selected value drives the results of any Beast Mode that references it, and those results flow into the card wherever the calculated field is used (as values, calculated columns, or a summary number). Displaying the Variable's selected value itself as dynamic label text—in the card title, axis labels, legends, or column headers—is a separate capability from the Variable control and is not something the control provides on its own.

### Current Limitations of Variable Values and Controls

A control's values are entered manually when you create or edit the Variable—they are static and are not populated from a DataSet field. A few consequences are worth planning around:

* **Values can't be reordered in place.** Choices display in the order you add them; to change the order, remove the values and re-add them in the order you want.
* **Options aren't dataset-driven.** A control's choices can't be bound to a DataSet column, so when the underlying list changes you re-enter the values by hand. Some teams generate the distinct list of values externally (for example, with a Workflow or a CodeEngine function) and paste those values into the control, but the control itself still holds a static, manually entered list.
* **Date defaults are static.** A Date Variable's default is a fixed date set when the Variable is created; there is no dynamic "today"/current-date default. If you need a card to open on the latest data, drive the date range with a Quick Filter default such as **Month to Date** instead of a Variable, or flag the most-recent date in a Magic ETL dataflow (compare each row's date to `MAX(date)`) and filter on that flag.
* **No dedicated Variable Manager.** There is no separate Variable Manager UI, and control choices can't be sorted or individually formatted. To see and manage every Variable in the instance, use the **Variables** tab in the [Beast Mode Editor](#variables-and-the-beast-mode-editor) and the DomoStats **Variables** reports (see [DomoStats Reports](#domostats-reports)).

## Build a Variable-Driven Toggle

You can use a Variable to let viewers switch what a card shows—for example, toggling a card between month-to-date and year-to-date, or between two metrics—without building separate cards.

1. Create a String Variable (for example, `Metric View`) with a dropdown [Default Control](#default-control) that offers the choices you want to toggle between, such as `MTD` and `YTD`.
2. In a Beast Mode on the card, write a `CASE` statement that returns the appropriate measure based on the Variable's value:

   ```
   CASE `Metric View`
     WHEN 'MTD' THEN <your month-to-date measure>
     WHEN 'YTD' THEN <your year-to-date measure>
   END
   ```
3. Add the calculated field to the card, then add the control to the dashboard as a [Dashboard Variable Control](#dashboard-variable-controls).

To toggle which rows appear rather than which measure displays, write a Beast Mode that returns `'Yes'` or `'No'` based on the Variable, then apply that Beast Mode as a card filter set to `Yes`:

```
CASE WHEN <row condition referencing the Variable> THEN 'Yes' ELSE 'No' END
```

<Note>
  **Note:** A Variable cannot change a column's data type or number format. To switch formatting (currency, percent, or plain number) based on a selection, build a formatted-label Beast Mode that returns text—for example, multiply a percent by 100, round it, and `CONCAT` the unit symbol—rather than expecting the Variable to reformat the value. Keep a separate raw-value Beast Mode when you also need the numeric value for sorting or charting.

</Note>

The same toggle pattern can switch a series or an axis: point the Beast Mode you drag onto the Y-axis (or the series/color field) at whichever measure the Variable's value selects.

### Build an "All" Option

Domo does not yet offer a native "select all" choice in a slicer or Variable control, so build the combined option with a Variable plus a Beast Mode include/exclude filter.

1. Create a String Variable (for example, `Region Filter`) with a [Default Control](#default-control)—pills, radio buttons, or a dropdown—whose choices are your individual values **plus** an `All` choice.
2. Write a Beast Mode that returns `Include` when either `All` is selected or the row matches the selected value, and `Exclude` otherwise:

   ```
   CASE
     WHEN `Region Filter` = 'All' THEN 'Include'
     WHEN `Region Filter` = `Region` THEN 'Include'
     ELSE 'Exclude'
   END
   ```
3. Apply that Beast Mode as a **card filter** set to `Include`, and save it on each card that needs the option rather than as a shared slicer—that keeps the include/exclude logic with the card so it behaves consistently on a dashboard.

If a single column holds several delimited values (for example, `"US, CA, MX"`) and you want a control to list each value on its own, that is a data-shaping task, not a Variable task: split the column into rows in an ETL first (see [Split Multi-Value Fields into Rows](/s/article/Split-Multi-Value-Fields-into-Rows)). A native "Select All" control in filters and slicers is an open feature request.

For related time-comparison patterns, see [Sample Beast Mode Calculations: Period-over-Period Transforms](/s/article/360043430133).

## Variables and Governance

Who can create, edit, and use Variables?

Variables are part of the Domo base product, so after a Variable is created, anyone can use it.

Variables have their own grant—the Edit Variables grant—that is automatically enabled for all users with the Edit Card grant enabled (Editor role and above), beginning with the October 2022 release. The Edit Variables grant allows a user to create, edit, and delete Variables in that instance. Admins can disable this grant for any user. If an admin turns off the Edit Variables grant for a user, that user can still use Variables, they just can't create, edit, or delete them.
