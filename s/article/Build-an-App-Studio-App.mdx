## Intro

App Studio is a low-code app builder that allows anyone to create, distribute, and consume apps.

App Studio levels up the interactive Domo dashboard experience you're used to. The foundation is an intuitive and highly customizable drag-and-drop interface that allows you to create app layouts. The rich themes library lets you personalize everything from cards, tables, and fonts to color palettes and icons to align your app with your brand. Customizable themes make app design approachable for non-designers.

The seamless navigational interface lets you collect all your content together in one place. Use components like tabs, buttons, card pop-ups, and natively integrated forms to create custom experiences and take actions directly from the app—actions like sending an email, triggering a DataSet, or moving to another page in the app. You can even bring in Domo Bricks to have more control over customization. App Studio also has [Forms](/s/article/000005171) natively integrated, as well as as well as customizable [app components](/s/article/000005864).

<Note>
  **App Studio integrations**

  - App Studio integrates with Domo Everywhere so you can publish App Studio apps. See
    [Publish Content to a Subscriber Instance](/s/article/360045120554) to learn more.
  - App Studio also integrates with Sandbox. Learn more about
    [Domo Sandbox](/s/article/4403367344023) in the Knowledge Base.
  - The Forecasting Universal Model from Domo. AI allows you to [forecast from a card](/s/article/000005567#forecast-in-a-domo-app) in your App Studio app.
</Note>

## App Configuration

In **App configuration**, there are two tabs: **Info & Permissions** and **Filter Options**. The **Filter Options** tab is covered in [Add Interactivity: Popups, Filters, and Actions to an App Studio App](/s/article/Add-Interactivity-to-an-App-Studio-App#filter-options).

In the **Info & Permissions** tab, you can change the name and description for your app and choose an icon to represent it in the Apps Home. You can also add other people/groups as app owners and choose whether to identify them of the change. Locking the app prevents anyone besides owners and admins in your Domo instance from editing it.

To save your changes to any of these settings, select **Save** in the editor's [main navigation](#app-editor).

To delete an app or clean up the cards it leaves behind, see [Manage an App Studio App](/s/article/Manage-an-App-Studio-App).


### Use Advanced Saving Options in App Studio

The saving workflow in App Studio supports continuous development across multiple pages without structural interruptions. By unifying the save experience, the system allows bulk updates to layouts and configurations without requiring a save action each time the view changes.

#### Save Your Progress

The save interface is located in the top-right corner of the editor and provides two primary methods for managing your work:

- **Save:** Select this option to commit all recent changes to the Domo environment while remaining in the editor. This lets you persist your progress and continue making further adjustments immediately.
- **Save and Close:** Select this option to commit your changes and exit edit mode simultaneously. This transitions the interface back to **View Mode**, where you can interact with the application as an end user.

1. Use the **Left Arrow (Undo)** and **Right Arrow (Redo)** icons in the top header to undo or redo any changes made to the page.

### Known Editor Behaviors and Troubleshooting

Keep the following editor behaviors in mind while building an app.

- **Save and Close returns to view mode.** Selecting **Save and Close** commits your changes and exits the editor to View Mode. To keep working after you save, select **Save** instead. See [Use Advanced Saving Options](#use-advanced-saving-options-in-app-studio).

- **App background vs. page background.** An app has an overall background set in the [App theme](/s/article/000005543), and each page has its own background set under [Format Page](#format-page). A page background is drawn on top of the app background, so setting a page background color can cover the app background on that page. To let the app background show through, clear or remove the page background.

Synthesized from community forum reports; needs confirmation. */}

- **Conditional-formatting Apply-To may show blank column names.** When you configure conditional formatting on a card inside the app editor, the **Apply to** column list can display blank. As a workaround, edit the card on a traditional dashboard in Analyzer, configure the conditional formatting there, then return to the app.

{/* [pm-input] Khushboo — confirm the conditional-formatting "Apply to" blank-column-list behavior when editing a card inside App Studio, and that the supported workaround is to edit the card on a traditional dashboard in Analyzer. Synthesized from community forum reports; needs confirmation. */}

- **Multiple people editing the same app.** Before several people edit the same app at the same time, coordinate who is working on which pages. Concurrent edits to the same content can overwrite one another when saved.

{/* [pm-input] Khushboo — confirm the current concurrent-editing behavior in App Studio: whether multiple users can safely edit the same app (or different pages of the same app) at once, and what happens to conflicting changes when each person saves. Synthesized from community forum reports; needs confirmation. */}

- **Recreate a page if the layout becomes corrupted.** If a page's layout stops behaving correctly and cannot be repaired by editing the affected elements, the reliable fix is to rebuild the page—add a new [app page](#add-an-app-page) and re-add the content—rather than continue troubleshooting the damaged layout.

{/* [pm-input] Khushboo — confirm that rebuilding a page is the recommended recovery step for a corrupted App Studio page layout, and whether a support-assisted repair path exists. Synthesized from community forum reports; needs confirmation. */}

- **Roll back to an earlier version with Sandbox.** App Studio does not keep a built-in version history, but you can use [Domo Sandbox](/s/article/4403367344023) as a version-control and rollback path for apps—commit an app to a Sandbox repository, then restore an earlier version if a change needs to be reverted. Undo and redo within a single editing session are available in the editor header (see [Undo/Redo Changes](#undoredo-changes)).

- **Stuck in full-screen or wide mode.** If the editor or app viewer becomes stuck in full-screen or an oversized width, clear your browser cache and close any other open sessions of the same app, then reopen it.

#### Navigation Behavior and Limitations

Keep the following current behaviors in mind when you configure app navigation.

- **Nav-bar buttons should use icons.** The Domo navigation buttons (**Home**, **Controls**, **Share**, and **Details**) are designed to display as icons. A button that has a text label but no icon can appear invisible until a viewer hovers over it, so assign an icon to every nav button you keep visible.

- **The Home button can be hidden but not relabeled.** You can show or hide the **Home** button under **Navigation**, but its label and destination ([Apps Home](#apps-home)) cannot be changed. As noted above, hiding **Home** means viewers must use the browser back button to return to previous pages.

- **Only built-in icons are available.** Navigation buttons and page icons can be set only from Domo's built-in icon set; uploading a custom icon image is not supported.

- **Suppress app and system navigation in embeds.** Use the **Show Navigation** and **Show System Navigation** options under [Pages and navigation](#use-the-left-navigation-toolbar) to control the app's own navigation and the surrounding Domo system navigation. See [Embed an App](/s/article/Distribute-an-App-Studio-App#embed-an-app) for embedded-app behavior.

#### Tabs Tips and Limitations

Keep the following in mind when you build with tabs.

- **Nest components inside the tab, not just over it.** When you add cards and other elements to a tab, drag each one onto the blue line that appears inside the tab so it is technically nested in the tab and not merely positioned on top of it. Elements that only look like they are inside a tab can cause the app to fail to save.

- **Tabs share a height.** A Tabs element sizes to the tallest tab, so a tall tab adds empty space to shorter tabs. To balance the height, add a [Spacer](#add-a-spacer) to the shorter tabs. This spacer adjustment applies to the desktop layout and does not carry over to the mobile view. (As noted above, the Tabs layout also will not resize smaller if the last item in any tab is at its minimum height.)

- **You cannot copy a tab's layout to another tab.** Each tab's layout is built independently; there is no option to copy one tab's arrangement of elements into another tab.

- **You cannot link directly to a tab.** A [Page Drill](#page-drill) or button action can open an app page, but it cannot open a specific tab within a page. Use separate pages when you need a direct link to specific content.

#### Filter Exceptions Tab

In the **Filter Exceptions** tab, define how the card is affected by filters, global date, and segments. Select one of the available options:

- **Allow filtering —** Allows all Filters to affect this card, including interaction Filters.
- **Allow global date —** Allows the global date to filter this card.
- **Allow segments —** Allows all segments to be displayed on this card.

Selecting <i className="icon-chart-bar-box sm" aria-hidden="true" /> **Add Content** expands the following options, described below:

- **Add existing card —** Allows you to choose from existing cards in your Domo instance to add to your layout.

- **Assign card creation —** Allows you to assign card creation to a user in your instance. You must include the assignee's name and the name of the card (25 characters or fewer). You can also include an optional message to the assignee. After entering the details, select **Assign** to notify the assignee or **Cancel** to discard your assignment.
