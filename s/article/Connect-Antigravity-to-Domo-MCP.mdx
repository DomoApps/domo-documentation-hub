## Required Grants

To connect Antigravity to Domo's MCP Server, the following grants must be enabled for your role:

- **Use AI Services —** Access to features and Apps built using the AI Services Layer.
- **Use AI Chat —** Access to the Domo AI Assistant.
- **Use MCP —** Access to connect external AI tools to Domo's MCP Server.

Learn more about [grants](/s/article/360043438973).

## Prerequisites

- [Antigravity](https://antigravity.google/) CLI or IDE installed.

- The **Domo MCP** server URL. Visit the [AI Library](/s/article/AI-Library) and retrieve the MCP server URL from the **Domo MCP** toolkit. Either URL works:

  ```
  https://<instance>.domo.com/mcp

  https://<instance>.domo.com/mcp/toolkits/domo
  ```

  <Note>**Note:** Replace `<instance>` with your actual Domo instance subdomain (for example, `mycompany` for `mycompany.domo.com`).</Note>

## Connect Antigravity

Connecting with OAuth is recommended. Use an access token only if you can't connect with OAuth.

Antigravity CLI and the Antigravity IDE read MCP servers from the same configuration file, `~/.gemini/config/mcp_config.json`. After you add the Domo MCP Server, it's available in both.

<Tabs>
  <Tab title="OAuth">
    <Steps>
      <Step title="Open the MCP Configuration">
        Open `~/.gemini/config/mcp_config.json` in a text editor, creating it if it doesn't exist.

        To open the file from the Antigravity IDE instead, select **…** at the top of the agent side panel, select **MCP Servers** > **Manage MCP Servers**, then select **View raw config**.
      </Step>

      <Step title="Add the Domo MCP Server">
        Add the following `domo-mcp` entry to the `mcpServers` object in the configuration file, replacing `<instance>` with your Domo instance subdomain, and save the file:

        ```json
        {
          "mcpServers": {
            "domo-mcp": {
              "serverUrl": "https://<instance>.domo.com/mcp"
            }
          }
        }
        ```

        <Note>**Note:** Antigravity uses `serverUrl` rather than `url` for remote servers. Leave out the `headers` object. Without it, Antigravity completes the OAuth flow for you.</Note>
      </Step>

      <Step title="Sign In to Domo">
        Start Antigravity CLI, then type `/mcp` and press **Enter** to open the MCP Manager. Reload the configuration if `domo-mcp` isn't listed yet, then follow the prompt to authenticate `domo-mcp`.

        A browser window opens to your Domo instance. Sign in with your Domo credentials, then select **Allow** on the consent screen that asks to allow Antigravity access to Domo.

        <Frame><img alt="Domo OAuth consent screen asking to allow an AI tool, in this example Claude, to invoke AI agents and view AI Chat history, with Cancel and Allow buttons" src="/images/kb/claude-mcp-oauth-consent.png"/></Frame>
      </Step>

      <Step title="Verify the Connection">
        In the MCP Manager, confirm that `domo-mcp` shows as connected. If it doesn't connect, check its connection logs in the MCP Manager.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>

  <Tab title="Access Token">
    <Steps>
      <Step title="Generate an Access Token">
        In Domo, go to **Admin** > **Authentication** > **Access Tokens** and generate a token, or request one from your MajorDomo. See [Manage Access Tokens](/s/article/360042934494#manage-access-tokens) for instructions.

        <Frame>![Access Tokens management page in Domo Admin settings](/images/kb/DOMO-MCP-Server-Screenshot-2.png)</Frame>
      </Step>

      <Step title="Open the MCP Configuration">
        Open `~/.gemini/config/mcp_config.json` in a text editor, creating it if it doesn't exist.

        To open the file from the Antigravity IDE instead, select **…** at the top of the agent side panel, select **MCP Servers** > **Manage MCP Servers**, then select **View raw config**.

        <Warning>**Important:** Don't add an access token to a workspace configuration file, `.agents/mcp_config.json`. That file lives in your project and is often shared through source control.</Warning>
      </Step>

      <Step title="Add the Domo MCP Server">
        Add the following `domo-mcp` entry to the `mcpServers` object in the configuration file, replacing `<instance>` with your Domo instance subdomain and `<DOMO_ACCESS_TOKEN>` with your access token, and save the file:

        ```json
        {
          "mcpServers": {
            "domo-mcp": {
              "serverUrl": "https://<instance>.domo.com/mcp",
              "headers": {
                "X-DOMO-DEVELOPER-TOKEN": "<DOMO_ACCESS_TOKEN>"
              }
            }
          }
        }
        ```
      </Step>

      <Step title="Verify the Connection">
        Start Antigravity CLI, then type `/mcp` and press **Enter** to open the MCP Manager. Reload the configuration if `domo-mcp` isn't listed yet, and confirm that it shows as connected.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Note>**Note:** MCP tool calls don't incur AI operation charges. However, if the tool that gets called uses any of the Domo-provided models, input and output token charges can apply.</Note>

## FAQ

<AccordionGroup>
<Accordion title="Can I connect multiple Domo instances?">
Yes. Repeat the steps in this article for each instance, using a unique server name and the corresponding domain in the MCP server URL for each.
</Accordion>

<Accordion title="What data does Antigravity have access to once connected?">
Antigravity can access the data and tools exposed by the Domo MCP toolkit, which includes querying DataSets and interacting with Domo features available through the MCP API. Access is scoped to what your Domo user account is permitted to see.
</Accordion>

<Accordion title="Can I add the server to a single project instead?">
Yes. Add the same `domo-mcp` entry to a `.agents/mcp_config.json` file in the project. Use OAuth for a project file so no access token is stored in it.
</Accordion>
</AccordionGroup>
