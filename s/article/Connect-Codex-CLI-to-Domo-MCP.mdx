## Required Grants

To connect Codex CLI to Domo's MCP Server, the following grants must be enabled for your role:

- **Use AI Services —** Access to features and Apps built using the AI Services Layer.
- **Use AI Chat —** Access to the Domo AI Assistant.
- **Use MCP —** Access to connect external AI tools to Domo's MCP Server.

Learn more about [grants](/s/article/360043438973).

## Prerequisites

- [Codex CLI](https://developers.openai.com/codex/cli) installed.

- The **Domo MCP** server URL. Visit the [AI Library](/s/article/AI-Library) and retrieve the MCP server URL from the **Domo MCP** toolkit. Either URL works:

  ```
  https://<instance>.domo.com/mcp

  https://<instance>.domo.com/mcp/toolkits/domo
  ```

  <Note>**Note:** Replace `<instance>` with your actual Domo instance subdomain (for example, `mycompany` for `mycompany.domo.com`).</Note>

<Note>**Note:** Older Codex CLI releases supported remote MCP servers only as an experimental feature. If `codex mcp add --url` isn't recognized, or the server is added but never connects, update Codex CLI.</Note>

## Connect Codex CLI

Connecting with OAuth is recommended. Use an access token only if you can't connect with OAuth.

Codex CLI saves MCP servers to `~/.codex/config.toml`, so the server is available in all of your projects. The Codex desktop app and IDE extension share this configuration.

<Tabs>
  <Tab title="OAuth">
    <Steps>
      <Step title="Add the Domo MCP Server">
        In a terminal, run the following command, replacing `<instance>` with your Domo instance subdomain:

        ```bash
        codex mcp add domo-mcp --url https://<instance>.domo.com/mcp
        ```
      </Step>

      <Step title="Sign In to Domo">
        Run the following command:

        ```bash
        codex mcp login domo-mcp
        ```

        A browser window opens to your Domo instance. Sign in with your Domo credentials, then select **Allow** on the consent screen that asks to allow Codex access to Domo.

        <Frame><img alt="Domo OAuth consent screen asking to allow an AI tool, in this example Claude, to invoke AI agents and view AI Chat history, with Cancel and Allow buttons" src="/images/kb/claude-mcp-oauth-consent.png"/></Frame>

        <Tip>**Tip:** On a computer without a local browser, such as a remote server, run `codex mcp login domo-mcp --no-browser`. Open the sign-in link on another device, then paste the full redirect URL back into the terminal.</Tip>
      </Step>

      <Step title="Verify the Connection">
        Run `codex mcp list` and confirm that `domo-mcp` is listed. You can also start Codex and run `/mcp` to see the active servers and their tools.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>

  <Tab title="Access Token">
    <Steps>
      <Step title="Generate an Access Token">
        In Domo, go to **Admin** > **Authentication** > **Access Tokens** and generate a token, or request one from your MajorDomo. See [Manage Access Tokens](/s/article/360042934494#manage-access-tokens) for instructions.

        <Frame>![Access Tokens management page in Domo Admin settings](/images/kb/DOMO-MCP-Server-Screenshot-2.png)</Frame>
      </Step>

      <Step title="Store the Access Token in an Environment Variable">
        Codex CLI reads the access token from an environment variable rather than taking it inline. In a terminal, run the following command, replacing `<DOMO_ACCESS_TOKEN>` with your access token:

        ```bash
        export DOMO_ACCESS_TOKEN=<DOMO_ACCESS_TOKEN>
        ```

        To keep the variable set in new terminal sessions, add the same line to your shell profile.
      </Step>

      <Step title="Add the Domo MCP Server">
        Open `~/.codex/config.toml` in a text editor, creating it if it doesn't exist. Add the following, replacing `<instance>` with your Domo instance subdomain, and save the file:

        ```toml
        [mcp_servers.domo-mcp]
        url = "https://<instance>.domo.com/mcp"
        env_http_headers = { "X-DOMO-DEVELOPER-TOKEN" = "DOMO_ACCESS_TOKEN" }
        ```

        The `env_http_headers` setting tells Codex to send the value of the `DOMO_ACCESS_TOKEN` environment variable in the `X-DOMO-DEVELOPER-TOKEN` header, so your access token stays out of the file.
      </Step>

      <Step title="Verify the Connection">
        Run `codex mcp list` and confirm that `domo-mcp` is listed. You can also start Codex and run `/mcp` to see the active servers and their tools.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Note>**Note:** MCP tool calls don't incur AI operation charges. However, if the tool that gets called uses any of the Domo-provided models, input and output token charges can apply.</Note>

## FAQ

<AccordionGroup>
<Accordion title="Can I connect multiple Domo instances?">
Yes. Repeat the steps in this article for each instance, using a unique server name and the corresponding domain in the MCP server URL for each.
</Accordion>

<Accordion title="What data does Codex have access to once connected?">
Codex can access the data and tools exposed by the Domo MCP toolkit, which includes querying DataSets and interacting with Domo features available through the MCP API. Access is scoped to what your Domo user account is permitted to see.
</Accordion>

<Accordion title="Can I add the server to a single project instead?">
Yes. Add the same `[mcp_servers.domo-mcp]` entry to a `.codex/config.toml` file in the project. Codex applies project configuration only to projects you've marked as trusted. Don't paste an access token into a project file that's shared through source control.
</Accordion>
</AccordionGroup>
