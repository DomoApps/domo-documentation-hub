## Required Grants

To connect Cursor to Domo's MCP Server, the following grants must be enabled for your role:

- **Use AI Services —** Access to features and Apps built using the AI Services Layer.
- **Use AI Chat —** Access to the Domo AI Assistant.
- **Use MCP —** Access to connect external AI tools to Domo's MCP Server.

Learn more about [grants](/s/article/360043438973).

## Prerequisites

- [Cursor](https://cursor.com/downloads) installed.

- The **Domo MCP** server URL. Visit the [AI Library](/s/article/AI-Library) and retrieve the MCP server URL from the **Domo MCP** toolkit. Either URL works:

  ```
  https://<instance>.domo.com/mcp

  https://<instance>.domo.com/mcp/toolkits/domo
  ```

  <Note>**Note:** Replace `<instance>` with your actual Domo instance subdomain (for example, `mycompany` for `mycompany.domo.com`).</Note>

## Connect Cursor

Connecting with OAuth is recommended. Use an access token only if you can't connect with OAuth.

<Tabs>
  <Tab title="OAuth">
    <Steps>
      <Step title="Open the MCP Configuration">
        Open the configuration file you want to use, creating it if it doesn't exist:

        - **`~/.cursor/mcp.json` (recommended) —** Makes the server available in all of your projects.
        - **`.cursor/mcp.json` —** Makes the server available only in the current project. Create this file in the project root.
      </Step>

      <Step title="Add the Domo MCP Server">
        Add the following `domo-mcp` entry to the `mcpServers` object in the configuration file, replacing `<instance>` with your Domo instance subdomain, and save the file:

        ```json
        {
          "mcpServers": {
            "domo-mcp": {
              "url": "https://<instance>.domo.com/mcp"
            }
          }
        }
        ```

        Leave out the `headers` object. Without it, Cursor completes the OAuth flow for you.
      </Step>

      <Step title="Sign In to Domo">
        Open **Customize** in the Cursor sidebar and confirm that `domo-mcp` is listed and enabled. When Cursor prompts you to sign in to `domo-mcp`, follow the prompt.

        A browser window opens to your Domo instance. Sign in with your Domo credentials, then select **Allow** on the consent screen that asks to allow Cursor access to Domo.

        <Frame><img alt="Domo OAuth consent screen asking to allow an AI tool, in this example Claude, to invoke AI agents and view AI Chat history, with Cancel and Allow buttons" src="/images/kb/claude-mcp-oauth-consent.png"/></Frame>
      </Step>

      <Step title="Verify the Connection">
        Return to Cursor and open **Customize**. `domo-mcp` shows as connected, with its tools listed.

        To test the connection, open the Agent chat and try a prompt such as "How many DataSets do I have access to?" Cursor asks for approval before it runs each Domo tool.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Access Token">
    <Steps>
      <Step title="Generate an Access Token">
        In Domo, go to **Admin** > **Authentication** > **Access Tokens** and generate a token, or request one from your MajorDomo. See [Manage Access Tokens](/s/article/360042934494#manage-access-tokens) for instructions.

        <Frame>![Access Tokens management page in Domo Admin settings](/images/kb/DOMO-MCP-Server-Screenshot-2.png)</Frame>
      </Step>

      <Step title="Add the Domo MCP Server">
        Open `~/.cursor/mcp.json`, creating it if it doesn't exist. Add the following `domo-mcp` entry to the `mcpServers` object, replacing `<instance>` with your Domo instance subdomain and `<DOMO_ACCESS_TOKEN>` with your access token, and save the file:

        ```json
        {
          "mcpServers": {
            "domo-mcp": {
              "url": "https://<instance>.domo.com/mcp",
              "headers": {
                "X-DOMO-DEVELOPER-TOKEN": "<DOMO_ACCESS_TOKEN>"
              }
            }
          }
        }
        ```

        <Warning>**Important:** Don't add an access token to a project's `.cursor/mcp.json` file. That file is usually shared through source control. To share the server with your team through that file instead, have each person store their own token in a `DOMO_ACCESS_TOKEN` environment variable and set the header value to `${env:DOMO_ACCESS_TOKEN}`.</Warning>
      </Step>

      <Step title="Verify the Connection">
        Open **Customize** in the Cursor sidebar. `domo-mcp` shows as connected, with its tools listed.

        To test the connection, open the Agent chat and try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Note>**Note:** MCP tool calls don't incur AI operation charges. However, if the tool that gets called uses any of the Domo-provided models, input and output token charges can apply.</Note>

## FAQ

<AccordionGroup>
<Accordion title="Can I connect multiple Domo instances?">
Yes. Repeat the steps in this article for each instance, using a unique server name and the corresponding domain in the MCP server URL for each.
</Accordion>

<Accordion title="What data does Cursor have access to once connected?">
Cursor can access the data and tools exposed by the Domo MCP toolkit, which includes querying DataSets and interacting with Domo features available through the MCP API. Access is scoped to what your Domo user account is permitted to see.
</Accordion>

<Accordion title="The server doesn't connect. How do I troubleshoot it?">
Open the Output panel with **Cmd+Shift+U** (Mac) or **Ctrl+Shift+U** (Windows/Linux) and select **MCP Logs** to see connection and tool-call errors.
</Accordion>
</AccordionGroup>
