## Required Grants

To connect GitHub Copilot CLI to Domo's MCP Server, the following grants must be enabled for your role:

- **Use AI Services —** Access to features and Apps built using the AI Services Layer.
- **Use AI Chat —** Access to the Domo AI Assistant.
- **Use MCP —** Access to connect external AI tools to Domo's MCP Server.

Learn more about [grants](/s/article/360043438973).

## Prerequisites

- [GitHub Copilot CLI](https://docs.github.com/en/copilot/concepts/agents/about-copilot-cli) installed, and signed in with a GitHub account that has Copilot access.

- The **Domo MCP** server URL. Visit the [AI Library](/s/article/AI-Library) and retrieve the MCP server URL from the **Domo MCP** toolkit. Either URL works:

  ```
  https://<instance>.domo.com/mcp

  https://<instance>.domo.com/mcp/toolkits/domo
  ```

  <Note>**Note:** Replace `<instance>` with your actual Domo instance subdomain (for example, `mycompany` for `mycompany.domo.com`).</Note>

## Connect GitHub Copilot CLI

Connecting with OAuth is recommended. Use an access token only if you can't connect with OAuth.

Copilot CLI saves MCP servers to `~/.copilot/mcp-config.json`, so the server is available in all of your projects.

<Tabs>
  <Tab title="OAuth">
    <Steps>
      <Step title="Add the Domo MCP Server">
        In a terminal, run the following command, replacing `<instance>` with your Domo instance subdomain:

        ```bash
        copilot mcp add --transport http domo-mcp https://<instance>.domo.com/mcp
        ```

        To add the server from inside Copilot CLI instead, start `copilot`, run `/mcp add`, and fill out the form. Enter `domo-mcp` for **Server Name**, select **HTTP** for **Server Type**, paste the **Domo MCP** URL into **URL**, and leave **HTTP Headers** empty. Press **Ctrl+S** to save.
      </Step>

      <Step title="Sign In to Domo">
        Start `copilot`. When Copilot CLI connects to `domo-mcp`, a browser window opens to your Domo instance. Sign in with your Domo credentials, then select **Allow** on the consent screen that asks to allow Copilot access to Domo.

        <Frame><img alt="Domo OAuth consent screen asking to allow an AI tool, in this example Claude, to invoke AI agents and view AI Chat history, with Cancel and Allow buttons" src="/images/kb/claude-mcp-oauth-consent.png"/></Frame>

        If the browser doesn't open, or `domo-mcp` later shows a `needs-auth` status, run `/mcp auth domo-mcp` to start the sign-in again.
      </Step>

      <Step title="Verify the Connection">
        In Copilot CLI, run `/mcp show domo-mcp` and confirm that the server is connected and its tools are listed.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>

  <Tab title="Access Token">
    <Steps>
      <Step title="Generate an Access Token">
        In Domo, go to **Admin** > **Authentication** > **Access Tokens** and generate a token, or request one from your MajorDomo. See [Manage Access Tokens](/s/article/360042934494#manage-access-tokens) for instructions.

        <Frame>![Access Tokens management page in Domo Admin settings](/images/kb/DOMO-MCP-Server-Screenshot-2.png)</Frame>
      </Step>

      <Step title="Store the Access Token in an Environment Variable">
        Set an environment variable named `DOMO_ACCESS_TOKEN` to your access token. For example, on Mac or Linux, run the following command, replacing `<DOMO_ACCESS_TOKEN>` with your access token:

        ```bash
        export DOMO_ACCESS_TOKEN=<DOMO_ACCESS_TOKEN>
        ```

        To keep the variable set in new terminal sessions, add the same line to your shell profile.
      </Step>

      <Step title="Add the Domo MCP Server">
        Open `~/.copilot/mcp-config.json` in a text editor, creating it if it doesn't exist. Add the following `domo-mcp` entry to the `mcpServers` object, replacing `<instance>` with your Domo instance subdomain, and save the file:

        ```json
        {
          "mcpServers": {
            "domo-mcp": {
              "type": "http",
              "url": "https://<instance>.domo.com/mcp",
              "headers": {
                "X-DOMO-DEVELOPER-TOKEN": "${DOMO_ACCESS_TOKEN}"
              },
              "tools": ["*"]
            }
          }
        }
        ```

        Copilot CLI replaces `${DOMO_ACCESS_TOKEN}` with the value of the environment variable, so your access token stays out of the file. The `tools` field makes all of the server's tools available to the agent.

        <Warning>**Important:** If you add the server with `copilot mcp add --header` or the `/mcp add` form instead, Copilot CLI saves the header value exactly as you enter it. Pasting your access token there stores it in plain text in `~/.copilot/mcp-config.json`.</Warning>
      </Step>

      <Step title="Verify the Connection">
        Start `copilot`, run `/mcp show domo-mcp`, and confirm that the server is connected and its tools are listed.

        To test the connection, try a prompt such as "How many DataSets do I have access to?"
      </Step>
    </Steps>
  </Tab>
</Tabs>

<Note>**Note:** MCP tool calls don't incur AI operation charges. However, if the tool that gets called uses any of the Domo-provided models, input and output token charges can apply.</Note>

## FAQ

<AccordionGroup>
<Accordion title="Can I connect multiple Domo instances?">
Yes. Repeat the steps in this article for each instance, using a unique server name and the corresponding domain in the MCP server URL for each.
</Accordion>

<Accordion title="What data does Copilot have access to once connected?">
Copilot CLI can access the data and tools exposed by the Domo MCP toolkit, which includes querying DataSets and interacting with Domo features available through the MCP API. Access is scoped to what your Domo user account is permitted to see.
</Accordion>

<Accordion title="How do I connect GitHub Copilot in VS Code?">
Copilot Chat in VS Code uses its own MCP configuration. Follow [Connect VS Code to Domo MCP](/s/article/Connect-VS-Code-to-Domo-MCP) instead.
</Accordion>
</AccordionGroup>
