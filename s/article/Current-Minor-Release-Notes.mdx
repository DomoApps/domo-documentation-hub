## October 29, 2026 Release

### AI Labs

**Updates:**

- Adds support for OAuth authentication and the new default MCP resource identifier in AI Labs.
- Adds support for Personalized Data Permissions (PDP) policies in AI Labs file handling, allowing administrators to control access to unstructured data based on user and group permissions.
- Changes the "Live help" button to open AI Chat instead of its previous destination.
- Enables AI Services to be accessed through the Domo Apps proxy, improving integration capabilities for custom applications.
- Enables form respondents to upload file attachments to Document Collections when submitting App Studio forms.
- Ensures that deleting an OAuth 2.1 client for Domo Essentials MCP immediately revokes all active sessions and access tokens, rather than allowing them to remain valid until expiration.
- Ensures that MCP OAuth sessions are immediately revoked when a user is deleted, their password is reset, or their role changes. Previously, OAuth sessions could remain active after these account changes.
- Improves the readability of audit log entries for AI Chat agent executions, making it easier to track AI activity in your instance.
- Places two experimental unstructured data tiles in Magic ETL behind a feature flag, making them available only when the AI Labs experimental features are enabled.
- Sorts the model dropdown list in AI Playground alphabetically for easier navigation.

**Issues Resolved:**

- A missing icon in the Report Builder Toolkit card within the AI Library.
- AI Agent tasks in Workflows failed with a deserialization error when a DataSet was specified as a knowledge source. The issue was introduced by a library update and affected the ability to run AI Agent tasks that referenced DataSets.
- AI agents embedded in pages or apps did not load their configured data sources correctly.
- AI Chat was unavailable in certain Domo instances due to regional configuration settings.
- AI Library cards in Domo Everywhere embeds and publications displayed blank grey space instead of their icons.
- AI Skills could fail to run due to an incorrect feature flag check.
- Apps created by App Catalyst could not be promoted from Sandbox to production, failing with an error about missing data sources.
- Custom toolkits in AI Labs could not connect using OAuth authentication.
- DomoGPT Medium v2.2 and v3 models were not functioning in Magic ETL.
- Embedded AI agents could not read files from document collections, resulting in 404 errors.
- FileSets would skip processing a file if its updated content matched another existing file, even when the file itself had changed.
- Magic ETL DataFlows using the AI Text Generation tile could fail intermittently with an "unknown error occurred" message.
- Personalized Data Permissions (PDP) rules for FileSets were rejected if the rule value ended with a slash.
- Sandbox Repository Toolkit cards in the AI Library displayed blank grey space instead of their icons.
- Steps were no longer visible in AI Chat and Agent responses.

- Ensures that tool display names and descriptions are correctly included when retrieving Domo-provided and skill-derived toolkits through the AI Services API.

### AI Services

**Updates:**

- Adds production deployment capabilities for Domo Models in AI Services.
- Adds support for additional AI model types in AI Services, expanding the range of models available for use in Domo's AI features.
- Adds support for Amazon Bedrock's OpenAI models as a provider option in AI Services, available through a feature switch.

- The CardGetTool in AI Services did not return filters applied to Cards in Analyzer.
- The DomoStats AI Chat Sessions report could fail with a "Temporary Internal Connector Error" message.

### Advanced Pipeline

**Issues Resolved:**

- The CLI delete-rows command would fail on upsert DataSets if the key file contained invalid data, such as a header row with a UTF-8 byte-order mark. Previously, such rows caused the entire delete operation to fail and could prevent further deletes until the problematic data version was manually removed.

### Alerts

### App Components

### App Platform

**Updates:**

- Ensures that low-latency sync cannot be enabled on App Studio collections that lack a declared schema, matching the existing behavior for batch sync.
- Rebuilds Change Data Capture (CDC) DataSets to use updated default settings for data parsing.

**Issues Resolved:**

- Access to AppDB Admin from the Asset Library in the redesigned interface.
- App Studio AppDB sync wrote JSON arrays in an incorrect format, causing them to be unparseable when synced to DataSets.
- AppDB collections could show a different row count than their synced DataSets, with some rows failing to write to the DataSet.
- Bricks from the Appstore failed to install in App Studio, displaying an "Install Failed" error message.
- Creating a card from the Asset Library would skip the wiring screen for designs requiring workflow mappings, Code Engine mappings, or code-editor brick configuration, resulting in incomplete cards. The wiring screen now appears as expected when setup is needed.
- Enabling low-latency sync for AppDB did not create the expected DataSet.
- Low-latency DataSets created by non-owners were not visible to the DataSet owner, making them accessible only to Admin users.
- Queries to DataSets in Pro-Code Apps could fail with a 500 error.

### App Studio

**Issues Resolved:**

- App Studio tabs could not be reordered when AI chat was disabled in the instance.
- Box plot charts in App Studio displayed as bar charts after applying a filter, showing only the maximum and minimum values instead of the full box plot visualization.
- Cards in App Studio dashboards appeared compressed with unexpected scroll bars in desktop view.
- Editable tables in App Studio could fail to accept user input when the DataSet schema's column name casing was changed.
- Grid and List components in App Studio displayed "Power from data to configure search/sort" even when a DataSet was already connected, preventing configuration of search and sort columns.
- In App Studio where a custom app reapplying a filter could inadvertently clear the page filter it was setting, causing cards to display unfiltered data. This update also restores the ability to remove a filter with a single click when it was applied by another card on the same page.
- In App Studio where charts could display data from a variable value set on a previously visited page, even when "Persist Variable controls" was disabled. Smart text displayed the correct card-level variable value, but chart data did not update properly after page navigation.
- In App Studio where filter cards did not stay synchronized across pages when "Persist interaction filters" was enabled. Previously, changing a filter on one page would update the data but not the filter card display on other pages, and removing a filter sometimes required clicking twice. The issue affected desktop web only; mobile worked correctly.
- Multiple Workflow Start actions in an App Studio app would all execute the same workflow instead of their individually configured workflows.
- Non-admin users received a PAGE_ACCESS_DENIED error when attempting to move or copy cards to App Studio pages that appeared as available destinations in the dialog.
- Some charts in App Studio would briefly appear and then go blank after the app loaded.
- Table cards exported from App Studio applications in scheduled reports lost their theme formatting, including alternating row colors and other styling.
- Text boxes in App Studio displayed unnecessary scroll bars regardless of content size or box dimensions.
- Users with the "Edit Data in Editable Table Cells" permission were unable to edit cells in App Studio editable tables that use linked DataSets unless they also had the "Edit Cards" permission.

- This update implements SCIM user deprovisioning via PATCH requests, resolving an issue where user deprovisioning actions were not being applied correctly through SCIM.
- Users could not log in via SAML if their profile contained text fields exceeding 255 characters.

### Cards

**Issues Resolved:**

- A reported issue where cards became stuck in a "Loading" or "Filtering" state and failed to render on dashboards. The cards would load successfully after changing a filter or when opened in Analyzer, but would hang on the initial page load. This update reverts a change that caused this behavior.
- Beast Mode calculations in Data Model cards failed validation with "A column in this calculation did not exist" when a variable was referenced after a column reference. Variables now populate and validate correctly in Beast Mode editors on Data Model cards.
- Beast Modes referencing Variables could not be duplicated to another DataSet using Beast Mode Manager. The action was incorrectly blocked with a message reporting the Variable as a nested Beast Mode reference.
- Card filters and controls failed to display values on cards built from data models that used aggregate filters combined with variable-driven groupings. A related fix addresses duplicate table aliases in nested data model queries with date ranges.
- Cards grouped by month displayed English month labels (e.g., "2026-Jan") instead of localized labels (e.g., "2026年1月") for non-English viewers, causing some cards to show "Data Not Available.".
- Cards with Relative Date variables could not be saved on Cloud Amplifier Snowflake instances.
- Custom JavaScript cards built from the DDX-HTML-Blank template could become stuck on "Loading..." and prevent the Pro-Code Editor from opening when editing the app.
- Date range filters in Analyzer would shift by one day when edited, with the problem compounding on subsequent edits for users in timezones behind UTC. A related fix corrects similar one-day shifts in card details and page filter date inputs for users in timezones ahead of UTC.
- Duplicate variable controls could appear on cards in Analyzer and card details views.
- Editor users could not upload new versions of Doc Cards they did not own, even when they had edit permissions on the card. Users who encountered a 403 error when attempting to update PDF or image files on Doc Cards can now successfully upload new versions.
- Exporting a card with a semicolon or non-ASCII characters in its title would result in a file without an extension or with a garbled filename.
- Issues where date variables and DATETIME comparisons did not correctly apply the company timezone. Variables now calculate dates in the correct timezone, and filters using date variables apply properly on dashboard load.
- Preset buttons in the expanded date selector on Cards were unresponsive and could become compressed into a vertical line after multiple click attempts.
- Shared pages from inactive or deleted users could incorrectly appear in the admin pages list.
- Table cards displayed raw decimal values instead of the configured number format (percent, currency, or abbreviated) for high-precision decimal columns. Affected cards now correctly apply decimal precision, percentage formatting, and thousands separator settings.
- Table cards with multiple columns and a total row could fail to render with a "Bad Request" error when adding dimensions, particularly when the card configuration reused certain column references.
- Users who owned a document card through group membership could not see the "Upload Version" button, preventing them from updating the card.
- Users with Editor permissions could not upload new versions of Document Cards they did not own. Users can now update Document Cards as expected when they have edit access to the card.
- Variable control filters applied in App Studio apps did not carry over when exporting cards as email attachments, causing filtered values to display as zero in the export.

### Cloud Integrations

**Issues Resolved:**

- A reported issue where DataSets displayed a false authentication warning even though the account credentials were valid and the data was syncing correctly. Re-entering valid credentials now properly clears the warning.
- Azure SQL Cloud Amplifier DataSets did not refresh their row count after each sync. The DataSet Overview now accurately reflects the current row count, including when the source table is empty or has fewer rows than before.
- Cloud Amplifier exports to Snowflake could lose table data when using REPLACE or APPEND modes due to incorrect schema mapping in table comments.
- Cloud Amplifier integrations could not be deleted when hidden system datasets remained associated with them, even though these datasets were not visible in Data Center.
- Cloud Amplifier writes to Snowflake that ran longer than 30 minutes could fail intermittently with a "Connection is closed" error.
- Customers using custom calendars in Cloud Amplifier could lose access to the feature or see incorrect date boundaries in their queries.
- Databricks live-query cards that sort on a window-function Beast Mode (such as DENSE_RANK or ROW_NUMBER) returned a query error instead of rendering.

### Connectors

**Issues Resolved:**

- A rare issue where the Facebook connector's settings page could fail to load properly.
- Connecting very large PostgreSQL tables (100 million or more rows) through Cloud Amplifier failed with a "VALIDATION_FAILED" error. Tables now connect immediately, and row counts are computed in the background rather than blocking the connection process.
- Creating a TikTok Business connector account would fail with a 500 error if the TikTok account display name contained an emoji.
- SMALLINT columns from Redshift Cloud Amplifier were imported as Text instead of Integer, preventing their use in aggregations like sum and max.
- Uploading multiple files consecutively in the File Upload connector could cause the interface to freeze and fail to transition to the preview screen. Users previously had to reload the page between uploads to avoid this behavior.

**Updates:**

- Adds Activity Log entries when columns are reordered on a DataSet's Schema tab, showing who made the change, when, and each column's previous and new position. It also provides a way to reset a DataSet's column order back to its original indexed order.

**Issues Resolved:**

- Cloud Amplifier Redshift DataSet Views failed with a "column does not exist" error when column names contained lowercase letters or full-width characters.
- DataSet Views created from federated DataSets could not be edited, displaying a "Something went wrong while trying to edit this view" error.
- The account sharing dialog would fail to open if a previously shared group had been deleted, preventing users from managing account permissions.
- The direction of time zone conversion for federated Postgres DataSets. Previously, when a company's time zone had a negative UTC offset, datetime values were shifted in the wrong direction—hours were added instead of subtracted. This affected displayed datetime values and date-range filter boundaries.

- DataSets failed to appear after enabling low-latency sync in Data Query.
- Empty objects in AppDB low-latency sync documents could prevent DataSet columns from being created.
- In Cloud Amplifier where the table list would not load when browsing Snowflake schemas if the user lacked admin permissions and the schema contained DataSets they could not access.
- Materialized DataSet Views could stop refreshing and incorrectly report successful runs with zero rows instead of displaying an error.
- Saving a DataSet View would reset the column order and remove column descriptions, hidden column settings, and tags from the Schema tab.
- Schema changes to low-latency AppDB DataSets were not applied after the initial sync was enabled.
- Snowflake connectors could fail to sync for some customers.
- This update adds support for dot notation when declaring nested-path columns in AppDB schemas for Pro-Code Apps, resolving an issue where such declarations would create empty columns.
