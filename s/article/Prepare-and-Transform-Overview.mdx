## Intro

Once your data is in Domo, you often need to clean, join, filter, or reshape it before it can power meaningful analysis. Domo's transformation tools read one or more input DataSets and write the result to a new output DataSet—making the cleaned, combined data available to every card, DataFlow, and AI model downstream. This article explains what the preparation tools are, when to use each, and points to the how-to articles for each tool.

---

## Required Grants

To create transformation pipelines, the following grants must be enabled for your role:

- **Can Create DataSets —** Create the output DataSets that transformation tools generate.
- **Manage DataFlows —** Create, edit, and delete DataFlows and Magic ETL pipelines.

Learn more about [grants](/s/article/360043438973).

## Transformation Tools

| Tool | Best for | How you work |
|------|----------|--------------|
| [Magic ETL](/s/article/What-is-Magic-ETL) | Most users; no SQL required | Drag-and-drop tiles on a visual canvas |
| [SQL DataFlows](/s/article/360042922994) | Data engineers fluent in SQL | Write MySQL or Redshift queries |
| [Adrenaline DataFlows](/s/article/360063698733) | Very large DataSets requiring fast aggregation | SQL script interface on Domo's high-performance engine |
| [DataFusion](/s/article/360043428313) | Simple joins of two DataSets | Point-and-click join configuration |
| [DataSet Views](/s/article/360046074774) | Filtered or projected views without data duplication | SQL-like view definition |

## Magic ETL

Magic ETL is the recommended starting point for most users. Build a data pipeline by dragging tiles onto a visual canvas—no SQL or code required for most operations.

## SQL DataFlows

SQL DataFlows let you transform data using MySQL, Redshift, or Adrenaline SQL. Best for engineers who prefer writing queries.

- [Create a SQL DataFlow](/s/article/360042922994) — Getting started with SQL DataFlows.
- [Adrenaline DataFlows](/s/article/360063698733) — High-performance option for large DataSets.

## DataFusion

DataFusion joins two DataSets into a single combined view without writing a full DataFlow. Best for simple unions and joins where no further transformation is needed.

- [Edit a DataFusion](/s/article/360043428313) — Create and configure a DataFusion join.

## DataSet Views

DataSet Views create a filtered or column-projected view of a DataSet without duplicating the underlying data. Changes to the base DataSet propagate automatically.

- [Manage DataSet Views](/s/article/360046074774) — Create, modify, and share DataSet Views.

## FAQ

<AccordionGroup>

<Accordion title="Which transformation tool should I start with?">
  Start with Magic ETL. It handles the vast majority of transformation tasks without requiring SQL or code. Move to SQL DataFlows if you need window functions, complex CTEs, or other SQL operations that Magic ETL tiles don't support. See [What Is a DataFlow?](/s/article/What-is-a-DataFlow) for a comparison of all types.
</Accordion>

<Accordion title="Does transforming data create a new DataSet or modify the original?">
  All transformation tools write to a new output DataSet. The original input DataSets are never modified. You can give the output DataSet any name and share it independently.
</Accordion>

<Accordion title="How does PDP work with transformation pipelines?">
  Input DataSets in any DataFlow or Magic ETL pipeline cannot be restricted by Personalized Data Permissions (PDP)—all rows pass through the transformation. Apply PDP policies to the output DataSet, not the inputs.
</Accordion>
