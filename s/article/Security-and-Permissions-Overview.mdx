## Intro

Domo's security and permissions system covers how users authenticate, what they can access, and how data-level restrictions are applied. The model has three layers: role-based access control (what features users can use), Personalized Data Permissions or PDP (what rows of data they can see), and instance security settings (SSO, IP allowlists, session policies). This article explains each layer and points to the key configuration articles.

## Required Grants

To configure security settings and manage permissions, the following grants must be enabled for your role:

- **Manage Roles —** Create and assign roles and grants.
- **Manage All Company Settings —** Configure instance-level security settings (Admin grant).

PDP applies row-level data filters to a DataSet so that different users see only the rows they are authorized to see—all powered by the same card and DataSet.

## FAQ

<AccordionGroup>

<Accordion title="What is the difference between role-based access and PDP?">
  Role-based access controls which Domo features a user can use (edit cards, manage DataSets, view Admin settings). PDP controls which rows of data within a DataSet a user can see. Both are independent: a user might have an Editor role but see only the rows of a DataSet that match their PDP policy.
</Accordion>

<Accordion title="Does PDP affect all cards powered by a DataSet?">
  Yes. When a PDP policy is applied to a DataSet, every card powered by that DataSet respects the policy. Users see only the rows their policy permits, regardless of which card or dashboard they are viewing.
</Accordion>

<Accordion title="Can I use both SSO and Domo's built-in login?">
  Yes. Domo supports SSO as the primary authentication method while keeping Domo's built-in login available as a fallback for service accounts or emergency access. The fallback behavior is configurable in instance security settings.
</Accordion>
