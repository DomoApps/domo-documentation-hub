## Intro

A DataFlow is a data transformation pipeline in Domo. It reads one or more input DataSets, applies transformation logic—joining, filtering, aggregating, computing new columns, and more—and writes the result to a new output DataSet that updates automatically whenever the inputs refresh. This article explains what DataFlows are, describes the three types, and links to the how-to articles for each.

---

## Required Grants

To create and edit DataFlows, the following grants must be enabled for your role:

- **Can Create DataSets —** Required to create the output DataSet generated by a DataFlow.
- **Manage DataFlows —** Create, edit, and delete DataFlows in your instance.

Learn more about [grants](/s/article/360043438973).

## DataFlow Types

Domo has three DataFlow types. All three read input DataSets and write an output DataSet; they differ in how you express the transformation logic.

- **Magic ETL —** Visual, drag-and-drop canvas. Arrange tiles to join, filter, aggregate, and reshape data—no SQL or coding required for most operations. Best for most users and use cases. See [What Is Magic ETL?](/s/article/What-is-Magic-ETL).
- **SQL DataFlows —** Write MySQL or Redshift SQL queries to transform data. More expressive than Magic ETL for complex SQL operations. Best for data engineers fluent in SQL. See [Create a SQL DataFlow](/s/article/360042922994).
- **Adrenaline DataFlows —** High-performance DataFlows built on Domo's Adrenaline engine. SQL script-based interface optimized for summarizing and aggregating very large DataSets rapidly. Available on the Domo Consumption agreement. See [Adrenaline DataFlows](/s/article/360063698733).

## When to Use Each Type

| If you need… | Use… |
|---|---|
| No-code transformation, accessible to non-engineers | Magic ETL |
| Full SQL expressiveness, window functions, advanced joins | SQL DataFlows |
| Maximum performance on very large DataSets | Adrenaline DataFlows |
| Python or R in the pipeline | Magic ETL with Scripting tiles |

## How DataFlows Run

DataFlows can be triggered in three ways:

1. **Automatically —** When an input DataSet refreshes, Domo can trigger the DataFlow to run immediately.
2. **On a schedule —** Set a fixed time or interval.
3. **Manually —** Select **Run** from the DataFlow detail page.

See [Advanced DataFlow Triggering](/s/article/000005216) for chained and conditional trigger setups.

## FAQ

<AccordionGroup>

<Accordion title="What is the difference between a DataFlow and a DataSet?">
  A DataSet is a data table—raw data stored in Domo. A DataFlow is a transformation process that reads one or more DataSets, applies logic, and writes the result to a new DataSet. DataSets are the data; DataFlows are the pipelines that transform it.
</Accordion>

<Accordion title="How does PDP interact with DataFlows?">
  Input DataSets to a DataFlow cannot be restricted by Personalized Data Permissions (PDP)—all rows pass through. Apply PDP policies to the output DataSet, not to the inputs. This applies to all DataFlow types. See [Create a SQL DataFlow](/s/article/360042922994) for the PDP guidance.
</Accordion>

<Accordion title="Can a DataFlow become disabled automatically?">
  Yes. DataFlows that have not run in an extended period may be automatically disabled to conserve resources. See [DataFlows Disabled Due to Extended Inactivity](/s/article/4404652354583) for details and how to re-enable them.
</Accordion>

<Accordion title="What is the difference between a DataFlow and a DataFusion?">
  A DataFusion is a lightweight join of two DataSets that creates a virtual combined view—no transformation beyond joining is applied, and the result is not a stored DataSet. A DataFlow applies richer transformation logic and writes a full output DataSet. Use DataFusion for simple joins; use a DataFlow for filtering, aggregation, or multi-step logic. See [Edit a DataFusion](/s/article/360043428313).
</Accordion>

</AccordionGroup>
